# Script-Board Forge — 短视频脚本·分镜双生成引擎

## 1. 核心定位

这个 skill 是一个**前期制作引擎（pre-production engine）**：把用户脑海里一个模糊的视频创意，落地成 1-3 份「结构本质不同」的完整方案，每份 = 一条**可拍摄的脚本** + 一张**逐镜头分镜表**。

它解决的不是"说什么"（那是文案），也不是"某一个镜头怎么生成"（那是 video-prompt-forge），而是把两者缝合起来的中间层：

> **叙事结构（说什么、按什么顺序说）× 视觉注意力设计（用户为什么继续看）× 镜头语言（每一秒画面怎么承载信息）。**

一条贯穿全流程的原则：**结构服务于目标，画面服务于结构，没有一个镜头是为了炫技而存在的。**

**为什么一次给多种结构？** 因为同一个 brief 往往有几种本质不同的打法——痛点驱动、结果驱动、故事驱动，各自赌的是不同的观看心理和转化路径。给出多个**策略上真正不同**的方案（而不是同一方案的三种措辞），让用户根据自己对受众的判断去选，比强行押注一种更有价值。

## 2. 生态位（与相邻 skill 的边界）

- **本 skill（上游 · 规划层）**：brief → 多结构「脚本 + 分镜」。
- **video-prompt-forge（下游 · 单镜头生成层）**：把本 skill 分镜表里的**某一条镜头**，扩写成可喂给 Sora / Kling / Veo 的 AI 视频提示词。→ 本 skill 输出的每条分镜，天然就是 vpf 的输入。
- **script-expert-ready（并行 · 长片层）**：长篇剧本 / 影视级叙事工程。若用户要的是几分钟以上的完整剧本，转交它。

若用户只要"帮我把这个画面写成一段 AI 视频提示词"——不要用本 skill，直接用 video-prompt-forge。

## 3. 执行流程

### STEP 0 — 意图澄清与信息门槛（Intent Gate）

**先判断信息是否足够，再决定"追问"还是"推断"。** 这一步的纪律是：**该问才问，能推就推，绝不反复追问。**

**核心变量清单（intake checklist）：**

| 变量 | 是否硬需求 | 说明 |
|------|-----------|------|
| **主题 / 主体** | ✅ 硬需求 | 拍什么——产品、主题、故事内核。缺了它无法动笔。 |
| **目标 / 目的** | ✅ 硬需求 | 让用户做什么/感受什么/学到什么：种草、转化、涨粉、科普、品牌、共情。它直接决定选哪种结构。 |
| 平台 | ⭕ 可推断 | 抖音 / TikTok / 小红书 / 视频号 / Shorts——影响时长、语气、竖屏节奏、hook 强度。 |
| 时长 | ⭕ 可推断 | 15/30/60/90/120s——决定节拍时间分配。默认按平台常见值。 |
| 目标受众 | ⭕ 可推断 | 谁看——影响语气与 hook。 |
| 核心卖点 / 关键信息 / 证据点 | ⭕ 可推断* | 商业内容尤其重要（成分、功效、价格、对比、口碑）。 |
| 情绪基调 | ⭕ 可推断 | 从主题意象与语气推断，别默认"中性"。 |
| 制作方式 | ⭕ 可推断 | 实拍 vs AI 生成——决定分镜是否要写关键帧描述。 |
| 硬性约束 | ⭕ 可推断 | 品牌元素、必含信息、禁用词、时长上限等。 |

**判定规则：**

- **必须追问**，当：① 主题/主体 缺失或看不懂；或 ② 目标完全不明、且主体本身也推不出目标；或 ③ brief 内部存在硬矛盾。
- **直接推断（并显式标注假设）**，当：主体 + 大致目标已在，只是平台/时长/受众/情绪/证据缺失——选合理默认值，用一行「本方案假设：…（如与实际不符请告诉我）」标注，然后继续生成。
- **商业 brief 比创意 brief 更倾向追问**：因为投流/转化型内容里，把受众或痛点猜错会真实浪费预算；纯创意/AI 视频探索型内容里，大胆推断、后续再调更高效。

**追问方式**：合并真正阻断创作的缺口，使用当前环境实际提供的反问方式。依赖答案的内容等待，已明确且不依赖答案的工作继续；平台、时长等可推断项不作为结束任务的理由。产品功效、价格和证据不得凭空补造。

> 反面校验：如果你发现自己准备问超过 3 个问题、或在追问用户其实已经能从上下文合理推断的东西——停下，改为"推断 + 标注假设"。

### STEP 1 — 锁定变量 + 结构选型（Structure Selection）

把 STEP 0 的变量固化，然后选 **1-3 种结构**。选型的唯一标准是**适配**，不是凑数。

**首先读取 `references/narrative-structures.md`**，获取每种结构的完整节拍模板、适用/不适用、溯源与边界。SKILL.md 只给速查：

| 结构 | 一句话 | 最适合 |
|------|--------|--------|
| **Hook–Value–Payoff（三段式）** | 为什么看→给你什么→结果/行动 | 万金油默认；科普/教程/测评/产品都合适 |
| **PAS**（Problem-Agitate-Solution） | 痛点→放大→解法 | 痛点型产品、痛点已知的受众（护肤/健康/工具） |
| **AIDA** | 注意→兴趣→欲望→行动 | 宽泛转化、品牌+产品、需要建立"想要"（香水/美妆/lifestyle） |
| **BAB**（Before-After-Bridge） | 原状态→理想态→怎么做到 | 有可视化前后变化的（改造、功效、蜕变） |
| **故事型**（Founder / Hero's Journey / Story Circle） | 普通→遇阻→尝试→获得→改变 | 品牌故事、情绪共鸣、人物/创业（目标是好感而非直接转化） |
| **剧情/冲突模型** | 目标 + 阻碍 + 解决 | 剧情短视频、情景广告 |
| **情绪型** | 共鸣 + 痛苦 + 释放 | 纯情绪向内容 |

**多方案要"本质不同"**：给一个护肤种草 brief，好的三选是【PAS：痛点驱动】+【BAB：蜕变驱动】+【HVP：干货教育驱动】——三种不同的策略赌注；而不是三条都在讲卖点、只是措辞不同。**如果两个方案抽掉标签后读起来一样，就砍掉一个、换一个真正不同的角度。**

选型时同时判断每个方案的**情绪曲线**（焦虑→希望 / 平静→惊喜 / 好奇→满足…），它会在 STEP 2 决定分镜的能量曲线。

### STEP 2 — 逐方案生成（对每个选中的结构，依次做 A→B→C）

**A. Hook 设计** ｜ 读取 `references/hook-library.md`。
为该结构的开场设计 hook，同时给出**文字 hook** 和**画面 hook**（第一帧的视觉异常）——两者要配对，光有文案没有画面钩子，等于没有钩子。遵守 hook 的"可兑现"原则：hook 承诺的东西，正片必须交付，否则是伤害完播与信任的标题党。

**B. 脚本撰写**（可拍摄脚本）。
按该结构的节拍模板，写出带时间轴的完整脚本，逐拍包含：时间段、口播/对白（VO/Dialogue）、屏幕字幕（On-screen text）、该拍要完成的叙事任务。语言要"可拍摄"：不写"介绍一下产品"，写具体说什么、画面发生什么。

**C. 分镜设计**（逐镜头分镜表）｜ 读取 `references/storyboard-grammar.md`。
把脚本翻译成一张 shot-by-shot 的表，每行一个镜头，列包含：

`镜号 | 时间 | 景别(WMC) | 运镜 | 主体+动作 | 构图/光影 | 声音(VO/SFX/Music) | 字幕 | [AI关键帧描述]`

（`[AI关键帧描述]` 列仅当制作方式=AI 生成时填写：主体外观、材质、光线的固定化描述，用于跨镜头一致性。）

**分镜与脚本的一致性是硬要求**：分镜的能量曲线必须复现脚本的情绪曲线——hook 拍要给强视觉钩子镜头，payoff/CTA 拍要给高级 hero shot，情绪最低点要给低饱和/压抑的镜头处理。翻译完做一次对照：**"这张分镜的节奏起伏，和脚本想要的情绪起伏，是一条线吗？"** 不是就重排。

### STEP 3 — 组装输出

按下面「输出格式」把 1-3 个完整方案 + 一段横向对比一次性交付。

### STEP 4 — 终稿前自检

对照第 5 节「质量红线」逐条过一遍，再交付。

## 4. 输出格式

**始终用这个结构。** 每个方案自成一块：

```
# 短视频方案 · [主题一句话]
> 平台 [x] ｜ 时长 [x] ｜ 目标 [x] ｜ 受众 [x]
> 本方案组假设：[若有推断，一行说明]

────────────────────────────
## 方案 A —— [结构名]（[情绪曲线]）
**为什么选它**：[1-2 句，这个结构赌的是什么、适合什么样的受众/场景]

### 脚本
[带时间轴的可拍摄脚本：每拍 = 时间段 / 口播 / 字幕 / 叙事任务]

### 分镜表
| 镜号 | 时间 | 景别 | 运镜 | 主体+动作 | 构图/光影 | 声音 | 字幕 | [AI关键帧] |
|-----|------|------|------|----------|----------|------|------|-----------|
| ... |

### 衔接 video-prompt-forge
[指出哪几条镜头最值得用 vpf 扩写成 AI 视频提示词；若整片 AI 生成，说明主体一致性锚点]

────────────────────────────
## 方案 B —— …（同上）
## 方案 C —— …（同上）

────────────────────────────
## 如何选
[3-5 句横向对比：各自的优势/风险、分别适合什么情况，给一个默认推荐]
```

输出要**完整但克制**：把每个方案写足，但不注水；对比部分要真的帮用户决策，而不是复述。

## 5. 质量红线

- **禁止"伪多方案"**：多个方案必须策略本质不同（见 STEP 1）。三种措辞不算三种方案。
- **禁止 hook 与正片错配**：hook 承诺 A，正片交付 B，是标题党——它拉高 3 秒留存却摧毁完播与信任，长期是负资产。hook 必须可兑现。
- **禁止脚本与分镜脱节**：分镜的情绪/能量曲线必须复现脚本的情绪曲线（见 STEP 2-C）。两张皮是最常见的低级错误。
- **禁止不可拍摄的空洞描述**：分镜里每一格都要"可执行"——如果一个摄影师/AI 模型无法据此布置画面，就重写。"很美的画面"不是分镜；"手从画面左侧入镜，逆光下瓶身冰霜边缘泛出冷蓝反光"才是。
- **禁止一个镜头塞多个信息**：一个镜头只承担一个信息，这是短视频信息密度的基础。
- **禁止"越快越好"的迷信**：3 秒 hook、每 3-5 秒变化是**经验法则**不是定律；完播由**绝对观看时长 × 留存率**共同决定，一味砍短会牺牲总时长。让时长服从内容本身需要的节奏（依据见 `references/storyboard-grammar.md`）。
- **禁止编造数据与来源**：不要搬运"XX% 的爆款视频…"这类无法溯源的营销数字当作事实。方法论里凡是经验法则，就标为经验法则；凡引用理论，只引真实存在、可核查的（见各 reference 的溯源注）。
- **禁止结构崇拜**：结构是生成的脚手架，不是成片的保证。严格套模板会产出"千片一面"（连 Save the Cat 都因此被批评为"编剧填空题"）。模板用来保证完整与节奏，最终要为这一条内容的独特性让路。
- **文案追求广泛共鸣**：优先唤起跨圈层的共同情感与"价值转化"，避免把受众钉死在狭隘的人群标签上；注意文案的节奏感。

## 6. 语言与适用范围

- **语言**：默认与用户同语言输出。分镜表里的镜头术语（景别/运镜）可保留中英对照；若用户明确目标工具是英文界面（如给 Sora 用），AI 关键帧列用英文。
- **平台差异**（选型与语气时纳入考虑）：小红书偏第一人称、干货/种草、语气软；抖音偏强 hook、快节奏；视频号受众偏年长、语气更稳；Shorts/TikTok 强 hook + 完播导向。
- **适用范围**：0-2 分钟短视频的脚本 + 分镜。**不负责**：单条 AI 视频提示词（→ video-prompt-forge）、几分钟以上的长片剧本（→ script-expert-ready）、纯文案不含分镜（可只交付脚本部分）、视频后期调色/剪辑指导。
