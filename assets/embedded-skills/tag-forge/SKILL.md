# Tag Forge

对素材做"一次通读、双份产出"：一行干净的 tag + 打标依据报告。核心纪律只有一条——**tag 不是想出来的，是从受控词表里选出来的**。自由发挥的标签属于第②步的候选，只有过了第③步三道闸门才能上文档。

## Read in order

- 必读 [tag-lexicon.yaml](./tag-lexicon.yaml)——它同时是候选池、抽取 schema、归一词典。没读词表就打标是本 skill 的头号违规
- 首次使用或需要判断 tag 归属哪个 facet 时，读 [references/facet-schema.md](./references/facet-schema.md)
- 需要完整走查示范时，读 [references/worked-example.md](./references/worked-example.md)（含一个 23 tag → 6 tag 的真实收敛案例）
- 用户问视频素材怎么打标时，读 [references/video-tag-methodology.md](./references/video-tag-methodology.md)，只讲方法论，不执行

## 两种模式

- **tag 模式（默认）**：输入文档/图片/文件夹 → 输出 tag 行 + 打标报告 + 词表增量
- **pack 模式**：输入 tag 组合查询（如 `品牌分析 AND 赫莲娜`）→ 输出知识包文档。触发词：'提取知识包'、'把 XX 相关的整理成一份'、'pack'

## Workflow：tag 模式

### Step 0：装载词表

- 完整读入 tag-lexicon.yaml，在心中按 facet 分组
- 记住配额：每份素材 tag 总数 **3–7**；形态恰 1、领域 1–2、实体 0–3、用途 0–2、状态恰 1
- 记住本轮新建限额：整轮运行新建 tag ≤ 10 个，单份素材新建 ≤ 2 个

### Step 1：盘点与路由

- 单文件直接进入 Step 2；文件夹则先列出全部待处理文件，按类型路由：
  - `md / txt / docx / pdf` → 文本通读
  - `png / jpg / webp` → 图像描述先行（见 Step 2 图片分支）
  - 视频文件 → 不处理，告知用户当前只提供方法论并指向 reference
- 已有 tag 行且用户未要求重打的文件：跳过并在报告中标注
- 文件夹批处理时报出总数，每处理完一份给一行进度

### Step 2：通读与候选抽取

对每份素材产出四样东西（此步允许自由发挥，**不查词表**，让内容自己说话）：

1. 两句以内的内容摘要
2. 自由候选 tag 列表（5–10 个，宁多勿漏，后面有闸门收敛）
3. 每个候选附**依据**：文本素材引原文 ≤30 字；图片素材写区域描述（如"左下角瓶身印有 HR 标识"）
4. 每个候选附置信度（高/中/低）

图片分支的纪律（沿用 image-reverse-describe 的描述先行原则）：先产出中立的画面描述——主体、场景、文字信息、风格——再从描述文本里抽候选。**禁止跳过描述直接打标**，这是防止 VLM 幻觉标签的唯一屏障。

**无依据的候选直接丢弃，不进入 Step 3。**

### Step 3：三道闸门（收敛引擎，本 skill 的心脏）

每个候选依次过闸，命中即停：

- **闸门一 · 精确/别名命中**：候选与词表某词条的 label 或 aliases 完全一致 → 归一到该词条 label，通过
- **闸门二 · 语义近邻**：候选与同 facet 下某词条含义相同或是其子集（如候选"抗老"→ 词条"抗衰老"；候选"HR 品牌"→ 词条"赫莲娜"）→ 归一到该词条 label，并把候选写法记入该词条 aliases 建议
- **闸门三 · 新建（收紧执行）**：两道闸都不中，先自问三个问题，全部为"是"才允许新建：
  1. 这个概念未来会不会有第二份素材用到？（一次性概念降级为正文关键词）
  2. 它是不是比已有词条更具体而非更宽泛？（宽泛词见黑名单）
  3. 它归属哪个 facet 是明确的吗？
  - 新建词条一律 `status: pending`，不算正式词表成员
  - 触达新建限额后，多余候选一律降级为报告中的"正文关键词"

**宽泛词黑名单**（永不成为 tag，只能当正文关键词）：分析、内容、资料、笔记、重要、参考、学习、知识、素材、其他。理由：出现在一半以上素材里的词没有检索区分度。

配额执行：闸门跑完后若仍超配额，按置信度从低到高裁剪；若不足 3 个，宁缺毋滥，不硬凑。

### Step 4：写回

- 文档顶部 tag 行的默认形态（与用户 app 的展示习惯一致）：

```
#品牌分析 #小红书营销 #功效性护肤 #赫莲娜 #竞品研究 #待整理
```

- 排列约定：形态 → 领域 → 实体 → 用途 → 状态，人眼扫一行即知文档定位
- 已有 YAML frontmatter 的 md 文件：写入 `tags:` 字段（Obsidian 兼容），不另加 tag 行
- 图片等无法内嵌的二进制文件：不动原文件，在报告中输出该文件的 tag 块，供用户或 app 层挂载
- 命名规则：有通行中文名用中文（#赫莲娜 而非 #HR）；无通行中文名保留官方英文写法（#SKII、#Houdini、#VEX）；英文写法变体全部进 aliases（SK-II、sk2 → SKII）

### Step 5：报告与词表园艺

每轮结束输出打标报告，包含：

- 每份素材：文件名 → 最终 tag 行 → 每个 tag 的依据一句话
- 本轮新建的 pending 词条清单，请用户逐条批复：**转正 / 合并到已有词条 / 废弃**
- 疑似同义词合并建议（如词表里同时存在"保湿"与"补水"且语料中混用）
- 孤儿 tag 提示：仅被 1 份素材使用的词条，建议观察或降级

用户批复后，把词表变更写回 tag-lexicon.yaml。**词表是活资产，每轮必须落盘，不能只改在对话里。**

## Workflow：pack 模式

1. 解析 tag 查询（支持 AND / OR / NOT，裸列举默认 AND）
2. 扫描范围内所有带 tag 的素材，按查询命中
3. 不堆砌全文——聚合每份命中素材的摘要与依据段，按主题重组
4. 输出知识包文档：主题综述 → 分节要点（每条要点后括注来源文件名）→ 素材清单
5. 命中不足 3 份素材时如实说明，并给出放宽查询的建议（如去掉一个 AND 条件）

## Global guardrails

- 不要在未读 tag-lexicon.yaml 的情况下打任何一个 tag
- 不要给没有依据的内容打 tag，哪怕"看起来显然是"
- 不要让文档里提及的每个实体都成为 tag——tag 回答"这份文档**是关于**什么的"，不回答"这份文档**提到了**什么"。对比提及的品牌、顺带引用的工具，进正文关键词，不进 tag 行
- 不要新建与已有词条仅措辞不同的 tag，那是闸门二的失职
- 不要把状态类判断（好/差/值得学）打成 tag——tag 描述内容，不做评价
- 不要在一轮里静默修改词表；所有词表变更必须在报告里可见并经用户批复
- 批处理中途出错时，保留已完成部分的结果，报告断点位置，不推倒重来

## Quality gate

写完 tag 行后逐条自查：

1. 每个 tag 都能在词表里找到对应词条（含本轮 pending）吗？
2. 每个 tag 的依据摘出来给第三个人看，对方会同意这个 tag 成立吗？
3. 遮住文档只看这行 tag，能大致猜出这份文档是什么、关于什么、用来干嘛吗？
4. 把这行 tag 放到素材库里另外十份文档上，会不会有一半也成立？——会，说明 tag 太宽泛，收敛失败
5. 形态和状态两个 facet 是不是恰好各一个？
6. 本轮新建的每个 pending 词条，三个新建问题都答"是"了吗？
