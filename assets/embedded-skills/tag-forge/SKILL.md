# Tag Forge

目标是让用户几乎不用参与：先把每份文档能确定的内容标签完整打好，只把少量真正存疑的新词集中问一次。`待整理` 等工作流状态由 Ready 单独保存，永远不作为用户可见的内容标签。

## Read in order

- 文件夹打标时，`tag_forge_prepare_batch` 返回的 `lexicon` 是本轮唯一可执行词表。不要用文件工具寻找或读取技能目录里的 `tag-lexicon.yaml`
- 需要判断 facet 时读 [reference/facet-schema.md](./reference/facet-schema.md)
- 需要完整示范时读 [reference/worked-example.md](./reference/worked-example.md)
- 用户问视频素材时读 [reference/video-tag-methodology.md](./reference/video-tag-methodology.md)，只讲方法论，不执行

## Content contract

- Tag Forge 自动负责的内容标签以 2-15 个为安全范围，不是要求凑满；已有手工或导入标签原样保留，不占这 15 个名额
- 必须恰有 1 个 `form`，并至少有 1 个 `domain` 或 `entity`
- `domain/entity/use` 不设各自硬配额；只要有直接证据、可跨文档复用，并能新增一条独立检索路径，就可以保留
- 同义词、翻译、大小写和拼写变体只保留一个归一标签；已有具体标签时不再添加更宽泛的上位词
- `entity` 只标文档主要对象，不把顺带提及的名字全部变成标签
- `use` 只有从内容或用户意图能确定时才标，不猜
- 不提交 `state` 候选；Ready 会把默认状态写入独立的 `ready_state`
- 置信度不低于 0.92、证据摘录可在正文精确回查的 `domain/entity/use` 新词，在每份文档最多 15 个自动内容标签内直接采用；允许把明确的跨语言表达归一为统一标签，不要求用户确认

短文自然可能只有 2-4 个，内容丰富的文档通常会有 5-10 个；当每个标签都提供不同连接维度时，11-15 个同样是正常结果。

满足“形态 + 主题/主要对象”才算完成。只有 `待整理`、只有形态，或只有零散实体，都不得报告完成。

## Document or folder workflow

### 1. Prepare

先调用 `tag_forge_prepare_batch`。单个 Markdown 直接传用户引用的 `@[文件名]` 或附件名，文件夹任务同样传用户引用的名称；工具会在本轮冻结授权内自行解析，绝不要向用户索要被隐藏的绝对路径。它会返回：

- 本批需要处理的 Markdown 正文和版本凭证
- 每份文档的不透明 `itemId`；后续原样回传，绝不用路径代替
- 当前已启用标签及别名
- 批次进度和继续信息

用户显式要求给文件夹打标时，Ready 每次都重读全部 Markdown，包括已有标签的文档，以捕捉正文变化并修复旧结果。单文档任务只处理用户选中的文件。不要自行跳过。

### 2. Read once, propose once

完整阅读每份正文后，一次性提交该文档的全部候选：

- 所有标签都必须用 `proposals`，提供 `facet`、归一标签、置信度和正文中的准确短摘录 `evidenceExcerpt`
- 每份文档用 Prepare 返回的 `itemId` 提交；不要改写，也不要回传展示路径
- 先阅读文档已有标签；不要再次提交它们的同义词、翻译或拼写变体，只补充尚未覆盖的独立检索维度
- 宽泛词“分析、内容、资料、笔记、重要、参考、学习、知识、素材、其他”只算正文关键词，不建标签

不要先试一个标签、失败后再猜另一个，也不要提交没有正文依据的标签简写。

### 3. Let Ready resolve new terms

Ready 按证据分三档处理：

- 已启用标签/别名：直接采用
- 置信度不低于 0.92、证据摘录可精确回查、且属于 `domain/entity/use` 的新词：逐字命中或明确的跨语言/概念归一均可在自动内容标签不超过 15 个时直接采用，不打扰用户
- 置信度 0.65-0.92 的可复用新词：保留可靠标签并进入一次集中确认
- 低于 0.65、无正文证据、过宽或一次性的词：忽略，不打扰用户

达到 15 个后，多余候选直接忽略，不得仅因数量溢出要求用户确认。

`form` 是封闭集合，未知形态不能自动采用。

### 4. Apply and review once

调用 `tag_forge_apply_batch` 写回本批。若返回 `reviewRequired: false`，继续用 `batchId` 准备下一批，直到 `done: true`。

扫描完整个文件夹后若仍有存疑项，Ready 宿主会自动在当前工具调用里弹出一张集中确认卡，并在用户提交后自动续写原批次。模型不要自行改写问题、不要另调 `ask_user_questions`，也不要伪造 `confirmationCardId` 或直接调用审核工具。

每个文件夹运行最多弹出一张确认卡，最多展示 35 项；容量外的中置信候选直接忽略，不再要求用户继续处理。

不要让用户去设置页，不要逐文件追问，不要在用户确认后重新创建批次。工具仍返回 `reviewRequired: true` 时说明确认尚未完成，绝不宣称整批完成。

### 5. Report

结束时简洁报告：处理数、完成数、各文件最终内容标签，以及用户实际确认过的少量新词。没有存疑项时不要额外要求确认。

## Single-document creation

新文档保存后的自动打标仍遵守同一内容合同；缺少“恰好一个形态 + 至少一个领域或主要实体”时不得稀疏完成。每条 `evidenceExcerpt` 必须能从最终将落盘的正文中精确回查；创建回执、最终正文一致性、版本校验、状态写入和索引回读由 Ready 负责。

证据摘录能在正文精确回查，且标签逐字命中、`confidence >= 0.65`，或属于明确的跨语言/概念归一、`confidence >= 0.92` 的 domain/entity/use 新词，在文档自动内容标签总数不超过 15 时由 Ready 直接采用；其余低可信候选直接忽略，新文档不发起标签确认。

## Pack mode

用户明确要求“提取知识包”或按标签组合整理时：

1. 解析 AND / OR / NOT 查询，裸列举默认 AND
2. 扫描命中素材并聚合摘要与依据段
3. 按主题重组为“综述 -> 分节要点 -> 来源清单”
4. 命中不足 3 份时如实说明并建议放宽条件

## Guardrails

- 不用通用写文件或 shell 绕过 Tag Forge 工具
- 不修改内置 `tag-lexicon.yaml`；新词由 Ready 的用户词表保存
- 不把无依据、仅提及、评价性或工作流状态写成内容标签
- 不覆盖用户手工标签；只替换 Tag Forge 自己拥有的标签
- 遇到版本冲突时重新准备该文档，不覆盖用户刚做的修改
- 运行未完成或仍有存疑项时，不宣称整批完成

## Quality gate

提交前逐份自查：

1. 是否有且仅有一个形态标签？
2. 是否至少有一个领域或主要实体标签？
3. 每个标签是否都能用标题或正文短摘录证明？
4. 是否误把顺带提及、宽泛词或 `待整理` 当成内容标签？
5. 新词是否给了准确 `evidenceExcerpt` 和诚实置信度？
6. 每个标签是否新增了一条独立检索路径，而不是重复已有标签的同义表达？
7. 最终标签能否让人只看标签就大致知道“这是什么、关于什么”？
