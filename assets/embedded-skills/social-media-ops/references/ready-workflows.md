# Ready 工作流手册：运营任务的采集与执行协议

> 定位：把方法论接到 Ready 的真实能力上——浏览器实证采集、串行/并行分析、结构化反问、文档产出。
> 通用纪律先读 §一；各工作流只写差异部分。方法论细节在对应 reference 文件，本文只管"怎么跑"。

## 一、通用执行协议

### 1.1 开工三步
1. **识别意图**（见 SKILL.md 意图路由表），有歧义时先用一次 `ask_user_questions` 结构化澄清（每轮最多一次，问题合并提；优先选择题+合理默认值，降低用户成本）。用户已说清的信息不重复问。
2. **申报计划**：一句话说明将采集什么、分析什么、大约多久、产出什么形态；深度任务给用户"快扫/标准/深诊"选择。
3. **立锚点**：确认账号定位/资产锚点（topic-discovery.md §一）。用户有历史档案或前轮已确认的，直接复用。

### 1.2 浏览器采集纪律
- **能采就采，不能采就要**：目标平台页面可公开访问时用浏览器实采；不可访问（登录墙/仅 App 生态）时如实说明，请用户提供截图、导出数据或口述关键数字，**绝不虚构采集结果**。
- 常用动作：`browser_navigate` 打开目标页 → `browser_read_page`/`browser_extract_structured` 提取结构化字段 → 列表页配 `browser_scroll_collect` 滚动收集 → 视觉判断（封面/版式）直接用 `browser_analyze_viewport` 返回可读分析结果；`browser_capture_viewport` 仅用于坐标动作前后留证，不把其 `image_id` 当作主模型可读图片。
- **节奏**：详情页每批 3-4 个，批间自然停顿；连续采集触发平台验证/登录时用 `browser_ask_user_takeover` 请用户接管处理，处理完继续，不静默放弃、不硬闯。
- **并行**：互不依赖的多账号/多关键词采集可用 `browser_start_task` 起后台任务并行跑，`browser_aggregate_results` 汇总；单账号内的详情深读保持串行小批次（防风控）。
- 开放性调研（找案例/查规则/看讨论）用 `web_search`/`web_fetch`/`browser_research_topic`。
- **平台规则/门槛数字必须实时核查**后再引用（platform-mechanics.md 只提供基线与核查方向）。

### 1.3 采集可达性速查
| 平台 | 公开可采 | 受限面 |
|---|---|---|
| 小红书 | 主页/笔记/搜索结果（web 端） | 频繁翻页易触发验证；后台数据仅用户可见 |
| 微博 | 主页/单条/话题/热搜 | 部分内容要登录 |
| 知乎 / B站 | 主页/内容/搜索 | 少量登录墙 |
| 抖音 | web 版主页/视频 | 数据面较薄，评论区受限 |
| X | 未登录几乎不可读 | 建议用户登录后采，或用户提供数据 |
| 公众号 | 单篇文章页可采 | 无公开主页列表；历史文章与后台数据请用户提供 |
| 视频号 | 基本不可 web 采集 | 全部依赖用户提供 |

### 1.4 产出纪律
- 结论先行；每个判断挂证据（哪条内容/哪个数字/哪条规则）；推断与事实分开标注。
- 报告级产出（诊断书/选题包/内容日历/复盘报告）写成 Ready 文档交付，聊天里给摘要；轻量问答直接聊天回答，不摆架子。
- 每份深度产出附"样本与边界"声明：采了什么、多少、没覆盖什么。
- 产出后主动给"下一步"选项（诊断→选题；选题→开写；写完→优化；发布→复盘），形成闭环但不强推。

## 二、工作流分册

### W1 账号诊断（自己的号 / 客户号 / 对标拆解）
- 方法论：account-diagnosis.md 全文。
- 确认项：对象关系、痛点与目标、资产背景、深度（快扫=只看账号层+列表层，约几分钟；标准=+5-8 条详情深读；深诊=+同行基线+搜索可见性）。
- 采集：账号层 → 列表层（30 条）→ 按 §2.2 规则选样本深读 → （深诊）3-5 个同量级同行列表层并行采集建基线 → 搜索层测收录。
- 分析：基线计算 → 五维评分 → 漏斗归因 → 十大结构病比对 → （定位弱）四步推演。
- 产出：按 account-diagnosis.md §八报告合同出文档；结尾按对象关系切换口吻（教练直说 / 附转述话术 / 研究拆解）。
- 快扫模式明确声明"未读正文详情，以下基于列表与封面层证据"。

### W2 选题挖掘
- 方法论：topic-discovery.md 全文。
- 确认项：锚点（无定位先补锚点三问，必要时引导先跑 W1）、平台、数量与偏好、是否限定方向。
- 采集：四个探测面至少走两个——搜索面（联想词+结果页水位）、对标面（3-5 账号列表并行）、评论面（高互动内容评论区）、时效面（日历+平台活动）。关键词矩阵生成后**请用户确认一轮**再批量搜索。
- 筛选：验证型对标筛选协议（低粉高互动信号+人工归因核查+排除用户自己的内容）；预算化迭代（翻页→定向扩搜≤2轮→如实降级）。
- 产出：选题包文档，每题符合"产出合同"（标题级表述+对标锚点+适配理由+切角形式+分层标签），附挖掘规模陈述；给"深挖某题/直接开写"下钻入口。

### W3 单条内容拆解（爆款分析/竞品内容分析）
- 方法论：content-craft.md（工艺维度）+ analytics-review.md §1.2（结构比）+ K18（对照）。
- 采集：目标内容全量（标题/封面/正文/标签/互动/评论区 top 评论）；同作者近 10 条列表（判断这条是其常态还是异常爆款）；可选：同关键词 1-2 条哑火内容做对照。
- 分析：钩子型/结构/峰值/CTA 逐层拆 → 互动结构比读价值类型 → 可复制因子 vs 不可复制因子分离 → 评论区需求信号顺手提取（喂选题库）。
- 产出：拆解卡（聊天或短文档）：为什么起量（证据）、可借鉴清单、不可照搬项、想仿写时的增量方向（衔接 W4）。

### W4 内容创作（新写 / 仿写）
- 方法论：content-craft.md 全文；仿写走 §7.1 四步（拆结构→换血肉→加增量→查相似）。
- 确认项：平台与形式、选题（无选题引导走 W2）、目标动作（赞藏/评论/转粉/转化，决定 CTA 型）、人设素材（经历/案例/口头禅）、字数时长。
- 采集：仿写需先完整采集参考内容（走 W3 轻量版）；新写可按需搜索事实素材（事实必须可溯源，不编数据案例）。
- 产出：标题 3-5 个（标注钩子型）+ 正文/脚本 + 封面文案与版式建议 + 发布备注（标签/时段/首小时动作）；过一遍发布前自检清单（content-craft.md §8）含合规扫描。

### W5 内容优化（改稿 / 起标题 / 封面方案 / 发布前体检）
- 方法论：content-craft.md §7.2 改稿协议 + §8 自检清单。
- 要求用户直接粘贴原文（比链接稳）；有链接时采集原页。
- 产出：诊断清单（每条问题挂依据）→ 推荐版全文 + 修改说明 → 可选风格变体；只要标题就出 8-10 个分钩子型的标题矩阵；封面给文案+版式方向（视觉细节建议转美术）。

### W6 数据复盘（单条 / 周期）
- 方法论：analytics-review.md 全文。
- 数据来源优先级：用户后台截图/读数 > 公开面采集 > 用户口述。首次使用引导建立数据账本（§5 模板）。
- 单条走 §2 四步（先排统计错觉再归因）；爆款走爆款专用协议；周期走 §3 六项。
- 产出：复盘纪要（三条结论+证据、下期 1-2 个实验假设、明确的不变项）；把实验假设登记为下次复盘的验证项。

### W7 增长瓶颈会诊（"卡在 X 粉不动了"）
- 方法论：growth-monetization.md §二 + account-diagnosis.md §6 漏斗树 + analytics-review.md §3。
- 采集：近 2-3 个月内容表现（列表层足够）+ 主页承接面检查 + 可选同行对照。
- 分析：先判平台期类型（人群天花板/内容疲劳/标签固化/质量滑坡）→ 涨粉三因子（曝光×主页访问率×关注转化）定位瓶颈因子 → 开对应处方。
- 产出：会诊书：类型判定（证据）+ 4 周实验路线（每周一个变量，带最小样本量与判定标准）。

### W8 变现规划
- 方法论：growth-monetization.md §三§四 + platform-mechanics.md 各平台商业化卡。
- 确认项：可交付能力（时间/技能/性格：能不能做服务、敢不敢直播）、收入预期、现有资产（私域/产品/案例）。
- 采集：账号达标情况对照平台门槛（**门槛数字实时核查**）；同赛道变现样本 2-3 个（他们怎么接单/挂什么产品）。
- 分析：前后端匹配诊断 → 路径匹配（轻/重服务、平台分成/商单/带货/知识付费/私域）→ 单位经济学粗算。
- 产出：变现路线图：现在就能做的 / 达到 X 条件后做的 / 不建议做的（附理由）；接单基建清单（报价思路/案例集/报备流程）。

### W9 限流排查与危机应对
- 方法论：compliance-safety.md §二（限流类型学+自查协议）§四（危机决策树）。
- 纪律：**先排统计错觉**（K19/K20：单条回落与正常波动不是限流）再查账号；逐项走自查协议（后台通知→近期内容比对治理清单→搜索可见性实测→再谈申诉）。
- 危机（负评发酵/被抄袭/合作翻车）：按分级处理表给"现在做/别做/时机"三栏行动单；重大法律风险明确建议咨询专业人士。
- 产出：排查结论（证据+置信度）+ 行动单；限流误判时给用户吃定心丸并转入正常复盘。

### W10 陪跑计划（内容日历 + 周期循环）
- 适用：用户要"接下来一个月怎么发"或长期陪跑。
- 方法论：topic-discovery.md §6 题库三层 + analytics-review.md §3/§4 + growth-monetization.md §一阶段目标。
- 产出：内容日历文档（周节奏×选题分层×形式配比+每条的目标动作），内置 1-2 个实验变量；约定复盘节点，到点走 W6 周期复盘并滚动更新日历。

## 三、意图边界与转接

- 视觉细节（构图/配色/封面精修）→ 建议转美术 agent；文案精写可深度协作文案 agent（本技能管策略与结构，逐字打磨是文案的主场）；纯学术研究/资料整理 → 智识 agent。
- 用户要求刷量、买赞、伪造数据、洗稿搬运、规避平台审核 → 拒绝并解释为什么伤号（通识 §4/K22），给合规替代方案。
- 涉及医疗/金融/法律等专业结论 → 提示内容合规边界（compliance-safety.md §一），agent 不替代专业人士。
- 所有"平台最新规则/门槛/算法改动"类问题 → 先实时核查再回答，注明信息日期。
