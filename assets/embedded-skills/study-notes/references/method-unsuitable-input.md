# Method: Unsuitable Input

用于纯表格、纯代码、法律条款、说明书、规格书等。

## Core rule

先承认：这类材料不适合普通学习笔记模板。

不要硬写成：

- “核心知识点”
- “值得记住的经验”
- “类比解释”

这样通常只会降质。

## What to do instead

切到原文真正适合的摘要类型，把"普通学习笔记"换成更贴合形态的产物：

- 原始数据表 / 数据集 → 数据摘要
- 纯代码 → 代码导读
- 法律条款 / 合同 / 制度 → 条款摘要
- 说明书 / 规格书 → 使用或规格清单

具体怎么写见 `## Recommended structure` 下对应的子段。如果材料同时含多种形态，按主导形态选一种，再用 mixed-content 思路把其它层加在末尾。

## Recommended structure

### `short`

- 先说明为什么不适合普通笔记
- 给最小替代摘要
- 保留关键参数、字段、条款或代码逻辑

### `standard`

- 先说明更合适的摘要形式
- 按数据、代码、条款或规格结构拆解
- 补风险、例外或缺失上下文

### `layered`

- 先给目录式总览
- 分块处理不同材料段
- 标出不能凭这份材料下结论的部分

### 原始数据表 / 数据集

改成 `数据摘要`：

- 数据是什么
- 最明显的模式/异常
- 缺什么上下文
- 后续该怎么看

### 纯代码

改成 `代码导读`：

- 这段代码做什么
- 关键输入/输出
- 核心逻辑
- 风险或限制

### 法律条款 / 合同 / 制度

改成 `条款摘要`：

- 这段条文管什么
- 义务/限制/例外
- 哪些词需要特别小心
- 还需要谁确认

### 说明书 / 规格书

改成 `使用或规格清单`：

- 这是干什么的
- 关键步骤或关键参数
- 注意事项
- 适配边界

## When the user explicitly insists on notes

如果用户明确说“就按笔记给我”，可以输出一个最小保真版本，但必须：

- 先说明这类内容更适合哪种摘要
- 再给改造后的结构
- 不要冒充普通文章笔记

`unsuitable-input` 不走普通 short path。即使脚本高置信且材料很短，也要先说明为什么不适合普通笔记，再切到替代格式。

## Analogy policy

- 不用类比。先切到替代格式，替代格式里也以参数、条款、字段、代码逻辑的精确为先。

## Route-specific failure modes

- 硬凑“核心知识点”和“人生启发”
- 删除参数、字段、例外或限制
- 把代码解释成泛泛业务道理
- 把条款摘要写成法律结论
- 对表格只写感受，不保留列名和关键数值

## Avoid

- 不要为了形式完整，往代码或条款里硬塞“人生启发”
- 不要省略参数、例外、限制这些最关键的信息
