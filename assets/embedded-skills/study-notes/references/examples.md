# Examples

只在你需要校准某一路由输出时读取对应片段，不要整份一起搬进上下文。

这些示例都是完整输出，不是半成品骨架。遇到故事、评论、新闻、报告、教程、混合内容时，优先看同类型示例，不要拿别的类型硬套。

## Example A: Knowledge Tutorial

### Input

如何让你的 AI 艺术更独特。大多数人在使用 AI 绘画时，第一反应是输入通用 prompt。这会让作品淹没在海量相似图像里。真正独特的 AI 艺术需要三个要素：具体的情绪、意外的材质组合、叙事性的构图。你提供的 creative direction 越具体，AI 的发挥空间反而越大。

### Output

#### 这件事是什么

这段内容讲的不是“怎么把 prompt 写得更长”，而是怎么让 AI 真正拿到有方向的创作指令。重点不在堆词，而在给它一个更具体的情绪、材质和场景。

#### 关键做法

- 情绪别写成空标签，要写成能看见的场景
- 故意混合不常见的材质或风格，让画面摆脱默认审美
- 不要只描述一个对象，要描述一个正在发生的瞬间

#### 怎么用

下次写 prompt 时，先检查自己给的是不是“抽象标签”。如果只是“好看、梦幻、科幻”，通常还不够；如果已经能让人脑中出现一个具体画面，方向才算开始清楚。

#### 一句话总结

AI 出图是否独特，关键不在词多，而在你给的创作方向够不够具体。

## Example B: News Brief

### Input

3月28日，上海市交通委发布新规，自2026年5月1日起，新增投放的共享电单车必须接入统一定位与电子围栏平台。已投放车辆需在六个月内完成改造。监管部门表示，新规主要为了解决乱停放和跨区调度失控问题。多家运营公司回应称，硬件改造会提高成本，但有助于减少罚单和投诉。目前细则尚未公布，车价补贴和过渡期执法尺度仍待明确。

### Output

#### 这件事是什么

上海要把新增共享电单车统一接入定位和电子围栏平台，老车也要在六个月内补改。这是一条治理规则，不只是技术升级。

#### 5W1H

- 谁：上海市交通委、共享电单车运营公司
- 什么：新增车辆必须接入统一平台，存量车辆限期改造
- 什么时候：2026年5月1日起执行，老车六个月内完成改造
- 为什么：主要解决乱停放和跨区调度失控
- 怎么做：接入统一定位与电子围栏平台

#### 当前已知和未知

- 已知：监管方向已经明确，平台接入是硬要求
- 未知：细则还没公布，补贴和过渡期执法尺度未定

#### 一句话总结

这是一条先定方向、细则待补的共享电单车治理新规。

## Example C: Data Report

### Input

2025年中国独立咖啡店经营报告。我们调研了42个城市的1260家门店。结果显示：样本门店日均出杯量同比增长12%，但客单价同比下降6%。一线城市的工作日早高峰销售占全天营收的43%，而三线城市晚间社交场景占比更高。拥有会员体系的门店复购率比无会员体系门店高18个百分点。报告同时提醒，样本以开业三年以上门店为主，因此对新店冷启动阶段的解释力有限。

### Output

#### 先看结果

这份报告说明，独立咖啡店的单量在涨，但单杯能卖出的价格在下滑。经营上更像“靠效率和复购守利润”，不再只是靠单次高客单。

#### 关键数据发现

- 日均出杯量同比增长 12%
- 客单价同比下降 6%
- 一线城市早高峰销售占全天营收 43%
- 有会员体系的门店，复购率高出 18 个百分点

#### 这些数据说明什么

门店经营重心正在往“复购”和“时段管理”偏。城市层级不同，主力消费场景也不同，不能用同一套时段打法。

#### 限制

样本以开业三年以上门店为主，所以这份报告更适合参考成熟店，不适合直接解释新店冷启动。

#### 一句话总结

单量增长不等于更好赚，独立咖啡店正在进入更依赖复购和精细运营的阶段。

## Example D: Opinion Commentary

### Input

很多人把AI写作工具当成提效神器，但我越来越怀疑，它正在把写作者最宝贵的肌肉偷走。写作不只是把句子排列整齐，而是在下笔前逼自己想清楚：你到底要说什么，你凭什么这么说。

### Output

#### 作者的核心论点

作者担心，AI 写作最危险的地方不是代写，而是让人把形成判断这一步也外包出去。

#### 作者凭什么这么说

他的理由是：写作最有价值的部分，不是润色，而是你在组织观点时被迫完成的思考。如果先让 AI 给大纲和初稿，人很容易只剩“修词”这一步。

#### 还可以再想一步

这更像一条强观点，而不是已经被充分证明的结论。它提醒的是风险方向，不是说明所有 AI 辅助写作都会让判断退化。

#### 一句话总结

这篇评论真正担心的，是判断力被“方便感”慢慢偷走。

## Example E: Narrative Story

### Input

我第一次带团队做直播是在一个周五晚上……复盘时我才意识到，真正让人留下来的不是流程熟练，而是临场时你能不能真的看见观众在困惑什么。

### Output

#### 故事梗概

作者原本只是幕后准备者，却在开播前十分钟临时顶上主讲，几乎在毫无准备的状态下完成了一场直播。

#### 关键转折

最重要的转折不是“顶上去”本身，而是直播结束后的复盘：作者发现观众留下来，并不是因为流程无误，而是因为现场表达真的在回应观众的困惑。

#### 这段经历留下什么

这更像一条关于沟通的体感经验：熟练流程很重要，但真正拉住人的，是你有没有在现场建立真实回应。

#### 一句话总结

一次不完美的临场顶替，反而让作者看清了沟通里最值钱的东西。

## Example F: Framework Methodology

### Input

设计系统不是关于工具的，而是关于共识的。当你建立一个设计系统，你实际上在做三件事：建立词汇表、建立规则、建立信任。

### Output

#### 框架是什么

这段话把设计系统重新定义成“团队共识系统”，而不是单纯的组件库或工具栈。

#### 三个组成部分

- 词汇表：先把按钮、间距这些基本概念说成同一种语言
- 规则：规定什么场景该用什么方案
- 信任：让团队相信这套系统会持续被维护和更新

#### 这三层怎么配合

没有词汇表，大家连问题都说不清；没有规则，系统只是素材库；没有信任，团队迟早会绕开系统各做各的。

#### 一句话总结

设计系统真正要解决的，先是共识，再是工具。

## Example G: Mixed Content

### Input

昨天某短视频平台宣布下线一批 AI 换脸模板，官方理由是近期投诉量上升。但作者随后写了一段评论，认为这件事真正暴露的不是模板审核，而是平台一直把创作门槛做低，却没有同步建立后果教育。事件本身只是一根导火索，真正的问题是平台过去默认“好玩优先”，现在才开始补治理课。

### Output

#### 先说这段内容有两层

第一层是事实：平台下线了一批 AI 换脸模板，理由是投诉上升。第二层是评论：作者认为，这件事暴露出的更深问题不是单次审核失手，而是平台长期把使用门槛做低，却没同步建立风险教育。

#### 事实层

- 某平台已经下线部分 AI 换脸模板
- 官方给出的直接原因是投诉增加
- 这说明平台至少开始把治理压力转成具体动作

#### 评论层

作者的判断是，模板下线只是表面动作，真正的问题在更前面：平台过去优先追求“好玩、易用、低门槛”，却没有提前让用户理解这种工具可能带来的后果。

#### 怎么理解这两层关系

如果只看事实，这是一条普通的平台治理新闻；如果把评论层也带上，它更像一次对平台产品逻辑的追责。两层都重要，但不能混成一句“平台终于意识到问题了”，因为前者是已发生的动作，后者是作者的解释。

#### 一句话总结

这段内容既在讲一次下线动作，也在借这次动作追问平台过去的产品逻辑。

## Example H: Unsuitable Input

### Input

```python
def rolling_alert(series, window=7, threshold=0.25):
    mean = series.rolling(window).mean()
    delta = (series - mean) / mean
    return delta.abs() > threshold
```

### Output

这段内容不适合做普通“学习笔记”，更适合做代码导读。

#### 这段代码做什么

它用滚动平均当参照，判断当前值偏离均值的幅度是否超过阈值。

#### 关键参数

- `window`：均值窗口大小
- `threshold`：触发提醒的偏离比例

#### 要注意的地方

如果均值很接近 0，偏离比例会变得不稳定；另外，前几项因为窗口不满，会出现空值。

## Example J: Layered Mixed Content

### Input

一份 9000 字混合材料：前半是政策新闻，后半是作者评论和执行建议。材料里同时包含新闻事实、评论判断和执行清单。

### Output

#### 一屏总览

这份材料至少有三层：政策事实、作者评论、执行建议。先不要把它压成一条结论，否则会把“已经发生的事”和“作者的解释”混在一起。

#### 子层地图

- 事实层：政策何时发布、要求什么、哪些细则还没确定
- 评论层：作者认为这不只是合规问题，而是组织治理能力测试
- 执行层：平台或团队接下来要检查来源登记、流程责任和后续追踪

#### 先展开到这里

如果继续展开，下一步应分别写事实时间线、评论论证和执行清单，而不是把 9000 字材料静默截成一段短摘要。

## Example K: Layered Data Report

Example J 展示的是 overflow 预览协议；本例展示 `layered` 三层结构完整执行后的成品。

### Input

一篇约 6800 字的论文（摘要 + 实验 + 结论），主题是生成式 AI 供应链安全。论文在 12 个模型服务链路上评估了 prompt injection、tool poisoning、retrieval contamination、policy confusion、memory hijacking 五类攻击，报告了各自的成功率与误报率，结论是单点过滤器无法覆盖跨链路污染，需要在检索、工具执行、记忆写入三个位置同时设防。

### Output

#### 一屏总览

这篇论文回答的问题是：生成式 AI 的安全防御应该放在哪个环节。它在 12 个真实模型服务链路上测了五类攻击，核心结论是：攻击是跨链路的，但现有防御是单点的，所以单点过滤器注定有漏。作者给出的解法是三处同时设防——检索入口、工具执行边界、记忆写入。如果要拿它指导实践，最该带走的是这份"设防位置清单"，而不是具体的成功率数字。

#### 分层摘要

**实验设置层**

- 评估对象：12 个模型服务链路，覆盖检索增强、工具调用、长期记忆三类架构
- 攻击向量：prompt injection、tool poisoning、retrieval contamination、policy confusion、memory hijacking 五类

**发现层**

- 五类攻击在不同链路上的成功率差异很大，但没有一类能被单一过滤器全部拦截
- 跨链路污染是主要盲区：在 A 环节注入、在 B 环节生效的攻击，单点检测的漏报率明显更高

**结论与建议层**

- 单点过滤器无法覆盖跨链路污染
- 防御要在三个位置同时部署：检索入口、工具执行边界、记忆写入

#### 记忆和使用层

- 该记住的：攻击跨链路，防御别单点；三个设防位置是检索、工具执行、记忆写入
- 该怎么用的：审计自己系统时，按这三个位置逐一检查是否有独立校验
- 还缺什么：论文只覆盖 12 个链路；具体成功率数字换一个架构未必复现，引用时要带上实验范围

#### 可信度提醒

结论方向（单点防御不足）有多链路实验支撑，相对可靠；但具体百分比受实验设置影响大，不要脱离"12 个链路"这个口径单独引用。
