# 镜头信息卡 Markdown 格式

用于用户要求“生成剧本/分镜/镜头脚本/AI 视频逐镜/分镜信息卡/按效果图格式输出”时。该格式把每个镜头变成一个可复制、可检索、可供 AI 生图/视频继续调用的信息卡，而不是传统横向表格。

## 触发场景

使用此格式：

- 用户要求生成剧本/分镜，并提到“信息卡”“代码块”“Markdown 卡片”“像效果图这样”“AI 视频逐镜”“视频提示词”“参考帧”“保留项/避免项”。
- 用户要求生成可直接给生图/视频模型使用的镜头脚本。
- 用户要求后续能按镜号调用单镜生成图片或视频。

若用户只是要传统分镜表，仍可使用 `shotlist-template.md` 的表格格式；若不确定，优先询问输出为“传统表格”还是“信息卡代码块”。

## 基本结构

每个镜头是一个独立的大块，用 `---` 分割线作为块边界，分割线后以 `## Shot XX / Ys` 开头；镜头大块本身不要整体包进代码块，也不要使用 `<details>` 折叠块。

镜头大块内部依次输出 7 个字段，每个字段标题下方都必须使用独立代码块包裹该字段内容，方便逐项复制、替换、回填和程序读取。多个 Shot 连续输出时，每个 Shot 前都用一条 `---` 分割线隔开。

字段顺序固定：

1. 画面
2. 镜头
3. 动作
4. 视频提示词
5. 参考帧
6. 保留项
7. 避免项目

代码块语言建议：

- `画面`、`镜头`、`动作`、`视频提示词` 使用 `text` 代码块。
- `参考帧` 使用 `md` 代码块，因为后续可能插入 Markdown 图片链接。
- `保留项`、`避免项目` 使用 `md` 代码块，便于保留列表格式。

## 标准模板

````md
---

## Shot 06 / 5s

### 1. 画面
```text
群体正常跑步推进，特写聚焦音的小腿和脚踝局部一起切入画面，空旷感只有几道拉开的低质光带和一层薄雾，鞋底和鞋头形成强攻击性透视。
```

### 2. 镜头
```text
低位前向跟拍，轻微后撤保持鞋体主导画面，允许看到脚踝以下的真实穿着关系，但透视不能扭曲鞋型。
```

### 3. 动作
```text
脚步带着轻微模糊向前加速推进，镜头与主体保持同步短距离后撤，边缘风压和粒子被强力拉开，画面张力最大化。
```

### 4. 视频提示词
```text
Use the uploaded reference frame as the visual lock. Generate a 5s continuous 16:9 low-angle forward attack shot of the same white sneaker pushing aggressively toward the camera, with only the ankle and lower leg visible. The camera retreats in sync while the shoe drives forward at high speed, pulling open air pressure and a few restrained light streaks around it. Preserve the toe-box perspective, outsole thickness, white material layering, and minimal premium environment. The shot should feel forceful and fast but never distort the shoe. No full body, no race-track background, no multi-subject ghosting, no exaggerated fisheye deformation.
```

### 5. 参考帧
```md
assets/shot06-line-art-v1.png

时长：5s
主动作：脚步带动鞋体高速向前，镜头低位同步后撤，风压和粒子被拉开。
镜头运动：low tracking retreat
音频：强风切，节奏重击
```

### 6. 保留项
```md
- 鞋头和鞋底透视关系
- 白色材质层次
- 极简光带空间
- 只保留脚踝以下的人体局部
```

### 7. 避免项目
```md
- 不要出现完整人物
- 不要让鞋头变形夸张
- 不要暗背景做成赛道场景
- 不要出现多主体叠影
```
````

## 字段规则

### 镜号 + 时长

格式：`## Shot 06 / 5s`

- 镜号沿用用户提供或分镜生成的编号。
- 中文项目也保留 `Shot` 前缀，便于后续程序解析。
- 时长缺失时可写 `TBD`，但正式执行前应补齐。
- `---` 分割线 + 镜号标题共同作为镜头大块的外层边界，不要把整个 Shot 包进一个代码块，也不要用 `<details>` 包住 Shot。

### 1. 画面

写画面中看见什么。包括主体、空间、光线、构图、气氛。

要求：

- 标题下方必须用独立 `text` 代码块包裹内容。
- 只写可见内容，不写抽象主题。
- 保留剧本事实，不新增剧情。
- 若服务 AI 图像/视频生成，要写清主体位置、可见身体范围、关键物件、环境边界。

### 2. 镜头

写摄影机如何看。包括景别、机位、角度、镜头运动、透视约束。

要求：

- 标题下方必须用独立 `text` 代码块包裹内容。

建议包含：

- 景别：全景/中景/近景/特写/极特写。
- 机位：低位/高位/正面/侧面/背后/俯拍/仰拍。
- 运动：固定/推/拉/摇/移/跟拍/手持/低位后撤。
- 约束：是否允许变焦、透视是否可夸张、是否要保持主体比例。

### 3. 动作

写人物、物件、镜头内运动如何发生。

要求：

- 标题下方必须用独立 `text` 代码块包裹内容。
- 动作要有起点、变化和落点。
- 如果用于视频生成，要写连续运动，不只写静态画面。
- 避免“很震撼”“很有力量”这种无法执行的词，改写成画面运动和物理关系。

### 4. 视频提示词

用于 AI 视频生成或图像转视频。可以用英文，也可以中英混合；若用户没有要求语言，优先英文提示词，因为多数视频模型对英文稳定。

要求：

- 标题下方必须用独立 `text` 代码块包裹内容。

提示词必须包含：

- reference frame / visual lock 如何使用。
- 主体、动作、镜头运动、时长、画幅。
- 关键连续性：角色、服装、道具、空间、光线。
- 负面约束：不要出现什么、不要变形什么、不要偏离什么。

### 5. 参考帧

写参考帧路径、时长、主动作、镜头运动、音频等执行信息。

要求：

- 标题下方必须用独立 `md` 代码块包裹内容。
- 如果已经生成图片，Markdown 图片链接也放在这个 `md` 代码块内。
- 后续单镜生图回填时，只替换或插入本字段代码块内的参考帧路径/图片链接，不要把图片链接插到 Shot 大块外部或文件末尾。

如果已经生成图片，写 Markdown 图片链接，格式：

````md
### 5. 参考帧
```md
![Shot 06 reference frame](assets/shot06-line-art-v1.png)

时长：5s
主动作：脚步带动鞋体高速向前，镜头低位同步后撤，风压和粒子被拉开。
镜头运动：low tracking retreat
音频：强风切，节奏重击
```
````

如果还没生成图片，先写预期路径：

````md
### 5. 参考帧
```md
assets/shot06-line-art-v1.png

时长：5s
主动作：脚步带动鞋体高速向前，镜头低位同步后撤，风压和粒子被拉开。
镜头运动：low tracking retreat
音频：强风切，节奏重击
```
````

### 6. 保留项

列出生成图像/视频时绝对要锁定的内容。

要求：

- 标题下方必须用独立 `md` 代码块包裹列表。

常见保留项：

- 角色脸型、年龄、服装、伤痕、发型。
- 场景布局、门窗、光线方向。
- 道具外观、位置、材质。
- 镜头透视关系、主体可见范围。
- 原文或剧本中不可改的动作/台词/情绪。

### 7. 避免项目

列出要避免的生成偏差。

要求：

- 标题下方必须用独立 `md` 代码块包裹列表。

常见避免项：

- 换脸、年龄漂移、服装漂移。
- 多手、多主体叠影、肢体变形。
- 过度美化、甜宠化、恐怖化、色情化、暴力夸张化。
- 误把空间变成赛道、舞台、酒店、实验室等错误场景。
- 改剧情、改关系、改结局、改核心物件。

## 文件输出建议

当用户要求生成剧本/分镜并使用信息卡格式：

- 关键分镜信息卡：`项目名_关键分镜信息卡.md`
- 场级分镜信息卡：`项目名_场级分镜信息卡.md`
- 指定场景逐镜头信息卡：`项目名_第X场逐镜头信息卡.md`
- 指定镜号信息卡：`项目名_ShotXX_信息卡.md`

## 与传统分镜表的关系

- 传统表格适合统筹、快速浏览、横向比较。
- 信息卡适合 AI 生图/视频、逐镜执行、复制到工具、回填参考帧。
- 如果用户后续要按镜号生成图片，优先使用信息卡格式。
- 信息卡不是“整个 Shot 一个代码块”，也不是 `<details>` 折叠块；正确格式是“`---` 分割线 + Shot 标题形成大块，字段各自独立代码块”。
