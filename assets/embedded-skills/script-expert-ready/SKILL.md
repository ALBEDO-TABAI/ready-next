# 剧本锻造 Script Expert Ready

把故事或已有剧本变成可拍摄、可继续编辑的成果。先识别用户所需的产物与已有材料，再进入对应环节；分镜、修订、单镜生图和资产清单任务不重走完整故事改编流程。

## 输入与决策边界

- 先读取用户实际提供的原文、版本和约束。用户只说“我有一篇小说”但没有提供正文时，索取原文；不从一句摘要冒充已完成原作改编。
- 故事是否能改编取决于主角、核心关系/冲突、关键事件与结局是否清楚，不以 500 字门槛阻断结构完整的短故事。只有概念且未授权扩写时，先补关键故事信息。
- 用户已指定形态、范围、分镜密度或参考版本，直接沿用；可从材料推断的可逆选择，说明假设后继续。只有未解决的关键歧义、硬约束冲突或用户明确要求逐步审阅时才暂停。
- 用户要求整套交付，持续完成所需环节、自检与修订。提示包、大纲和分批写入是工作步骤，不自动成为审批点；不把自主生成的中间稿标成“用户已确认”。
- 只做所请求的环节；额外的分镜、生图、资产细化或外发不会因默认流程自动获得授权。用户只要诊断、建议或提示包时，在该交付物处结束。

## 按产物选择资料

只加载当前环节需要的 reference。已有可用材料直接复用，不读取全套模板。

| 用户需要 | 工作与参考 |
| --- | --- |
| 判断影视形态 | 读取 [form-judgment](references/form-judgment.md)，结合故事给出推荐；已指定形态时无需重复确认 |
| 剧本化提示包 | 用 [prompt-pack-template](references/prompt-pack-template.md) 固定改编边界与执行要求 |
| 分场大纲 | 用 [scene-outline-template](references/scene-outline-template.md) 写场号、事件、转折与必保元素 |
| 故事改编为剧本 | 默认先整理提示包与分场，再用 [script-format](references/script-format.md) 写正文，用 [selfcheck-template](references/selfcheck-template.md) 检查和修订；用户明确跳过中间产物时直接写正文，在内部保留原文约束 |
| 已有剧本修订 | 对照原文与用户要求，用上述正文格式与自检模板完成修订，不重新询问形态 |
| 传统分镜表 | 用 [shotlist-template](references/shotlist-template.md)，按指定场次和密度完成 |
| 镜头信息卡、AI 视频逐镜 | 用 [shot-card-format](references/shot-card-format.md)；保留分镜密度与连续性，不另读传统横表模板 |
| 指定镜号的参考帧或分镜图 | 用 [single-shot-image-workflow](references/single-shot-image-workflow.md)，读取该镜信息、真实生图并回填；生图能力不可用时不编造图片 |
| 数字资产清单 | 用 [asset-list-template](references/asset-list-template.md)，从所给版本提取角色、场景、道具和母题，保留稳定 ID 与连续性要求 |

## 全程约束

- 人物、关系、结局、关键场景、物件、母题和核心台词以原文及用户明确改编要求为依据；不擅自新增第三者、车祸、绝症、强反转等情节。
- 写成可拍的动作、对白、空间和节奏；不以主题解释或心理独白替代场景。分镜和资产环节不改剧情、台词或关系。
- 原文、提示包、分场与正文冲突时，按用户当前要求和原文修正受影响部分，再继续；不靠后文补丁掩盖前文偏离。
- “完整分镜 / 逐镜头 / 拍摄用 / AI 视频逐镜”必须按对应范围完整拆镜，不能压缩成关键镜头。仅当密度无法从用途推断且会改变交付时询问。
- 信息卡格式只由 `shot-card-format.md` 定义：按镜号分块、七字段各自独立代码块；不以传统横表、整镜一个代码块或 `<details>` 替代。
- 资产基于所提供的版本提取；未确认版本标“未锁定”，可以交付草表，不替用户锁定。修订时保留原资产 ID，注明真实变更。
- 用户明确指定语言或只需某种输出时遵从该要求；固定模板用于所请求的产物，不强制附加其他交付物。

## 写入与连续完成

正式产物使用当前环境实际授权的写入/导出能力；在 Ready 中遵守本轮冻结的目标目录与工具授权，不从示例路径推导写权限。通用工作区可用且未指定路径时，建议 `script-expert-ready/项目名/`。项目名避开路径分隔符、换行和冒号。

- 剧本、大纲、提示包、分镜、资产清单分别保存为含项目名的 `.md` 文件；同名不覆盖，创建新版本。自检报告单独保存，不混入剧本正文。
- 长项目按场或集连续推进，保存已完成范围、下一场/镜号与版本关系；批次大小按实际容量选择，不把“分批”变成要求用户反复说继续。
- 写入后回读文件，核对场号、镜号、数量、引用和完整性。修复自检中的致命问题及影响交付的偏差，再给结果。
- 若缺少写入能力，交付可复制正文并说明尚未落盘；若用户明确要求文件，则这仍是未完成项。需要用户选择目标或授予权限时，只询问该缺口，不擅自改存其他路径。

## 完成判定

所请求的产物覆盖约定范围、与来源及约束一致，必要自检已完成，文件或图片已实际写入并核对。只要仍有缺场、失败生图或未完成的必要文件，就不能宣称整套完成。

最终简述完成内容和可用链接；有真实阻碍则说明已完成部分及缺少什么。需要观察使用效果时参考 [test-prompts.json](test-prompts.json)，不以模板文字齐全替代实际产物验证。
