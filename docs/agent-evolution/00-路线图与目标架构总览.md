## 5. 全局设计原则

1. **文件为真值源，DB 为索引投影**（范围严格限定在知识层，存量记忆体系不动）；派生视图永不手改，坏记录忽略不带病显示。
2. **确定性工作交给代码**，LLM 只做判断；LLM 调用前必过省钱门控；纪律既写提示词也做运行时守卫（fail-fast 结构化错误）。
3. **完成被证明、阻塞被分类、学习被落盘且有准入门槛**；占位值是 blocker；空轮合法可审计。
4. **窄通道原则**：finalizer 管收口、adjudicator 管裁决、编译器管分派——每个闸门只长一种逻辑。
5. **意图判断是路由问题**：误判代价 = 多走一站；拒绝权后置到行动时确认；纠偏靠先例卡。
6. **最小传话**：跨层只传用户原话 + 引用；执行计划不替用户改写任务。
7. **账本单向上行**：执行级 → 事件 → task 级 → run 级；唯一写入者 + CI gate。
8. **用户主权与体验连续**：派生/退休/知识晋升/危险动作默认需确认；归属切换默认不切会话；个性化可解释可撤销；第三方内容永不构成许可。
9. **主 agent 保持薄**；每个新增涌现/建议面默认有数量上限与关闭开关——主动性不等于打扰。

## 6. 不做清单

OKR 上半截；跨 agent 消息总线；per-agent 工具白名单；agent 级模型路由；无确认自动派生；每 4h 全量 LLM 维护；多工作区/语音层；反爬绕过类能力（高风险站点走视觉通道或用户手动）；provider 级重试（C5.2 管辖）与 UI 渲染层缺陷（不在本系列）。
