# 设计明细 10：涌现体系重构——从"文件时间分组"到"意图流"

> 系列：docs/agent-evolution/（00 为路线图总览，08 为缺陷追踪）
> 解决缺陷：D-emer1（涌现 = 静态时间分桶，无意图维度、无行动出口、权重写死、与 agent/任务体系隔离）
> 来源：用户需求重述（"更符合不同用户他们日常的意图"）+ file-emergence v1 现状取证（candidate-extractors/scoring/四时间桶，已实装）+ Matrix 证据聚合哲学
> 状态：设计稿

---

## 1. 需求再理解：涌现到底是为了什么

v1 的回答是"文件树顶部按 未来/今天/过去/遥远 四桶展示推断出的项目"。这回答的是**"我的东西怎么归类"**。但用户的真实日常问题是 **"我现在该做什么 / 系统能不能替我先想一步"**——涌现的本质应该是：

> **系统从使用痕迹中主动浮现"值得用户现在关注的事"，并且每件事都带着可以直接执行的出口。**

不同用户的"日常意图"不同（写作者：续写+素材；内容创作者：采集+剪辑；研究者：文献+笔记），但意图的**形态**是有限且共通的。v1 的根本局限：① 只有文件一种对象；② 只有时间一种组织维度；③ 只有"展示"没有"出口"（看到分组后还得自己想下一步）；④ 权重公式写死，不随用户行为校准；⑤ 与任务/agent/知识体系完全隔离——而那边恰恰有最强的意图信号（blocked 任务、待裁决证据、重复模式）。

## 2. 目标设计：统一涌现内核 + 意图流投影

### 2.1 保留 v1 的内核哲学，扩展信源与对象

v1 的 `候选抽取 → 资格判定 → 打分 → 置信度 → evidence[] 可解释` 管线是对的（与 Matrix 证据聚合同构），**不推倒**。重构点是把它从"文件涌现专用"升级为"涌现内核"：

```
信源（扩展）                      候选对象（扩展）
├─ 日历/文件活动/对话/浏览历史      ├─ 项目/文件聚类（v1 已有）
├─ task_projections（02 篇扩列后    ├─ 可续跑/待裁决/阻塞的任务
│   含 blocked/check_in_pending/    ├─ 重复模式 → 专项 agent / 技能候选（03 篇）
│   blockerCategory/续跑条件）       ├─ 重复主题 → 知识卡候选
├─ CheckIn 学习信号（02 篇）        └─ 已完结产物（待用户查收）
└─ 卡片访问信号（01 篇）
```

### 2.2 意图流（Intent Feed）：六类卡片

统一产出 `EmergenceCard`，按**意图形态**而非时间分类：

| 类型 | 回答的日常意图 | 数据源 | 一键出口 |
|------|---------------|--------|---------|
| 续上 resume | "我刚才/昨天做到哪了" | active/blocked 任务 + continuation_ref | 续跑（C2.4 链路）/ 打开会话 |
| 跟进 follow-up | "有什么在等我" | check_in_pending、blockerCategory=user_input_missing | 裁决卡（02 Q5）/ 补充信息 |
| 准备 prepare | "接下来有什么要来" | 日历未来事件 + 关联项目（v1 future 桶升级） | 打开项目 / 让 agent 预整理材料 |
| 收割 harvest | "做完的东西在哪" | completed 任务的 proof 产物（近 N 天未打开过的） | 打开产物 / 归档 |
| 成形 forming | "我手头在长出什么项目" | v1 项目聚类（today/past 桶升级） | 打开项目组 / 命名确认 |
| 沉淀 crystallize | "系统学到了什么、要不要采纳" | 03 篇候选卡（agent/技能/知识候选）、疑似重复卡 | 确认成立 / 驳回 / 合并 |

**每张卡必须三件套齐**：evidence 链（可解释，复用 v1 结构）+ confidence + 行动出口。没有出口的卡不投影（纯信息归入各自面板，不占意图流）。

### 2.3 投影策略：一个内核，两个视图 + 一个注入

| 消费者 | 形态 | 说明 |
|--------|------|------|
| 工作台意图流（新） | 首页/侧栏卡片流，按"今天相关度"排序，≤8 张，可折叠分组 | 主交互面 |
| 文件树四桶（v1 保留） | 现状不动 | forming/prepare 类卡的文件视角投影，向后兼容 |
| 模型注入（06 X1） | 任务索引行 | resume/follow-up 卡与任务索引**同源同数据**——给用户看的是卡，给模型看的是行 |

第三行是本设计的关键收益：**意图流与上下文注入共享一份"当前值得关注的事"的计算结果**，用户与 agent 看到同一个世界，"用户点了续上"与"agent 被注入续跑条件"天然一致。

### 2.4 个性化：权重漂移而非写死公式

- 每张卡的曝光/点击/驳回/忽略记入反馈日志（复用 file_activity_events 模式，新增 emergence_feedback 事件类型）；
- 维护回合（03 篇）周期性消化反馈：某类卡持续被驳回 → 降低该类型对该用户的权重（写成 preference 卡，01 篇体系内，可被用户看到和删除——个性化是**可解释可撤销**的，不是黑盒）；
- 卡类型可在设置中关闭；
- 默认权重模板按 v1 公式起步，漂移幅度有界（±50%），避免反馈回路失控。

### 2.5 隐私与降噪边界（防止意图流变成新通知噪音）

**隐私**：
- proof 路径展示规则：卡片只展示产物**名称与类型 + 跳转**，不内联渲染内容；secret-storage 引用、`.env`/凭证类路径、隐私目录（可配置）下的产物**不出现在卡面**（显示"产物已生成（受保护路径）"）；
- 第三方来源的证据（浏览历史/网页断言）在卡面必须标注来源域名；
- 沉淀类卡（候选采纳/记忆晋升）涉及"系统对用户的画像"，措辞用观察句不用判断句（"最近 5 次让我整理周报" 而非 "你是一个需要周报助理的人"）。

**降噪与去重优先级**（同一对象只出现一次，规则定死）：
- 任务面板 vs 意图流：意图流只收"**需要用户行动**"的任务卡（续跑确认/裁决/补信息），纯进行中任务留在任务面板——意图流是行动队列不是状态镜像；
- 意图流 vs 文件树四桶：文件/项目对象优先在文件树视图，仅当其携带行动出口（如"日历明天有关联日程 → 预整理"）才进意图流；
- 二次确认分级：续上/跟进卡一键执行（低危）；沉淀类卡（派生 agent/晋升记忆/更新站点风险）**必须**显式确认且不可一键批量；涉及 M2 动作的出口（如"清理这批文件"）走 05 篇确认闸门，意图流不豁免；
- 全局上限 ≤8 张 + 单类型 ≤3 张 + confidence 门槛 + 反馈降权，四重控制。

## 3. 与 v1 实现的迁移关系

| v1 资产 | 去向 |
|---------|------|
| candidate-extractors / scoring / confidence / evidence | 升级为涌现内核公共模块（加任务/CheckIn/候选三个 extractor） |
| 四时间桶 + FileEmergenceSection UI | 保留为文件视图，消费内核的 forming/prepare 卡 |
| 10 分钟缓存 + stale 标记 + 异步刷新 | 内核级复用（意图流同策略；任务类卡走事件桥即时失效） |
| file_emergence_enabled 开关 | 拆分为 emergence_file_view / emergence_intent_feed 两开关 |

## 4. 工作包拆分与验收

| WP | 内容 | 依赖 | 验收 |
|----|------|------|------|
| E1 | 涌现内核抽取（EmergenceCard schema + 三个新 extractor：任务/裁决/候选） | 02 Q1（任务信号字段） | 单测：六类卡各自从 fixture 信号正确产出，evidence 完整 |
| E2 | 工作台意图流视图 + 行动出口接线（续跑/裁决/确认候选） | E1、02 Q5、C2.4 | 端到端：blocked 任务 → 卡 → 点击续跑成功；候选卡 → 确认 → 04 派生流程 |
| E3 | 反馈日志 + 卡类型开关 | E2 | dismiss 持久化；关闭类型不再投影 |
| E4 | 权重漂移（维护回合消化反馈 → preference 卡） | E3、03 C3 | 连续驳回 N 次 → 权重下降且 preference 卡可见可删 |

v1 范围（对齐 00 路线图）：E1+E2 先做 **resume / follow-up / 沉淀** 三类（意图密度最高、数据这就绪）；prepare/harvest/forming 随 v1 文件涌现的既有数据逐步并入。

风险：意图流变成通知噪音 → ≤8 张硬上限 + confidence 门槛 + 反馈降权三重控制；与文件树视图重复感 → 两视图卡片互相去重（同一对象只在更相关的视图出现）。
