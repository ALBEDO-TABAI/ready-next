# 设计明细 11：浏览器执行体系重构

> 系列：docs/agent-evolution/（00 为路线图总览，08 为缺陷追踪）
> 解决缺陷：D-brow1（工具粒度碎片化、planner 改写任务、无脚本通道、无交互纪律、站点知识不沉淀、委托边界过大）
> 来源：用户需求（"matrix 浏览器功能更体系、更广泛适用、更目标高效"）+ Matrix browser-skill 深读（52KB，双通道/快照纪律/定位器优先级/错误恢复状态机/token 经济/确认政策）+ ready 现状取证（25 交互 + 13 采集工具、browser-task-planner 预编译 BrowserTaskPlan、BrowserDomainOrchestrator V7 工作流引擎、S3 采集判定矩阵已合入）
> 状态：设计稿

---

## 1. 现状诊断：六个结构性问题

| # | 问题 | 表现 |
|---|------|------|
| 1 | **逐工具回合制** | 25 个细粒度交互工具，每个动作 = 一次模型回合（点击→等返回→再思考→输入→…），token 重、延迟高、长链易断 |
| 2 | **planner 预编译改写任务** | browser-task-planner 在代码侧把用户意图编译成 BrowserTaskPlan——正是 Matrix 明令禁止的"rewrite it into a brittle keyword plan"，意图在编译中失真（live-info/collection intent 检测仍是模式匹配） |
| 3 | **无脚本通道** | 结构稳定、可重复、可验证的步骤（翻页、批量读字段、表单填写）没有"一次脚本搞定"的通道，被迫拆成几十个工具回合 |
| 4 | **无交互纪律合同** | 快照新鲜度、定位器唯一性、失败恢复策略没有系统化——每次都靠模型即兴，同错误反复踩 |
| 5 | **站点知识不沉淀** | 登录墙行为、反爬风险、选择器特征、限速经验留在单次会话里，下次重新踩坑 |
| 6 | **委托边界过大** | workflow 引擎接管整个用户任务，调用方失去掌控——Matrix 的纪律是"只委托一个边界清晰的步骤，调用方保持任务所有权" |

S3 系列已修好**采集判定层**（verdict 矩阵/失败账本/轮播），本篇针对的是其上的**交互执行层**。

## 2. 目标架构：双通道 + 纪律合同 + 站点知识

```
调用方（主/专项 agent，持有任务所有权，按 09 篇分包）
   │
   ▼ 通道决策树（技能资产里的硬规则）
   ├─ DOM 稳定、步骤可精确表达、需重复/可验证 ──► 脚本通道 browser_run_script（新）
   ├─ DOM 不稳、视觉路径更清楚、防爬风险站点 ───► 视觉/工具通道（现有 25 工具回合制）
   └─ 批量采集 ────────────────────────────────► 采集管线（现有，S3 已加固）
   │
   ▼ 共享底座
   交互纪律守卫（快照新鲜度/定位器唯一性/恢复状态机）
   站点知识卡 knowledge/sites/{domain}.md（01 篇体系）
   确认闸门（传输类动作走 I3，05 篇）
```

### 2.1 批量执行通道（核心新增——**spike 假设，形态未定**）

⚠️ 定位修正（Codex 评审采纳）："任意 JS 字符串执行"只是 spike 要验证的**上界假设**，不是既定设计。spike 按保守优先评估两个候选：

- **候选 A（优先）：受限脚本 / 操作 DSL**——一次提交一个预定义操作序列（goto/snapshot/locator/click/fill/extract/assert 的 JSON 编排，支持简单循环与变量），运行时逐步执行。表达力低于 JS 但天然可审计、可静态校验、安全面小——已足够消灭"翻页取数"类回合开销；
- **候选 B（上界）：受限 JS 沙箱**——仅当 DSL 表达力实测不够（如复杂条件分支/数据变换）才升级；沙箱只暴露浏览器操作 API，无 Node、无 require、无网络直连。

**两个候选共用的安全清单（任一形态都必须满足，列为 spike 验收）**：
1. 域名白名单——脚本/序列只能操作声明过的域，跨域跳转即中止；
2. 写操作租约——修改性动作（click/fill/submit）需持有执行租约（Matrix cursor lease 的移植），一序列一租约，完成即释放；
3. 表单提交拦截——transmission 类动作（submit/支付/消息发送）运行时挂起，走 05 篇冻结放行闸门，不信任脚本自律；
4. 跨 tab 状态隔离——序列绑定单 tab（多 tab 需显式声明 target），不得触碰用户其他标签页；
5. 审计日志——每个动作（含参数摘要与结果）落 ready-browser.log，序列全文存档可回放。

**持久状态**：跨调用保留绑定（tab 引用、中间数据），不每次重建。**收益目标**："翻页取数类回合数较工具通道降 ≥80%"是 **spike 目标与立项依据，不是正式验收硬指标**——spike 结束后按实测改写为真实数字进实施合同。

### 2.2 交互纪律合同（提示词资产 + 运行时守卫双轨）

提示词侧（`prompts/browser/discipline.md`，06 X3 资产化，内容移植 Matrix）：

1. **五步交互配方**：确认快照够新 → 从最新快照构建最稳定定位器 → 唯一性不显然则 count() → 恰好 1 个才执行 → 动作改变 UI 才重拍；
2. **定位器优先级**：data-testid → 稳定 data-* → 稳定 href → 角色+可访问名 → 作用域 getByText → 作用域 CSS → 兜底坐标/节点路径；
3. **错误恢复状态机**：歧义（strict violation）→ 不重试、新快照紧作用域；语法错 → 不复用同形式；超时 → 新快照确认目标存在再重建；同目标两连败 → 停止升级复杂度、降级稳定属性；
4. **token 经济**：禁止全文倾倒（body.textContent 当搜索引擎）、禁止逐元素遍历读取、宽观察定向后缩小到容器、快照未变则复用。

运行时侧（守卫，fail-fast 结构化错误）：定位器解析到 0/多个 → 拒绝执行并返回 `{kind:'locator_ambiguous', count}`（模型据此走恢复状态机，而非靠自觉）；快照陈旧计数器（页面导航后旧快照引用报 `snapshot_stale`）。**Matrix 用提示词约束，ready 有运行时层可以把关键纪律变成硬错误**——这是后发优势。

### 2.3 站点知识卡（与 01/03 闭环）

`knowledge/sites/{domain}.md`（belief card 的子类，tag: knowledge）：

```yaml
---
title: 小红书站点特征
confidence: H
tag: knowledge
site: xiaohongshu.com
riskLevel: high          # 反爬风险 → 通道决策树强制视觉通道
---
- 防爬：脚本检测严格，禁用脚本通道（封号风险）
- 登录墙：详情页需登录；登录态 cookie 有效期约 X 天
- 选择器：feed 卡片容器 [data-v-xxx]；轮播指示器 .swiper-pagination
- 限速：连续翻页 > N 次触发验证
```

- **读**：通道决策与执行前，按当前 domain 命中即读（索引线索机制，01 §6）；
- **写**：两个来源——执行失败的 CheckIn（learningDecision: memory_card，02 篇）当轮写（落 staged）；crystallize（03 篇）从重复失败模式补写/升降置信度；
- **预置**：首批内置 5-10 个高频站点卡（小红书/微博/B站/知乎/淘宝），作为种子资产随应用分发（嵌入式技能模式）。

⚠️ **与现有站点真值源对齐（防双源漂移，Codex 评审第 14 点）**：ready 已有代码侧站点事实——`browser-site-experience-store` 与高风险站点禁用守卫。规则定死：

- **执行强制类事实**（riskLevel、禁脚本、限速阈值）：**代码 store 是唯一权威**，守卫只消费 store；知识卡 frontmatter 的 `riskLevel` 是 store 的**只读镜像**（同步生成，卡片手改无效），卡片永远不能独立改变守卫行为；
- **经验叙述类事实**（选择器特征、登录墙行为、踩坑记录）：知识卡是权威，store 不存这些；
- **学习回路的升级路径**：crystallize 从失败模式发现"某站风险应上调" → 产出**建议卡**（staged）进意图流沉淀类 → 用户确认 → 写 store（经专用更新接口）→ 卡镜像随之刷新。学习永远不直改 store。

### 2.4 委托边界重构

- **planner 降级为建议器**：browser-task-planner 保留 tab 上下文收集与连续性提示，产出**建议**（候选 tab、可能的延续任务、站点卡命中提示），不再产出执行计划；用户原话逐字直达执行 agent（05 I4 最小传话）；
- **workflow 引擎接包不接任务**：BrowserDomainOrchestrator 的执行单元改为 09 篇的任务包（边界清晰的一步 + 编译期 Criteria），调用方保持所有权与汇总责任；
- **采集管线不动**：S3 已加固的 verdict/重试/轮播链路保持，作为"批量采集"通道继续服务。

## 3. 通道决策树（写进技能资产的硬规则）

```
需要浏览器 →
  store riskLevel=high？（browser-site-experience-store 为权威；站点卡仅镜像/说明）
                    ──是──► 视觉/工具通道（或建议用户手动）
  │否
  步骤可用 DOM 精确表达且可验证？ ──是──► 脚本通道
  │否（视觉判断、布局不稳、探索性浏览）
  └──► 视觉/工具通道
  批量同构采集？ ──► 采集管线（独立判定）
```

## 4. 工作包拆分与验收

| WP | 内容 | 依赖 | 验收 |
|----|------|------|------|
| B1 | 批量执行通道 spike：DSL（候选 A）优先评估，JS 沙箱（候选 B）为上界；安全清单五项全验证 | 无（spike 先行） | spike 报告：形态选型 + 安全清单逐项证明 + 翻页取数实测回合数（spike 目标 ≥80% 降幅，按实测定正式指标） |
| B2 | 交互纪律提示词资产（决策树/五步配方/恢复状态机/token 规则） | X3 | 资产快照测试；含站点黑名单硬规则 |
| B3 | 站点知识卡 schema + domain 命中读取 + 种子卡 ×5 | 01 K1 | 命中小红书 → 强制视觉通道的端到端 |
| B4 | 运行时守卫（locator 唯一性 fail-fast + snapshot 陈旧检测） | B1 | `locator_ambiguous` 触发模型恢复路径的行为测试 |
| B5 | planner 降级 + verbatim 直达 + workflow 接包改造 | I4、09 PK3、S4 稳定后 | 计划改写消失断言：执行侧收到的 brief = 用户原话片段 |
| B6 | 失败 → 站点卡学习回路（CheckIn/crystallize 写卡） | 02 Q4、03 C3 | 注入一次登录墙失败 → 站点卡产生/更新 |

分期：**B2+B3 先行**（纯提示词与知识资产，零运行时风险，立即改善现有通道的行为质量）→ B1 spike 并行 → B4 随 B1 → B5/B6 在 09/02/03 就绪后。

风险：脚本通道被滥用于风险站点 → 站点卡 riskLevel 硬拦 + 默认白名单渐开；CDP attach 与现有 browser-engine 冲突 → spike 阶段先验证共存，不行则退化为"受限脚本 DSL"（预定义操作序列一次提交，仍可砍掉大部分回合）；planner 降级回归风险 → 建议器与旧路径灰度并行一个版本。
