# 文档模式「源码 / 排版」收口设计

- 日期：2026-03-25
- 主题：文档模式去掉独立预览，将“排版”收敛为唯一成品界面
- 相关范围：
  - `src/renderer/pages/modes/DocumentMode.tsx`
  - `src/renderer/components/document/MarkdownEditor.tsx`
  - `src/renderer/components/document/TiptapEditor.tsx`
  - `src/renderer/components/document/DocumentWidgetBlockCard.tsx`
  - `src/renderer/components/document/NotePreview.tsx`
  - `src/renderer/components/document/WidgetRenderer.tsx`
  - `src/renderer/components/document/note-preview-parser.ts`
  - `src/renderer/styles/index.css`
  - `src/renderer/styles/tiptap.css`

## 1. 背景与问题

当前文档模式在文本类文件上同时存在 `源码 / 排版 / 预览` 三套心智：

1. `源码`：显示 Markdown 原文。
2. `排版`：更接近所见即所得，但仍带有编辑属性和生成式内容操作按钮。
3. `预览`：走另一套结构化笔记展示链路，内容编排、属性展示和生成式内容包装方式与排版不一致。

这导致了几个具体问题：

- 用户很难判断哪个界面才算“最终效果”。
- “排版”和“预览”都在承担成品展示，职责重叠。
- 生成式内容在两套界面中重复渲染、重复维护。
- 后续若要做导出功能，很难确定到底复用哪一条渲染链。

## 2. 目标

本次收口目标如下：

1. 文本类文档只保留两档：`源码`、`排版`。
2. `排版` 成为唯一成品界面，承担阅读、展示、导出预备态。
3. `源码` 成为唯一编辑界面，承担精确改写与生成式内容操作。
4. 生成式内容在两个界面都可见，但角色不同：
   - `排版`：只显示最终内容，不显示操作控件。
   - `源码`：显示内容与编辑动作。
5. 清理掉“排版”和“预览”之间重复、冲突的展示逻辑。

## 3. 非目标

本次不处理以下事项：

- 不重做文本编辑器底层能力。
- 不重做 `show-widget` 语法或文档工具协议。
- 不在本次直接交付完整导出功能，只把排版界面收口成未来导出的可信基础。
- 不改变图片 / 视频 / PDF / 表格等非文本文档的独立查看链路。

## 4. 备选方案

### 方案 A：只保留 `源码 / 排版`，排版吸收预览能力

做法：

- 删除顶部 `预览` 按钮。
- 将 `预览` 中真正属于成品展示的能力并入 `排版`。
- `排版` 成为唯一的成品视图。

优点：

- 用户心智最清晰。
- 导出基线唯一。
- 生成式内容不再需要维护两套成品包装。

代价：

- 需要把当前 `NotePreview` 中有价值的展示能力有选择地并入 `排版`。
- 需要重新界定源码模式与排版模式下生成式内容卡片的行为。

### 方案 B：保留排版正文，结构化内容另找次级入口

做法：

- 删除顶部 `预览` 按钮。
- 排版只展示正文，不吸收属性区、头图、结构化标签等。
- 结构化内容通过别的入口查看。

优点：

- 实现更轻。
- 排版界面更克制。

缺点：

- 仍然不是完整成品视图。
- 用户仍需寻找额外入口。
- 导出链路仍不够明确。

### 方案 C：隐藏预览但保留两套底层展示

做法：

- 主按钮不显示 `预览`，但底层继续保留独立预览链路。

优点：

- 表面改动最小。

缺点：

- 实际复杂度不降。
- 割裂感继续存在。
- 未来导出和生成式内容维护仍然混乱。

## 5. 最终决策

采用 **方案 A**。

用户已确认以下方向：

1. 文本类文档最终只保留 `源码 / 排版` 两档。
2. `排版` 应直接等于今天用户认知里的“预览 / 成品”。
3. 生成式内容的操作按钮不应留在成品界面，而应收回到源码模式。
4. 排版界面需要更干净，以便未来导出直接复用。

## 6. 最终交互设计

### 6.1 模式规则

#### 文本类文档

- 适用：`md / markdown / txt / docx`
- 顶部只显示：
  - `源码`
  - `排版`
- 默认打开：
  - `排版`

#### 代码 / 配置类文件

- 适用：`json / ts / tsx / js / jsx / css / html / yaml / xml ...`
- 只显示：
  - `源码`

#### 二进制 / 查看类文件

- 适用：图片 / 视频 / PDF / 表格
- 继续使用各自独立查看器，不强行套入 `源码 / 排版` 切换。

### 6.2 排版模式定义

排版模式是唯一成品界面，原则如下：

- 不承担编辑职责。
- 不出现调试型、编辑型、管理型操作按钮。
- 视觉上接近可直接导出、可直接交付、可直接阅读的文档。

排版模式保留内容：

1. 文档标题与正文层级。
2. 标签、作者、更新时间、状态等轻信息。
3. 头图 / 视频封面 / 媒体首图等成品内容。
4. 正文中的图片、链接、代码块、引用、列表。
5. 结构化属性块与关联信息，但视觉上做弱化，不做成工具面板。
6. 生成式内容（图表、信息卡、可交互模块）的最终展示结果。

排版模式移除内容：

1. `让 agent 更新`
2. `查看源码`
3. `复制源码`
4. `删除`
5. “源码已折叠”“可直接在下方编辑”等编辑提示
6. 仅对编辑场景有意义的状态标签或边框

### 6.3 源码模式定义

源码模式是唯一编辑界面，原则如下：

- 始终可以精确定位并改写原始 Markdown / 文本。
- 对生成式内容保留更强的操作能力。
- 界面允许带有工具性，但不需要承担最终成品观感。

源码模式中，生成式内容以“编辑卡片”呈现：

- 保留内容预览，方便边改边对照。
- 保留操作按钮：
  - `让 agent 更新`
  - `查看源码`
  - `复制源码`
  - `删除`
- 保留源码可展开能力，支持精确修改与定位。

## 7. 组件与渲染链收口

### 7.1 顶部模式切换

当前：

- `DocumentMode` 根据文件类型给出 `source / rich / preview` 等不同选项。

调整后：

- 文本类文档只返回 `source / rich`。
- `rich` 在文案上仍显示为 `排版`。
- 删除对 `preview` 的主入口暴露。

### 7.2 `MarkdownEditor`

当前：

- `source` 渲染原文。
- `rich` 渲染 Tiptap。
- `preview` 渲染 `NotePreview`。

调整后：

- 删除 `preview` 分支。
- `rich` 成为唯一成品展示界面。
- `source` 保留为原文与生成式内容操作层。

### 7.3 `TiptapEditor` 与生成式内容卡片

当前：

- `show-widget` 在排版编辑器里被替换成带按钮的 `DocumentWidgetBlockCard`。
- 卡片包含 “预览” 等动作。

调整后：

- 该卡片明确只属于源码模式。
- 移除 `预览` 动作。
- 保留编辑相关动作。
- 卡片文案从“预览跳转”改为“源码编辑辅助”。

### 7.4 `NotePreview` / `note-preview-parser`

当前：

- 这是独立成品渲染链，包含属性区、标签、头图、媒体块、生成式内容块。

调整后：

- 不再作为独立模式入口。
- 其中真正有价值的结构化展示能力需要被迁移或复用到排版模式。
- 可以保留解析器 / 数据整理逻辑，供排版模式消费，而不是直接保留原样界面。

### 7.5 `WidgetRenderer`

当前：

- 同时被排版卡片和独立预览链路使用。

调整后：

- 继续作为统一内容渲染器保留。
- 排版模式直接展示其结果，但不包编辑按钮。
- 源码模式使用编辑卡片包装它。

## 8. 数据流与状态

### 8.1 视图状态

- 现有 `DocumentViewMode` 简化为：
  - `source`
  - `rich`
- 文本文档默认值改为 `rich`。
- 若收到旧状态中的 `preview`，在归一化时自动回落到 `rich`。

### 8.2 聚焦与跳转

- 文档引用跳转、聊天回跳等场景，继续优先落到源码模式，便于立即修改。
- 若未来需要“在排版中滚动到某个 widget 或段落”，可保留单独的滚动定位能力，但不恢复独立 `preview` 模式。

### 8.3 生成式内容操作

- Agent 更新 widget、查看源码、删除 widget 等上下文，仅在源码模式下暴露。
- 排版模式只消费最终内容渲染结果，不提供写动作。

## 9. 错误处理

1. 文本文档若结构化信息解析失败：
   - 排版模式仍应保证正文可展示。
   - 结构化区块可降级隐藏或退化为普通文本，不能影响整篇文档。

2. 生成式内容渲染失败：
   - 排版模式显示静态或错误兜底，但不暴露编辑动作。
   - 源码模式仍保留操作按钮，方便修复。

3. 旧的 `previewFocusWidgetTitle` / `onRequestPreview` 链路：
   - 需要清理或改造为“在排版或源码中聚焦内容”的新语义。
   - 不能继续保留名不副实的“预览”命名。

## 10. 实施步骤

1. 调整模式枚举与模式按钮，只保留 `源码 / 排版`。
2. 将文本文档默认模式改为 `排版`。
3. 从 `MarkdownEditor` 中删除独立 `preview` 分支。
4. 清理 `DocumentWidgetBlockCard` 中的“预览”动作与相关命名。
5. 保留源码模式下的生成式内容编辑卡片。
6. 把 `NotePreview` 里有价值的结构化展示能力迁到排版模式：
   - 属性区
   - 标签
   - 头图 / 媒体区
   - widget 成品展示
7. 统一排版模式视觉风格，使其更接近成品阅读界面。
8. 更新文档、变更记录与相关测试。

## 11. 验收标准

满足以下条件才算完成：

1. 文本类文档顶部只剩 `源码 / 排版`。
2. 文本类文档默认进入 `排版`。
3. 排版界面中不再出现生成式内容操作按钮。
4. 源码界面中仍可对生成式内容进行更新、查看源码、复制源码、删除。
5. 排版界面中能看到：
   - 标题
   - 正文
   - 属性 / 标签等结构化信息
   - 头图或媒体首图（若存在）
   - 生成式内容最终结果
6. 删除独立预览主入口后，现有文档查看、跳转、widget 展示不出现明显回退。
7. 自动检查通过：
   - 类型检查
   - 相关测试
   - 构建

## 12. 测试计划

### 12.1 单元 / 合约

- 模式可用项测试更新为：
  - 文本文档 => `source / rich`
  - 代码文档 => `source`
  - 二进制文档 => 各自查看链路
- 生成式内容卡片测试更新：
  - 源码模式保留编辑动作
  - 排版模式不暴露编辑动作

### 12.2 集成回归

- 打开 Markdown / TXT / DOCX，确认默认进入排版。
- 切换到源码，确认原文可编辑、可保存。
- 文档中包含 `show-widget` 时：
  - 排版模式只显示成品
  - 源码模式保留操作卡片
- 文档引用回跳仍能正确定位。
- 图片 / PDF / 表格等文件不受本次模式收口影响。

### 12.3 视觉验证

- 排版模式整体观感不再像“另一个编辑器状态”，而更像正式文档。
- 生成式内容在排版模式下观感与正文一致，不显得像调试面板。
- 源码模式的生成式内容卡片仍然方便实际编辑，不变成纯原始文本噪音。

## 13. 风险与注意事项

1. 若直接删除 `preview` 而不迁移结构化展示能力，排版界面会变得“太薄”。
2. 若把结构化展示能力硬塞进现有 Tiptap 编辑视图，容易再次混入编辑心智，需要明确区分“排版层展示”与“源码层编辑”。
3. 若保留旧的预览命名但改变含义，会让后续维护更加混乱，建议同步清理命名。
4. 导出功能未来应优先复用排版渲染链，因此当前排版层不应依赖编辑专用控件。
