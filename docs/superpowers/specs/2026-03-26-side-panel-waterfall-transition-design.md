# Side Panel Waterfall Transition Design

**Date:** 2026-03-26

## Goal

把工作台左侧的 `文件管理`、`全局搜索`、`技能中心` 从“点击后瞬间硬切”改成更连贯的上下接力切换。修正后的目标效果是：

- 外层面板框保持不动，像固定视窗
- 真正移动的是视窗里的标题行和内容层
- 旧内容向上流动时，会在顶部被遮挡消失
- 新内容不是整块浮进来，而是从底部逐步露出
- 标题行也按同样逻辑交接，不再像单独漂浮的胶囊
- 透明度只做极轻微辅助，不能再让人感觉“整块面板在淡出淡入”
- 滚动方向要跟左侧按钮的上下层级关系一致，不能无论怎么切都只朝一个方向
- 标题和内容应共用同一条滚动节奏，避免落位时速度抖动

## Current Structure

- 侧栏入口在 `src/renderer/pages/WorkbenchMode.tsx`
- 图标点击只修改 `sidePanelVariant`
- 真实渲染发生在 `src/renderer/components/layout/SidePanel.tsx`
- `FilesPanel`、`GlobalSearchPanel`、`SkillsCenterPanel` 当前都各自绘制标题与内容

这意味着最合适的改动位置不是分别给三个面板塞动画，而是在共享壳层里建立统一切换编排，同时把标题和内容拆成可复用片段。

## Chosen Approach

采用“共享壳层编排 + 固定视窗遮挡 + 标题/内容分离”的方式：

1. 由 `SidePanel` 负责追踪“当前显示面板”和“正在切入面板”
2. 切换时短时间同时保留旧面板和新面板
3. 标题区域和内容区域都放进固定高度的遮挡视窗
4. 旧层与新层同时存在，但只移动内部内容，不移动视窗本身
5. 内容区域做“向上流过窗口”的交接动画
6. 标题区域也做同样的纵向交接，只是节奏略慢一点
5. 三个面板内部业务逻辑继续留在各自组件里，不把文件搜索、技能列表这些状态搬到壳层

## Why This Approach

- 最接近用户想要的“瀑布流式接力”感受
- 宽度与显隐逻辑还能继续沿用现有 store
- 不需要重写三个面板的内容逻辑
- 后续如果还想给别的侧栏模式加同类切换，可以直接复用

## Interaction Details

### Content handoff

- 内容视窗固定不动，并裁掉溢出内容
- 旧内容层内部整体上移，在顶部被遮挡掉
- 新内容层内部从下方进入视窗，像本来就在下方等待露出
- 不再使用明显的整层淡出淡入，也不做横向位移

### Title handoff

- 标题行本身也放在固定高度视窗中
- `文件管理` / `全局搜索` / `技能中心` 这一行按相同逻辑向上流动
- 旧标题在顶部被裁掉，新标题从底部露出，不再像单独浮层交叉淡化

### Motion constraints

- 节奏比上一版更慢，优先给“流过窗口”的直觉，不抢眼
- 标题和内容共用同一条主节奏，不再分别延迟
- 从上往下切与从下往上切要严格镜像
- 尊重系统减弱动效偏好，必要时退化为简化切换
- 连续快速点击时，以最后一次目标为准，不允许残留错误标题或空白面板
- 外层宽度动画继续保留，但不能让人感到内容层被整块推动

## Component Boundaries

- `SidePanel.tsx`
  - 新增切换编排
  - 统一渲染标题槽和内容槽
  - 处理切换阶段、方向与动画 key
- `FilesPanel.tsx`
  - 抽出标题文案和主体内容片段
- `GlobalSearchPanel.tsx`
  - 抽出标题文案和主体内容片段
- `SkillsCenterPanel.tsx`
  - 抽出标题文案和主体内容片段

## Risks And Mitigations

- 风险：快速切换时状态错位
  - 处理：用显式切换阶段和稳定 key 控制旧新面板并存周期
- 风险：每个面板原本自己带标题，拆分时容易影响布局
  - 处理：只搬走第一行标题，主体间距继续沿用原 panel token
- 风险：动画很花但不顺手
  - 处理：限制位移距离和时长，避免过长、过飘

## Validation Plan

- 补一条更具体的侧栏切换契约测试，防止退回“整块淡入淡出”的实现
- 运行相关测试与类型检查
- 启动应用，实际点击 `文件管理 -> 全局搜索 -> 技能中心 -> 文件管理`
- 重点确认：
  - 标题和内容都像在固定视窗中上卷
  - 顶部确实是被遮挡消失，而不是整块飘走
  - 面板不闪白
  - 文件管理内部滚动和搜索输入内容不会因为切换被清空
