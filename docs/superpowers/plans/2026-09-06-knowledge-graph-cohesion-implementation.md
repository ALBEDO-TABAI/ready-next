# 关系图谱整体聚拢

用户目标：接近所附 Obsidian 截图的整体圆形分布；真实关系形成可辨识的小群，无关联节点也属于同一片点云。

## 根因与范围

现有布局按连通分量排货架、给孤点设置分量禁入区，再用每点固定锚点保留这些隔离。高连接数节点的单圈半径随子节点数量线性增长，放大空洞。仅改中心力或视口缩放不能消除初始化造成的巨大空白。

只修改 Renderer 图谱布局、连接角色配色与必要的自动取景时机，不修改图数据、节点类型、真实连接、文档打开和用户手动视口。

用户后续补充：中心点应更大，发散点用不同颜色，与无关联点区分。以真实相邻节点数判断：0 为灰色独立点，1 为橘色关联端点，2 及以上为强墨色连接中心，大小随连接数增长并封顶。文档与标签使用同一规则；未解析目标仍保持较低透明度。布局、正式绘制和绘制回退共用去重后的有效邻接事实，反向重复边、自连和缺失目标不能制造虚假的中心点。

## 先写行为合同

归属：`src/__tests__/search-force-layout.serial.test.ts` / `npm run verify:knowledge-graph`。

1. 数百条连接的中心节点初始化占地随节点数的平方根增长，不能形成巨大空心单环。
2. 混合大星群、小星群和大量孤点，在初始与稳定位置均形成近圆形整体；以邻近点距离验证没有远离主体的孤岛。
3. 全孤点、纯关系群和稀疏工作区均保持有限坐标、局部关系辨识度和有界收敛。
4. 保留按节点 ID 恢复位置、局部拖动、拖动避让、释放回弹与空间网格性能合同。
5. 实际 Electron 中验证真实 GraphView 与 Worker：整体形态、稳定取景、缩放/移动、悬浮、点击与切换重开。使用合成文档，截图不含个人资料。
6. `graph-canvas-renderer.test.ts` 在明暗主题、文档/标签类型、重复/反向/自连/无效边下验证角色颜色与中心大小；`graph-view-interactions.test.tsx` 验证布局完成后取景、逐帧不跳动、手动移动/拖点后不抢视口。
