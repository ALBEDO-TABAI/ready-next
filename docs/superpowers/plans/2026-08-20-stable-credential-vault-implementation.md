# Ready 稳定本地凭据库与外部服务升级恢复实施合同

## 1. 已证实的问题

Ready 当前把外部服务与远程 IM 密钥交给 Electron `safeStorage`，并在 Main 同步解密。当前本机发布包使用 ad-hoc 签名，每次打包的应用身份都会变化；升级后旧密钥可能无法再由新包读取。现行失败分支又把原始 `__enc__...` 返回给调用方，造成设置页假显示“已配置”、工具错误开放、密文进入请求以及 Main 等待系统钥匙串等同源问题。

这不是地图语义判断的兼容问题。地图、高级搜索、图片模型和远程 IM 都必须只消费同一个可验证的凭据状态。

## 2. 单一真值

1. 新凭据只写入 `<userData>/credentials/ready-credentials.json`；目录权限为 `0700`，文件和临时文件权限为 `0600`。
2. 文件使用版本化 JSON、原子替换和写后回读。损坏文件、符号链接、错误 owner 或无法收紧的权限一律关闭凭据能力，不覆盖原文件。
3. SQLite 只保存不可变的代际 handle，不保存明文、`safeStorage` 密文或可逆混淆值。handle 必须同时绑定业务 owner、字段名与随机代际，不能跨配置复用。
4. 启动先异步载入凭据库，再注册设置 IPC 与 Agent runtime；后续工具准入只读已冻结的内存快照，不在 Main 热路径访问钥匙串或同步读文件。
5. 公共状态只有 `ready | missing | recovery_required | vault_unavailable`。只有 `ready` 可算已配置并向外部服务发请求。

## 3. 保存与删除

1. 保存先用新代际写入凭据库并回读，再把配置切换到新 handle；配置写入失败时仍沿用旧代际，配置切换成功后才回收旧代际。
2. 清除先删除凭据；即使第二步失败，也只能表现为不可用，不得继续使用用户已清除的旧值。
3. IPC 回包、日志、错误、任务输入、环境变量与 Renderer 永不包含明文或旧密文。
4. 用户只修改名称、地址或开关时，尚未恢复的旧密文保持 `recovery_required`，不会被误删，也绝不会进入运行时。
5. 启动时只有在外部服务与远程频道两类引用都被完整解析后才清理无引用代际；任一 JSON、结构或 owner/字段身份异常都跳过整轮清理并保留全部凭据。

## 4. 旧数据迁移

1. `__enc__`、`__plain__` 和无 handle 的非空旧值都只是待迁移材料，不能以“非空”判定为已配置。
2. 启动不得自动访问系统钥匙串或尝试解密旧值；窗口可交互后只做一次本地分类，避免系统授权弹窗覆盖 Ready。
3. 旧材料原样保留并标记 `recovery_required`；只有用户重新填写的新值才能按“写凭据库并回读 → 写 handle”进入运行时。
4. 用户重新填写某一项后，新值立即成为唯一真值，并清除该项旧材料。
5. 迁移失败值不得进入 header、query、body、环境变量、sidecar 或连接测试。
6. 旧 Tavily/Jina 独立设置、一次性迁移函数和环境开关全部退役；运行时只读取凭据库支持的外部服务配置。

## 5. 地图路由

1. 高德启用且凭据状态为 `ready`：路线任务只开放 `map_plan_route`，排除网页与 Browser 工具。
2. 用户确实未配置：开放公开网页估算，并明确结果性质与“设置 > 外部服务”入口。
3. 用户有配置但状态为 `recovery_required` 或 `vault_unavailable`：不得伪装成未配置后静默走网页；保留地图主路径并返回明确恢复提示。
4. 本轮开始时冻结上述状态；轮中设置变化不改写本轮工具面。

## 6. 完成门槛

- 不同 ad-hoc 包连续安装后，新凭据仍可读取。
- 带旧密文的升级启动不访问系统钥匙串、不出现授权弹窗；本地分类幂等且不阻塞窗口。
- 设置显示、连接测试、工具准入与真实执行对四种状态完全一致。
- 凭据文件权限、非符号链接、原子写、写后回读与损坏文件拒绝都有行为测试。
- 生产代码不得出现旧 Tavily/Jina 设置名、迁移函数或紧急恢复开关，并由专项检查阻止回流。
- `verify:native`、设置专项、地图专项、typecheck 与包体验证通过。
- 新安装包中实测：记忆跨重启连续；高德已配置时走地图；未配置时才走诚实网页估算；日志无连续密钥解密失败。
