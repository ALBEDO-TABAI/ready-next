# 微信、飞书远程助手可靠性

## 范围与事实

用户要求按当前 Codex 内核完善绑定、通信和恢复。默认交付形态为本人绑定后的远程助手：明确文字输入经现有 `sendScoped` 准入，单独附件只入资源层。不得恢复旧 AgentSdkRuntime。保留工作树里已有的文档阅读器改动。

当前缺口：普通文字被资源入口直接结算；远程 scope 没有当前 Codex 初始 head；Python 入站队列 pull 即删除；微信提前提交游标且异常不会恢复 healthy；飞书 SDK 使用模块级事件循环，旧 stop 实际不存在；飞书附件发送被忽略；扫码完成依赖 Renderer 保存；连接测试/保存吞掉 adapter 启动失败。

本机参考：2026-09-05 `/Applications/ChatGPT Matrix Runtime.app/Contents/Resources/codex --version` = `0.153.0-alpha.5`。`app.asar` 中 `remote-connections-settings-d2a5835f4dca.js` 分开设备授权、在线状态、重连和撤销；`remote-conversation-page-b12640ba33a4.js` 用明确 thread/turn 身份发起输入。它不是微信/飞书网关；只借鉴身份、授权与连接状态分离，不复制其网络拓扑。飞书接口以官方 SDK 与 im/v1 协议为依据。

## 可执行合同（先于实现）

1. 入站消息在持久保存前不确认；pull 可重读，ack 幂等；子进程重启后未确认消息仍可读。微信游标在所有入站持久保存后推进。
2. 同一远程事件只产生一个输入；不同来源、账号、自然线程和发送人不得混合；禁止失效绑定和旧可见上下文写入新会话。
3. 仅已绑定本人文字启动当前 Codex `sendScoped`；资源消息、未授权消息和机器人消息不启动。每个自然线程串行执行，确认回复可绕过执行队列解除等待。
4. 远程初始 scope/head 使用现行 Codex 创建合同；最终回复仅消费 canonical closeout 结果；消息/附件持久化不由远程入口重复写入。
5. 执行中断不自动重跑未知外部动作；回复状态未知不盲重发。恢复后给出明确可见状态。
6. 微信扫码完成由 Main 保存并启用；重绑、取消、设置页关闭、旧扫码结果都不能覆盖新绑定。停用后的迟到收信不消费，旧连接不得重启复活。
7. 飞书 SDK 连接只由一个事件循环管理；连接成功前不显示已连接；重复 start 不重复连，stop 后线程/网络任务可回收。鉴权失败、权限不足、发送失败如实返回。
8. 飞书图片/文件上传后使用真正的消息键发送；失败不报成功；话题回复回到原话题；长文本分段不切断 Unicode 字符。

## 实现与当前证据

- 已用每条事件独立的持久入站替代仅在内存合并的入口；Main 事件仓储、Python 持久队列和显式 ACK 配套，异步执行按远程会话串行。
- 原生首次准入同时需要有效 head action 引用和明确工作面；远程入口读取当前 Main 投影，并调用同一个 `sendScoped`。实机演练复现并修复了两项遗漏，没有削弱准入条件。
- 微信扫码由 Main 收口；请求网络前先保存本次身份，绑定身份和完成记录在同一事务提交，所有通道变更经同一队列同步。取消和删除先写本地真值，迟到结果不能重新启用。现有凭据经微信收信接口验证成功后，可恢复原账号身份；只接受完全匹配的原账号，旧回执、旧绑定及已取消的扫码不能接管新绑定。失效凭据仍需本人扫码。
- 飞书本人绑定码只接受私聊且只能消费一次；正常消息与附件携带生产者绑定身份。公网回调在缺少验证密钥或通道停用时拒绝，不能绕过长连接授权。
- 飞书发送文件、图片及原话题回复按实际接口执行；微信游标在事件落盘后更新，删除绑定清理对应账号凭据。发送结果未知由本地发送记录阻止盲重发。
- `verify:remote-im`：86 项 TypeScript/Electron 行为检查通过，无跳过；19 项 Python 专项由同一 gate 运行，全部通过。`verify:native`：179 项通过，无跳过。类型、版本、迁移编号和 CSS 约束检查通过。
- 本地真实 Electron + 当前 Codex + 飞书 SDK + 回环接口完成本人配对、首轮与第二轮收发、重复/未授权消息拦截、纯附件保存及设置页验证；并通过微信旧凭据恢复、连续两轮收发及重复/未授权消息拦截；四轮主账本均为 `done/done`。这证明应用整条调用链，不代表真实微信/飞书账号联网验收。
- 全局 `check-silent-catch` 当前仍有 180 项历史缺口；用未改动 HEAD 的独立临时源码副本执行同一检查也为 180 项，按文件与内容摘要比较本轮新增为 0，没有把全局检查标为通过。
- 回放命令：`READY_REMOTE_TEST_PYTHON=<安装 requirements.txt 的 Python> npm run verify:remote-im-live`。安装包可用 `READY_REMOTE_PROOF_APP=<挂载的 Ready.app 路径>` 运行相同脚本；回执及截图写入 `outputs/remote-im-live-*`，临时账号配置在进程退出后删除。
- 当前日常应用仅有旧微信配置；没有飞书应用配置。最终真实服务联调需要用户自己的飞书应用配置，以及必要时的微信扫码。个人凭据没有读取或导出到文档/安装包。
