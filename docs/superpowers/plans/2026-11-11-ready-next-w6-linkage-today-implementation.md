# Ready Next W6 串联与今日：一种引用，一条收下的路，一页此刻

属于 [收束路线图](2026-11-11-ready-next-coherence-roadmap.md) 的 W6。证据：[b-shell](../audits/2026-11-11-ready-next-coherence-audit/b-shell.md) §3–§6 与实机观察 O4、O13。依赖 [W2](2026-11-11-ready-next-w2-shell-unification-implementation.md)、[W3](2026-11-11-ready-next-w3-library-model-implementation.md)；今日页的资讯区依赖 [W5](2026-11-11-ready-next-w5-rss-sieve-implementation.md)，待办区依赖 [W4](2026-11-11-ready-next-w4-module-surfaces-implementation.md)-T4。

## 1. 模块靠什么串起来

模块多不是问题，问题是从一处到另一处要不要想“怎么过去”。整合计划已经铺好了底：统一的引用（`ready://`）、对象身份、关系索引、日历四图层。还差的是用户摸得到的那一层：

| 串联方式 | 底层 | 用户摸得到的部分现状 |
| --- | --- | --- |
| 指过去：任何对象都能被引用、点开、看一眼 | ReadyRef、`open-ready-ref.ts`、速览 | 没有统一的引用胶囊；各处是普通链接，点法不一样；有的类型点不开，速览多数只给路径或网址 |
| 拿过来：在哪看到的都能收下，并记得出处 | FastCard、画板句柄、文档写入服务、来源页 | 资讯、书、PDF 进不了 FastCard；FastCard 拖不进画板；拖拽有三种互不相认的格式 |
| 回得去 | `reference-return.ts` | 只记一步，只在内存里；浏览器里不显示返回 |
| 同一条时间线 | 日历图层、“这一天” | 已有，由 W4 补待办 |
| 一处看全 | — | 没有。“主页”只在文档侧栏里，内容是最近访问和日程 |

本工作线做四件事：引用胶囊、统一拖拽与收下矩阵、全局返回、今日页。

## 2. 引用胶囊与打开

### 2.1 一个胶囊

`RefCapsule`（放在 `src/renderer/components/ui/`）：类型图标、标题、悬停预览。用在所有出现 ReadyRef 的地方：文档正文（`[[页面]]`、`@` 提及、日期）、助手消息、日历事件的关联、画板的引用卡、资讯与书房的出处。

行为全应用一致：

| 操作 | 结果 |
| --- | --- |
| 点击 | 打开对象；跨模式时留下返回入口（§4） |
| `⌥` 点击，或悬停后按空格 | 速览，不离开当前位置 |
| `⌘` 点击 | 在新标签或分屏的另一侧打开 |
| 拖动 | 携带统一拖拽格式（§3.1） |
| 右键 | 打开、速览、复制引用、在文件视角中显示 |

在可编辑的正文里，光标进入胶囊时按普通文字处理，避免影响输入；这一点沿用块编辑器现有的做法。

### 2.2 打开与速览补齐

`modules/workbench/open-ready-ref.ts` 缺的分支补上：FastCard 条目（打开暂存栏并定位）、资讯的查询（打开资讯并应用该查询）、对话引用里的具体一轮（打开对话并滚到那一轮）。

速览（`modules/workbench/object-ui/preview.ts`）从“只给路径或网址”补到有内容：

| 类型 | 速览内容 |
| --- | --- |
| 页面 | 现有：正文预览，可编辑 |
| 数据库 | 默认视图的前几行 |
| 画板 | 缩略图（卡片的位置与标题），不是路径 |
| 书、划线 | 封面、书名、作者；划线则显示该段原文与上下文 |
| 资讯文章 | 标题、来源、摘要、筛子的理由 |
| 日程、日期 | 现有；日期显示“这一天”的摘要 |
| 网页 | 标题、网址、已保存的摘录（有来源页时） |
| 对话 | 该轮的问题与回答开头 |

### 2.3 `⌘K` 的呈现（O13）

- 结果只显示标题，不带扩展名；类型一律中文（页面、数据库、画板、书、划线、资讯、日程、对话、书签、收集、命令）。
- 补上现在搜不到的：书与划线、FastCard 条目。
- 没有输入时显示：最近打开的对象（跨四个模式，取自 §4 的历史）与常用命令。
- 每条结果 `↵` 打开、`⌥↵` 速览、`⌘↵` 在另一侧打开。

### 2.4 不再漏到系统浏览器

三处仍然把链接交给系统浏览器：全局搜索里资讯的“打开原文”（`window.open`）、日历的“加入下一场会议”、书源链接。全部改走 `openWebpageInBrowser`。认证流程等必须外开的列入白名单。新增检查脚本：渲染层出现 `window.open(`、Main 出现 `shell.openExternal(` 而不在白名单内即失败。

## 3. 拖拽与收下

### 3.1 一种拖拽格式

`application/x-ready-ref`（附 `text/uri-list` 与纯文本）是唯一的内部拖拽格式。退役：浏览器标签发的旧格式、FastCard 的 `x-ready-fastcard`、日程同时发的旧 `x-ready-drag`。发送端和接收端同一批改，不留双格式。

接收端统一处理全部引用类型：

| 拖到 | 结果 |
| --- | --- |
| 文档正文 | 插入引用胶囊；图片类的 FastCard 插入图片并复制到页面的附件目录 |
| 画板 | 落成对应的卡片：页面成文档卡，网页与资讯成链接卡，FastCard 成它原来的卡，日程成实时事件卡，划线成引用卡 |
| 助手输入框 | 成为本轮的资源（走现有的结构化资源层，授权规则不变） |
| 日历 | 页面、卡片、文章：新建一个关联了它的日程 |
| 侧栏的页面树 | 页面或文件：移动；其他类型不接受 |

### 3.2 收下矩阵

“必须”的格子是 G7 的验收范围。标“已有”的不动，只统一叫法与位置。

| 来源 ＼ 去向 | FastCard | 画板 | 当前文档 | 来源页（划线） | 助手 | 日历 |
| --- | --- | --- | --- | --- | --- | --- |
| 网页、网页选区 | 已有 | 已有 | 必须：选区“引用到文档” | 已有 | 已有 | 可选：选区“加入日程” |
| 资讯文章、选区 | **必须** | **必须**（经 FastCard 的“保存到画板”或直接拖） | **必须**：引用到当前文档 | 已有 | 已有 | 已有（时间提示） |
| 书、划线 | **必须** | **必须** | 已有（引用卡） | 已有 | 已有 | — |
| PDF 选区 | **必须** | 经 FastCard | 必须 | 已有 | **必须**：问 AI | — |
| 文档页面、块 | — | **必须**：拖成文档卡；块“发送到画板” | 已有 | — | 已有 | 已有（日期、会议笔记） |
| 数据库行 | — | **必须**：拖成文档卡 | 已有 | — | 已有（前 25 行） | 已有（日期字段） |
| 画板卡片 | — | — | 已有（添加到文档） | — | 已有 | 已有 |
| 日程 | — | 已有 | 已有 | — | 已有 | — |
| FastCard | — | 已有；**必须**补拖入 | **必须**：拖入或“插入到文档” | — | 已有 | — |
| 助手的回答、产物 | — | **必须**：“存为卡片” | **必须**：“存为页面”，走“保存到…”选层级，带 `ready_source` | — | — | 已有（工具） |

规则：

- 所有“存入 FastCard”走同一个 Main 接口，记录出处（网页优先，其次书、资讯文章、PDF 的引用）。
- 所有选区上的动作用同一个浮动条，顺序固定：划线、存入 FastCard、引用到文档、问 AI，后面是该模块特有的（翻译等）。四个阅读场景（网页、资讯、书、PDF）叫法一致。
- 浏览器“更多”菜单里的“剪藏到 Obsidian 笔记”改为“剪藏到资料库”。
- 收下之后给一个轻提示，带“撤销”和“打开”，不切走当前位置。

## 4. 全局返回

现在的返回只记一步（`modules/workbench/reference-return.ts`），放的位置也不统一：文档在标签栏末尾，资讯和日历是胶囊，浏览器不显示。

- 新增跨模式的导航历史：每次“打开对象”记一条（模式、ReadyRef、滚动锚点）。只记用户的打开动作，不记模式内的普通滚动和输入。
- `⌘[` 后退、`⌘]` 前进，在四个模式下都生效。文档标签内部已有的前进后退并入：先走标签内的历史，到头再走全局的。
- 返回入口统一放在内容区的左上角（纸的面包屑之前），写明回到哪里：“← 新书发布”。四个模式一致，浏览器模式也显示。
- 历史保存在 `ready.db`（界面状态），重启后最近 50 条仍可用，并作为 `⌘K` 空输入时“最近打开”的来源。

## 5. 今日页

### 5.1 是什么

打开 Ready 先看到的一页：四种信息在此刻的交汇。它是文档模式里的系统标签页（E4），由现有的 ink 主页（`modules/document/ink/InkHome.tsx`）升级而来，代码放到 `src/renderer/modules/today/`。窗口右上角的品牌红点打开它；启动时默认打开它（可在设置里改成“回到上次的位置”）。

### 5.2 内容

每个区块只消费已有的服务，不建新的存储。每一条都是 ReadyRef，可以点开、速览、拖走。

| 区块 | 内容 | 数据来自 |
| --- | --- | --- |
| 问候 | 一句按时段的问候与日期，用展示字体（W1 的 DL7，这一屏唯一的一处） | — |
| 接下来 | 今天剩下的日程（最多 3 个）与下一个的倒计时；今天与已过期的待办（最多 5 条，可直接勾掉） | 日历快照；W4-T4 的待办查询 |
| 为你筛过的 | 资讯里分数最高的 5 篇，带理由；“筛子校准”卡片出现时排在这里 | W5 的查询 |
| 继续 | 最近编辑的页面（3 个）、在读的书与进度（1–2 本）、还没保存的草稿 | 页面访问记录、阅读位置、草稿服务 |
| 收集 | FastCard 暂存里最近的 3 条与总数，“整理到画板” | FastCard |
| 涌现 | 文件涌现“今天”一组里的前几项 | 文件涌现快照 |

规则：

- 空的区块不显示标题和空壳，整页都空时给一段引导（添加订阅源、新建第一页、导入一本书）。
- 页面本身是纸；区块之间用留白和发丝线分开，不用卡片套卡片。
- 首屏的数据在 150ms 内就绪；慢的区块（资讯）先出占位再补，不阻塞模式切换。
- 文档侧栏里原来的“即将开始”和主页的“即将开始”都由这里取代（O4）。
- 助手空状态下的两张建议卡（“梳理当前工作”“安排下一步”）保留在助手面板里，不搬到今日页。

## 8. 风险

| 风险 | 处理 |
| --- | --- |
| 胶囊放进可编辑正文影响输入法与光标 | 沿用块编辑器现有的链接处理；胶囊只是呈现，源码仍是 Markdown 链接；有中文输入法的真实窗口用例 |
| 退役旧拖拽格式时漏掉某个发送端 | 检查脚本搜旧格式字面量；发送端与接收端同批改 |
| 今日页变成又一个要维护的大杂烩 | 区块数量固定为六个；新增区块要先改本文 |
| 今日页拖慢启动 | 首屏只读本地快照；资讯区异步；计时进验收 |
| 助手消息“存为页面”绕过写入口 | 走草稿与“保存到…”的既有流程，不新开写路径 |
