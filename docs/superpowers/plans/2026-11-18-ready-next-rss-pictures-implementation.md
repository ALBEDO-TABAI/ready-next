# 资讯配图：列表（编辑部）与图册（画报）

用户在真实窗口里看过后提出：订阅更新和日报里一张图都没有，显得沉闷，获取信息也不直观。先做了效果页让用户选（三套方案，见 `https://claude.ai/artifact/QH4TywCwCnkbbRW2TGWzXT`），用户选定：编辑部和画报两种都要，用标题栏里的两个按钮切换——“列表”按钮呈现编辑部版式，“图册”按钮呈现画报版式。

本文是这项改动的合同。先合同，后代码；每条都对应一个可运行的检查。

## 1. 为什么现在没有图

- 行尾小图的代码早就有（`RSSCoverImage` 的 `thumb` / `preview`），封面取自订阅源：附件、`media:content`、`media:thumbnail`、正文第一张图。
- 用户的来源大多不带图：Hacker News 只有链接；少数派的订阅源里没有图；走 RSSHub JSON 的条目封面在代码里被直接置空。
- 日报只有头条读封面，其余条目的读取结果里没有封面字段。

## 2. 图从哪里来（P1–P3）

**P1 取图顺序。** 一条资讯的配图依次是：① 订阅源自带的封面（`rss_items.cover_image`）；② 条目自己的网页声明的预览图（`og:image`，没有则 `twitter:image`）。②只在①为空时使用。

**P2 补图不动条目本身。** 网页预览图存在条目旁边的表 `rss_item_pictures` 里，绝不写进 `rss_items`。理由是硬约束：`rss_items.cover_image` 一变，触发器会换掉 `content_revision`、把已保存的正文标成过期并清空、让事件归组重算，刷新时还会重新排队调用模型。检查：补图前后同一条目的 `content_revision`、`rss_article_content`、`rss_processing_jobs` 行数、`rss_workspace_state.revision` 全部不变。

**P3 补图的规矩。**

| 项 | 规定 |
| --- | --- |
| 对哪些条目 | 没有订阅源封面、链接是公开网页地址（http/https）、来源是普通订阅源。经用户自己的登录会话读取的来源一律不补（不向那些站点多发请求）。 |
| 怎么取 | 复用 `link-preview` 的公网抓取（内网地址拒绝、最多 4 次跳转、8 秒超时、不带 Cookie），只读网页声明，不执行脚本、不下载图片。 |
| 取到什么 | 只保存 https 地址（http 的改写为 https，因为界面不加载 http 图片）；长度上限 2000。 |
| 多久一次 | 每条只查一次。读取失败的（超时、非 2xx、不是网页）6 小时后再试一次，之后不再试。网页没有声明图的记为“没有”，不再试。 |
| 频率 | 同时最多 2 个请求；同一个主机相邻两次请求至少隔 1 秒。 |
| 什么时候查 | ① 一次刷新结束后，为最新的、还没查过的条目查，最多 24 条（不该查的条目不留记录，所以每次多读几倍的候选、跳过它们，免得它们占满名额）；② 界面显示到某条还没查过的条目时请求（`rss:lookupPictures`，一次最多 24 条）。两者走同一个队列，同一条目不会同时查两次。 |

检查：单元测试用假的抓取函数证明——有订阅源封面的条目不发请求；同一条目并发请求只抓一次；同主机间隔、并发上限；失败只重试一次且要过 6 小时；会话来源返回 `skipped` 且不发请求。

**P4 RSSHub JSON。** `parseJSONFeed` 按普通订阅源同样的顺序取封面（条目的图片字段、附件、正文第一张图），不再固定为空。这是订阅源自带的封面，按既有规则写进条目：某个来源若确实走 JSON，升级后第一次刷新会让它近期条目的封面从无变有，这些条目按“内容有更新”处理一次（与任何订阅源改了封面时一样）。RSSHub 默认返回 XML，走 JSON 的来源很少。

## 3. 读取结果（P5–P6）

**P5 列表与筛子。** 应用自己读列表时（`rss:queryItems`、`rss:queryCards`、`rss:sieveQuery`），每个条目的 `coverImage` 是 P1 的结果：订阅源封面优先，否则是已存的网页预览图，都没有则为 `null`。这一步只在 IPC 入口补上（`RSSPictureStore.fill`），存储层的读取（`RSSContentStore.query / cards / getArticle`、筛子的 `query`）一个字段都不变。

这样定的原因（实现中查到的）：存储层的读取不只给界面用。助手工具读它，早先的迁移（把聊天记录里的旧资讯引用换成新地址的那一步）也靠它判断引用还在不在。如果把新表连进存储层的查询，老数据升级时那一步迁移会在新表建出来之前就去读，读不到表，于是把有效的引用全标成“无法定位”。配图是给人看的东西，所以只加在给人看的入口上。阅读页顶部的封面也因此保持原样：只显示订阅源自带的封面。

**P6 日报。** 应用自己读日报条目时（`rss:readDigests` 的 `entries` 视图），每个条目多一个 `coverImage`：该条目现在的配图（P1）。它不属于出刊时保存的快照，也不出现在助手工具 `rss_read_digests` 的结果里（工具结果不因此变长）。

**P7 请求补图。** `rss:lookupPictures({ itemIds })`，1–24 个条目，返回每个条目的 `{ itemId, coverImage, state }`，`state` 取 `feed | page | none | failed | skipped | unknown`（定义见 `src/shared/rss-pictures.ts`）。全部条目有结论后才返回。

## 4. 版式（P8–P10）

**P8 两个按钮。** 订阅更新（全部 / 未读 / 收藏 / 主题）、为你筛过的、日报与简报三个版面各有一个“列表 / 图册”切换：订阅更新的在筛选那一行、“全部源”之前（用户指定的位置），为你筛过的在标题行右侧，日报与简报在面板顶栏右侧。用户点名的是订阅更新；另外两个版面也加，是实现时的判断（用户原话是两种版式都要）。每个版面各记各的选择（本机 `localStorage`，键 `ready-rss-layouts`），没切换过的版面是“列表”。

**P9 列表 = 编辑部。**

- 订阅更新：筛子选出的“精选”条目，图放大排在文字下面（16:9，最宽 448），推荐理由在图下；其余条目行尾一张 120×80 的小图。没有图的条目是纯文字，不放占位。已读条目的图变淡。
- 为你筛过的：排第一的那条用通栏图（21:9）开场，其余条目右侧小图（116×78）。
- 日报：头条的图通栏排在标题下（2:1）；“今日看点”是三张并排的图卡，下面一行是本期版面；各条目右侧一张 176×118 的图。

**P10 图册 = 画报。**

- 订阅更新：封面网格，列数随面板宽度（不足 560 一列，不足 880 两列，否则三列，1280 以上四列）；封面 3:2，下面是时间、来源和两行标题。没有图的条目用自己的摘要当封面；只有链接的条目用链接的站点名。仍是虚拟滚动。
- 为你筛过的：两列封面（16:10），标题和理由在图下。
- 日报：先是一张 16:9 的封面图，再是头条标题；“今日看点”的标题压在图上（4:5）；各版面排成两列图卡。

压在图上的文字和角标用 `--rn-media-veil` / `--rn-on-media`，两种主题下相同（图不随主题变）。其余只用已有的 `--rn-*` 令牌。

## 5. 验收

- 单元测试：P2、P3、P4、P5、P6、P7 的行为；版式切换与记忆；两种版式下三个版面的渲染（有图、无图、图加载失败、已读）。
- 原生测试（Electron 运行时）：新表的迁移、逐行升级测试（`scripts/run-rss-workspace-native-tests.cjs`）、P2 的“不动条目”检查、老数据升级时已保存的资讯引用仍然有效。
- 真实窗口（隐藏）：三个版面各两种版式，浅色与深色，截图由实现者自己看过；补图在本地夹具站点上走通（不访问外部网站）。

## 6. 不做的事

- 不下载、不缓存图片本身；图片仍由界面直接向来源加载（与现有封面一致）。
- 不为补图调用模型，不改动筛子、分类、出刊逻辑。
- 不给登录会话来源补图。
- 不加设置项。若以后需要关闭补图，再加开关。

## 7. 实现记录（2026-11-18 至 11-19）

- **分工**：数据层（新表、补图服务、请求入口、RSSHub JSON、测试）由 Codex 按本合同实现；界面、合同和评审由 Claude 做。评审时改了两处：P5 从“在存储层的查询里合并”改为“只在应用读列表的入口补上”（原因写在 P5）；刷新后的补图改为多读几倍候选、跳过不该查的条目。
- **界面的组成**：`RSSPicture` 是唯一的图框组件，按所在位置取不同的框；`RSSFeedGallery` 是图册的虚拟滚动（按行虚拟化，回到列表时停在原来的位置）；`RSSLayoutSwitch` 是两个按钮；样式都在 `rss-pictures.css`。原来的 `RSSCoverImage` 只剩阅读页顶部封面这一种用法，日报右栏的“导读”并进了正文。
- **图框不随图变形**：框的形状是定的，图按框裁切，所以图片陆续到达时列表不跳。全景、方图或很小的图放进大框时整张显示、不放大。加载失败或太小（不足 48 像素，多半是统计用的像素点）的图不显示，条目回到纯文字或用摘要当封面。
- **验证**：单元测试（界面 6 项、数据层 17 项，全量 8642 项中唯一失败的是日历的一项计时测试，单独运行通过）；Electron 运行时的资讯测试 525 项、`verify:native` 536 项，都没有跳过；IPC 对应、迁移编号与全新升级、设计令牌、层叠层、静默捕获、计划配对各项门禁通过；真实窗口（隐藏）`verify:ready-next-rss-pictures` 14 项，回归跑了外壳、设计矩阵、筛子（11 项）和引用胶囊（22 项），都通过；采集检查里资讯的各步通过，它在后面“助手新建对话”那一步停下，那一步找的按钮位置是外壳改版前的，与本次无关。旧的 `run-rss-reader-acceptance.cjs` 是给改版前的外壳写的，在这个分支上第一步就找不到入口，没有作为依据。
- **没有在检查里做的事**：向真实网站补图。检查不访问外部网站，补图的规矩由注入假抓取函数的测试覆盖，抓取本身沿用画板链接预览已经在用的 `link-preview`。
- **顺带修好**：`verify:native` 里有两项测试自“编辑后重发覆盖上一轮”那次提交起就失败（它们手写的聊天表缺少新加的一列），与本次改动无关，单独提交修复。
