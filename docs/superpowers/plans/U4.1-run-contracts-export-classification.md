# Stage U PR U4.1 — `run-contracts.ts` Export Classification

Single source of truth for the WIRE / INTERNAL split that U4.1b–e
implements. Locked by U4.1a — any subsequent re-classification needs a
new PR description that supersedes a row.

## Cross-process surface audit (codex-style)

Grep results for `from '*run-contracts'` outside of `src/main`:

| Search root | Imports from run-contracts |
|---|---|
| `src/preload/` | 0 |
| `src/renderer/` | 0 |
| `src/shared/` | 0 |

Conclusion: every `run-contracts.ts` export is consumed only inside
`src/main`. The "wire" status of a type is determined by whether its
**runtime shape** crosses the preload boundary (via an IPC handler
return value or `mainWindow.webContents.send` payload), not by static
import edges.

Audit of `ipc-handler.ts` confirms only **one** type from
run-contracts.ts is named at a preload-boundary callsite:

```
src/main/modules/claude-bridge/ipc-handler.ts:44
  import type { TaskProjectionChangeEvent } from '../agent-control/run-contracts'
```

The renderer-side manual copy of the same shape lives at
`src/renderer/types/electron.d.ts:472` as `TaskProjectionRecordData`
(which is the array element of `IPCResponse<TaskProjectionRecordData[]>`
returned by `agent:listTaskProjections`).

So the real WIRE surface from this file is **2 types** — narrower than
plan v7's "5 wire-contract files" estimate. The remaining ~63 exports
are all main-internal.

## Migration sequence (U4.1b-e)

- **U4.1b** — Create `src/shared/ipc-contracts/task-projection.ts` and move
  `TaskProjectionRecord` + `TaskProjectionChangeEvent` (plus their
  transitively-needed sub-types: `UnifiedTaskState`, `TaskStep`,
  `TaskStepChildTask`, `BudgetWarningLevel`, `RecoveryRecord`,
  `TaskInteractionState`, `TaskType`).
  - Sub-types stay duplicated until U4.1c sorts out shared placement;
    re-exports from run-contracts.ts keep existing consumers happy.
- **U4.1c** — Co-locate / dedup the wire-adjacent sub-types from U4.1b.
- **U4.1d** — Move all remaining 63 INTERNAL exports to
  `run-contracts-internal.ts`. Enable `check-wire-contract-isolation.cjs`.
- **U4.1e** — Delete the now-empty `run-contracts.ts`. Add path-existence
  gate `check-no-run-contracts-file.cjs`.

## Risk notes

- `TaskProjectionRecord` extends `UnifiedTaskState` (line 318 → 303), so
  U4.1b must also relocate `UnifiedTaskState` or wrap it via a wire-side
  duplicate. Recommended: relocate (it's only used by the projection
  record, no other consumer).
- `TaskProjectionChangeEvent` references `TaskProjectionRecord` — order
  is naturally satisfied by moving both in U4.1b.
- `SkillRunContract` (line 979) is the largest single export at ~400
  LOC; U4.1d will be the heaviest move PR.
- The actual cross-process surface narrowness (only 2 wire types) means
  U4.1b is much smaller than plan v7 estimated (~50 LOC vs ~400 LOC).
