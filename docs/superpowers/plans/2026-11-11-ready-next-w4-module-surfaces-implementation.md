# Ready Next W4 模块界面收口：画板、书房、日历、待办、FastCard

属于 [收束路线图](2026-11-11-ready-next-coherence-roadmap.md) 的 W4。证据：[f-canvas-library](../audits/2026-11-11-ready-next-coherence-audit/f-canvas-library.md)、[e-calendar](../audits/2026-11-11-ready-next-coherence-audit/e-calendar.md) 与实机观察 O6、O9、O16。依赖 [W1](2026-11-11-ready-next-w1-design-system-implementation.md) 的基元与材质。文档、数据库在 [W3](2026-11-11-ready-next-w3-library-model-implementation.md)，资讯在 [W5](2026-11-11-ready-next-w5-rss-sieve-implementation.md)，浏览器在 [W7](2026-11-11-ready-next-w7-browser-agent-implementation.md)。

## 1. 这条工作线管什么

这几个模块的功能在整合阶段接通了，但后来补进去的界面没有经过设计（Codex 看不到窗口，界面又约定由 Claude 来做，这一段就空着了）。本工作线逐个模块做三件事：去掉多余的，补上缺的，把没设计的部分按 W1 做出来。

每个模块给一张“留、去、补”表。表里没列的现有功能默认保留。

### 2.3 约束

- 画板的写入仍只走画板句柄（D4、运行时合同 §7 的 M4 一节），撤销重做仍在当前界面内。
- 浮动工具条属于浮层，但它在画板自己的内容区内，不盖住原生网页层时不必触发让位；分屏且另一侧是浏览器时要验证不越界。
- E3 遗留的缺陷（嵌套画板里 `../` 链接解析错误，见运行时合同 §7）顺手关闭：修 `search-engine/object-links.ts` 的解析规则，让 `ready-canvas-write-native.test.ts` 里保留的失败用例通过。

### 2.4 链接预览在代理环境下

链接预览是 Main 的共用服务（`src/main/modules/link-preview/fetch-public.ts`），画板的链接卡、页面的书签块、FastCard 都用它。它在建立连接时解析域名并拒绝一切非公网地址，其中包括 198.18.0.0/15。使用 fake-IP 模式的代理会把所有域名都解析进这个网段，于是在这类机器上每一次预览都失败。

决定（路线图 §9）：**只在确认本机处于 fake-IP 代理下时放行这个网段。**

- 放行的条件要同时满足：请求的主机是域名，不是 IP 字面量；解析结果全部是公网地址或落在 198.18.0.0/15；一个固定的对照域名（例如 `example.com`）此刻也解析进 198.18.0.0/15。
- 对照结果按进程缓存几分钟，网络变化后重新探测。
- 其他一律不变：IP 字面量、其他私网与保留网段、重定向到这些地址，照旧拒绝；大小与超时限制不变。
- 不加设置项。

解析函数已经可以注入解析器，测试不需要真实网络。

## 3. 书房

书房的质感已经是目标外观（纸页、书脊、台）。要做的是把控件换成基元，并去掉常驻的一次性入口。

| 项 | 处理 |
| --- | --- |
| 书架顶部“导入本地书 / 从藏书阁导入…” | “导入”保留为一个按钮（菜单里有本地文件、找书）。“从藏书阁导入”是一次性迁移，移到“设置 › 阅读” |
| 书架底部的文字工具条（找书 F、分类、最近、颜色、厚薄、抽一本） | 保留功能，换成基元；排序收成一个“排序”菜单，“找书”“抽一本”保留为按钮 |
| 阅读器顶部（目录、夹一张书签、书签 0、笔记 0、排版） | 换成图标按钮加提示；数量用角标 |
| 阅读器底部（上一页 5 / 24 下一页） | 保留，换基元 |
| 字体 | 现在只有宋、黑、楷。原藏书阁有的字重滑杆可以补，优先级低 |
| 划线后的去向 | 补“存入 FastCard”（见 W6 的收下矩阵） |
| 台的背景点阵 | 保留，颜色改用令牌 |
| 暗色与夜间纸 | 进截图巡检 |

阅读器有四套（书房、文档书本模式、资讯文章、PDF），分工已在运行时合同里写明，本工作线不合并它们。要统一的是它们共用的东西：划线浮层、划线颜色、笔记面板的外观，以及“存入 FastCard”“问 AI”“划线到来源页”这三个动作的位置和叫法。

## 5. 待办

用户说的是“日历、日程、待办”。现在待办只有一种形态：文档里带日期链接的勾选项，出现在日历的待办图层，能拖动改期，不能在日历里勾掉，没有日期的不出现（[e-calendar](../audits/2026-11-11-ready-next-coherence-audit/e-calendar.md) §待办）。

不另建任务库。待办仍然是 Markdown 里的 `- [ ]`（D14），补的是看和改的入口。

| 项 | 做法 |
| --- | --- |
| 待办清单 | Main 提供一个查询：资料库里全部未完成的勾选项，带所在页面、所在标题、日期（有的话）。从已有的文档索引派生，可重建 |
| 在哪看 | 今日页的“待办”区（W6）；日历侧栏的“待办”小节，分“今天”“已过期”“未安排”三组 |
| 勾掉 | 在清单或日历图层里点勾选框，经文档写入服务只改那一行（把 `[ ]` 改成 `[x]`），文件其余字节不变；文档开着且有未保存内容时按 C3 的规则合并或报冲突 |
| 安排 | 把“未安排”的一条拖到日历的某一天：写入日期链接。已有的拖动改期不变 |
| 识别的写法 | Ready 的日期链接（现有）；Obsidian Tasks 的 `📅 YYYY-MM-DD`（只读识别，改期时改写为 Ready 的日期链接前先问一次，并记住选择） |
| 不做 | 重复任务、子任务、优先级、独立的任务数据库 |

## 6. FastCard

FastCard 原来是浏览器里的暂存栏。现在能收东西的地方多了（资讯、书、PDF），它应该是全局的。

| 项 | 处理 |
| --- | --- |
| 入口 | 图标栏的“收集”按钮（W2 §2.1），任何模式下都能打开暂存栏。浏览器工具条上原来的按钮保留（它还负责网页上的浮层） |
| 暂存栏 | 外观换基元。每张卡显示来源（网页、资讯、书、PDF）与时间；勾选后“保存到画板…”“引入对话”“删除” |
| 拖拽 | 拖到画板、拖到文档、拖到助手输入框，都用统一拖拽格式；`x-ready-fastcard` 私有格式退役（W6） |
| 快记（`⌥⌘Space`） | 保留；录音转写见 §2.2 |
| 新的来源 | 资讯、书、PDF 的“存入 FastCard”由 W6 的收下矩阵统一接入，共用同一个 Main 接口 |

## 8. 合同 MS1–MS7

| 合同 | 标准 |
| --- | --- |
| MS1 | 画板内容区是一整块台，没有常驻的表单行和文字按钮排；所有工具有图标、提示和键盘操作 |
