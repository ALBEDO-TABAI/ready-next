# Ready Next W7 浏览器与 Agent：让助手走出“当前这一页”

属于 [收束路线图](2026-11-11-ready-next-coherence-roadmap.md) 的 W7，落实 E8、E9。证据：[g-browser-agent](../audits/2026-11-11-ready-next-coherence-audit/g-browser-agent.md)（现状）、[h-external-landscape](../audits/2026-11-11-ready-next-coherence-audit/h-external-landscape.md)（外部）。行为边界以 [当前运行时合同](../../architecture/current-runtime-contracts.md) §6 为准；本计划要改其中几条，改的地方在 §4 逐条列出，实现前先改合同。

## 1. 结论先行

用户问了三件事：Codex 有没有可用的新特性，WebMCP 这类项目帮不帮得上，怎样让 Ready 的浏览器好用并且能被助手驾驭。

| 问题 | 结论 |
| --- | --- |
| Codex 原生的浏览器、电脑操作能不能接用 | **不能。** 它们是 ChatGPT 桌面应用里的能力，开源的 app-server 只有策略配置，没有让第三方宿主驱动的接口。本机 `codex features list` 里 `browser_use` 等显示 stable，指的是那套能力，不是给 Ready 用的。Ready 继续用自己的工具栈，经动态工具交给 Codex |
| Codex 新版本里有什么用得上 | 三样：**动态工具可以并行调用**（0.164）、**模型步骤之间可以替换动态工具**（0.166，需实测）、**延迟加载工具的状态管理**（0.167 默认开启）。延迟加载（`defer_loading`）和工具返回图片在固定的 0.160.1 里已经有，Ready 还没用上延迟加载 |
| WebMCP | **值得接，但排在后面，并且先要升级 Electron。** 它让网页自己声明“我能做什么”，助手直接调用而不是点按钮。但它还是社区组草案，Chrome 只在 origin trial，真实采用目前只查到 Shopify。Electron 42 的 Chromium 里没有调用工具的 CDP 命令，43 起才有 |
| chrome-devtools-mcp、playwright-mcp、browser-use 等 | **不接。** Ready 已经有自己的 CDP 客户端、可访问性快照和目标引用，感知模型与业界主流一致。把外部自动化接到 Ready 自己的网页上会绕过标签所有权、行动确认和证据复核。值得借的是做法：快照差分、交还给人的流程、按来源区分只读与可写 |
| 真正的瓶颈在哪 | 不在工具数量（已有 28 个），在四条限制：**跨标签没开放、下载没开放、鼠标操作只能在前台、被打断后不能接着做。** 再加一条：**Electron 42 已停止支持** |

## 2. 现状要点

来自 [g-browser-agent](../audits/2026-11-11-ready-next-coherence-audit/g-browser-agent.md)，动手前重新核对。

- **工具面**：当前页开放 18 项；显式网页引用只给 6 项只读；8 项高级工具要技能授权。`browser_tabs`、`browser_download`、`browser_research` 在注册表里有定义，但不进入最终授权集合。
- **感知**：CDP 的可访问性树与 DOM，加脚本补采；目标引用绑定页面、frame 与快照版本；逐 frame 采集；截图可以作为图片返回给模型（模型不支持视觉时网关拒绝）。
- **动作**：经 `webContents.debugger` 发 CDP 输入事件。文字与键盘可以在隐藏的页面上投递；**指针、滚轮、拖拽只在可见、活动、前台的页面上开放**。隐藏的页面被停放在屏幕外一个 1×1 的区域里（`host-layout-service.ts`），所以点不中任何东西。
- **等待**：轮询就绪、文本、网址、选择器；所谓 `network_idle` 实际比较的是资源条目数和一个很粗的内容签名，不是在途请求归零。
- **接线**：动态工具在 `thread/start` 注册，`turn/start` 不能追加；所以每轮准入前冻结浏览器工具子集。延迟加载关闭。
- **打断之后**：人工接管、复核拒绝、验证码之后没有自动接续，要用户重新发话。
- **浏览器壳**：有标签、分组、分屏、书签、历史、下载、广告拦截、登录态持久化。没有地址栏建议、页内查找、阅读视图；搜索引擎写死 Google。
- **MCP 客户端**：只支持本地 stdio。

## 3. 目标

用户确认的四类任务，都要做稳：

| 类别 | 例子 | 现在卡在哪 |
| --- | --- | --- |
| A 多站点调研汇总 | 搜索，打开五个结果逐页读，对比，带来源写成文档 | 跨标签；只能在当前页上来回导航 |
| B 登录后的站内操作 | 在已登录的后台填表、发帖、改设置 | 等待判断粗；复杂控件；动作前后的证据比较 |
| C 下载与文件处理 | 下载报告、上传附件、把结果存进资料库 | 下载工具隐藏 |
| D 长流程不打断用户 | 几十步、跨多个标签，用户继续做自己的事 | 鼠标操作要求前台；被打断后不能接续 |

## 4. 做法

### 4.1 评测先行

没有评测集，“更好用”无从谈起，也无法防止改一处坏一处。

**基准站点。** 一组本地确定性的测试页面，由脚本在回环地址上提供，覆盖：普通表单、多步表单、单页应用的路由与延迟渲染、嵌套 iframe、shadow DOM 控件、分页与无限滚动、登录墙、下载、上传、原生对话框、新标签与弹窗、富文本编辑器、canvas 应用。放在 `scripts/browser-eval/sites/`。

**两层评测。**

| 层 | 内容 | 何时跑 |
| --- | --- | --- |
| 工具层（不需要模型） | 用脚本按固定顺序调用工具，核对每个工具在每类页面上的返回与回执：快照能看到目标、点击落在目标上、等待在该结束时结束、下载落盘并校验、接管后不再投递 | 接入 `npm run verify:browser-surface`，每次改动都跑 |
| 任务层（需要模型） | 四类共 24 个任务（每类 6 个），每个任务有可机器判定的终点（某个文件存在且内容匹配、某条记录被创建、文档里包含指定来源）。记录：是否完成、步数、令牌数、耗时、人工介入次数 | `npm run verify:browser-agent-eval`，用用户配置的模型手动触发，有费用上限；结果存到 `docs/superpowers/audits/` |

先在现有代码上跑一遍任务层，得到基线。之后每个解锁项合入前后各跑一遍。目标是路线图的 G9。另备一份真实站点的冒烟清单（十个以内，人工跑），只用于发现基准站点覆盖不到的问题，不作门槛。

### 4.2 跨标签

开放 `browser_tabs`，但只在任务自己的工作标签范围内：

- 助手新开的标签进入该任务的后台工作标签组，不抢用户的前台标签（现有合同已如此规定）。
- `list` 只列该任务拥有的标签和被钉住的当前页；`open` 记录“由哪个标签的哪个动作打开”的因果关系；`switch`、`close` 只能作用于任务拥有的标签。
- 用户的其他标签对助手不可见，除非用户把它作为引用交给本轮。
- 任务结束或被取消时，工作标签保留供用户查看，占用释放；用户可以一键关闭该任务的全部工作标签。

需要改的合同：运行时合同 §6 里“在因果后继页签权威完成前……不得暴露 `browser_tabs`”一句，以页签因果关系落地为条件解除。

### 4.3 下载

开放 `browser_download`：

- 沿用已有的底层：当前浏览器会话、临时文件、预算校验、哈希、原子发布。
- 补上合同要求的“独立回执消费者”：下载完成后生成一条回执（文件路径、大小、哈希、来源网址、所属任务），进入工具结果与任务记录；文件落在本轮授权的目录或资料库的 `下载/`，并登记为对象，返回 ReadyRef。
- 公开地址静默跳到本地网络的仍然拒绝。
- 上传已有，不动。

### 4.4 后台工作面

让指针操作不再要求用户把网页放到前台。

**做法。** 给助手的工作标签一个“始终在渲染的不可见承载面”：一个不显示的窗口，关闭后台节流，网页按正常尺寸布局（例如 1280×800），而不是停放在 1×1 的区域里。代码里已有先例：截图用的隐藏窗口就是 `paintWhenInitiallyHidden` 加 `backgroundThrottling: false`（`browser-controller-capture-runtime.ts`）。助手的指针、滚轮、拖拽在这个承载面上投递；用户想看时，把这个标签“请到前台”，它就挂回主窗口。

**先做验证（T5 的第一步）。** 在基准站点上确认：承载面上 CDP 的鼠标事件命中正确；懒加载、`requestAnimationFrame`、`IntersectionObserver`、页面可见性相关的逻辑按预期工作；与焦点模拟不冲突；内存与 CPU 的开销可接受。验证不通过就退回“前台才开放指针”，并把原因记在本文。

**不变的规矩。** 每次物理投递前重读写权限；停止或接管一生效就不再投递；Agent 指针层只在标签可见时显示。

需要改的合同：§6“指针、滚轮和拖拽仍只在可见、活动、前台 host 上开放”，增加“或任务自己的后台工作面”。

### 4.5 等待

`network_idle` 改成真的：用 CDP 的网络事件统计在途请求，归零并保持一小段时间才算；加上 DOM 变动静止（一段时间内没有结构变化）。`browser_wait` 的条件增加“某个目标出现或消失”“某个目标的文字变化”。长连接与轮询请求按类型排除，避免永远等不到。

### 4.6 感知

| 项 | 做法 |
| --- | --- |
| 快照差分 | 动作之后的观察返回“相对上一次快照变了什么”，而不是整页重发。目标引用规则不变：页面变了就要重新观察 |
| 带编号的截图 | 模型支持视觉时，`browser_screenshot` 可以在截图上标出快照里目标的编号，用于 canvas 类页面或快照不足以定位的情况。默认不开，由模型按需请求 |
| 覆盖 | 基准站点上的 iframe、shadow DOM、委托控件都有工具层用例；发现看不到的目标就补采集，不靠站点规则 |

### 4.7 被打断之后

合同规定“下一次助手执行必须由用户的新输入单独准入”，这条不改。改的是让用户的这一步变成一次点击：

- 助手被接管、遇到验证码或登录墙、被复核拒绝时，任务卡和网页上方的提示条给出明确的状态与一个按钮。
- 验证码、登录：提示条写“需要你来完成登录”，把该标签请到前台；用户处理完点“我处理好了，继续”。
- 接管之后：点“让助手接着做”。
- 这两个按钮做的事是**以用户身份发一条新的输入**，内容是固定的一句话加上对原任务的引用。它经过完整的准入、冻结与授权，不是自动接续，也不产生非用户发起的后继任务。
- 需要用户出面时发一条系统通知（用户不在 Ready 前台时）。

### 4.8 工具面与 Codex 运行时

| 项 | 做法 |
| --- | --- |
| 延迟加载 | 0.160.1 已支持 `defer_loading`。把 8 项高级工具和不常用的工具设为延迟加载，默认面只留常用的。先量：默认面的令牌数、模型选错工具的次数，前后对比 |
| 升级 Codex 运行时 | 评估从 0.160.1 升到 0.167 或更新：并行调用动态工具（调研类任务可以并行读多个标签）、取消时工具生命周期正确收尾、步骤间替换动态工具（如果有可用的接口，就能在一轮之内补工具，不必整轮冻结）。升级按既有的运行时采纳流程做（参照 `2026-10-07-codex-runtime-0.160.1-adoption-implementation.md`），单独一批 |
| 持续关注 | 每次运行时升级时复查：是否出现宿主可用的浏览器接口。出现了再评估，不预留代码 |

### 4.9 Electron 升级

Electron 42（Chromium 148）已于 2026-10-20 停止支持。Ready 内嵌浏览器，会打开任意网页并保存登录态，运行在不再有安全更新的 Chromium 上是实打实的风险。升级到当前受支持的版本线（调研时为 45）。

**评估（T1）**要回答：原生模块（better-sqlite3 等）能否重编；窗口材质与毛玻璃是否正常；`WebContentsView` 相关的行为有无变化；打包与签名；Playwright 的 `_electron` 能否驱动；全部 `verify:*` 与真实窗口脚本的结果。在独立 worktree 里做，输出一份评估记录。

**执行**：用户已于 2026-11-11 授权，评估通过即执行，不再另行确认（路线图 §9）。

- **目标版本**：执行时最新的受支持稳定大版本，且至少已有一个补丁版本；刚发布的 `.0` 不选，退一个大版本。
- **时机**：尽早，放在路线图的 B0。越早升，后面每一批的真实窗口验收和截图基线就都建立在最终的运行时上。
- **合入条件**：全部 `verify:*`、全部真实窗口脚本、打包冒烟通过。合入时同步 `package.json`、lockfile、`CLAUDE.md` 与 `AGENTS.md` §1 的技术基线，并重拍截图巡检的基线。
- **不通过**：留在 42，把阻塞点和复现方式写进评估记录，W7 其余部分照常进行（只有 4.11 依赖升级），每次 Electron 出新补丁时重评一次。

### 4.10 浏览器壳补全

让人自己用着也顺手。

| 项 | 做法 |
| --- | --- |
| 地址栏建议 | 输入时给出历史、书签、已打开的标签、搜索建议 |
| 搜索引擎 | 可在设置里选择，不再写死 |
| 页内查找 | `⌘F` |
| 阅读视图 | 对文章类页面提供“阅读视图”：复用资讯阅读页的正文抽取与排版，同一套划线、存入 FastCard、问 AI、翻译。也就是说，网页文章和资讯文章用同一个阅读器 |
| 发现订阅源 | 页面声明了 RSS、Atom、JSON Feed 时，地址栏出现“订阅”，一键加为资讯来源 |
| 标签进外壳侧栏 | W2-T3；助手的工作标签单列一组，显示所属任务与状态（运行中、等你处理、已完成），可以“请到前台”或“全部关闭” |
| “剪藏到 Obsidian 笔记” | 改名（W6） |
| 不做 | 密码管理与自动填充、扩展、设备模拟 |

### 4.11 网页自带工具（WebMCP，实验）

前提：Electron 升到含 `WebMCP.invokeTool` 的版本。

- 页面注册了工具时，CDP 的 `toolsAdded` 事件告诉 Ready。Ready 向助手提供两个工具：列出当前页的自带工具、调用其中一个。只有启动已启用且准入时钉住/显式可见页面真的注册了工具，这两个工具才进入本轮冻结的工具面；回合中不扩权。
- 网页给的工具名、描述、返回值都是不可信内容：按“资料，不是指令”处理，标明来源；带 `consequentialHint` 或未明确 `readOnlyHint: true` 的调用走行动确认，并受 BA7/T10 按来源的可写范围约束；调用记录进任务日志。
- 放在“设置 › 浏览器”里的一个实验开关后面，默认关闭。
- 用一个本地页面注册工具做测试；不承诺真实站点的效果。

### 4.12 安全

现有的所有权、写权限、行动确认、独立复核全部保留。借鉴外部做法补一条：

- **按来源区分只读与可写。** 一个任务里，助手可以读任何它被允许打开的页面，但“会改变页面状态的动作”（提交、输入、点击会跳转的控件）只在用户本轮明确涉及的来源上默认允许；到了别的来源要做这类动作时，先问一次，回答对本任务内该来源有效。这是把现有按工具、按目标的机械判定再加一层按来源的范围，仍由代码判定，不靠模型自述。
- 网页内容里的指令不执行：现有的浏览器纪律提示词已有，评测集里加几条注入用例（页面里写着“忽略之前的要求……”），作为回归。

### BA10：工作标签归属（2026-11-14，先合同后实现）

- **存什么、谁写**：Main 是唯一写入者；迁移 158 在现有 profile 数据库保存稳定标签编号、浏览器任务编号、父任务、所属 run、会话及可见代次、浏览器 profile 与来源标签。标签集合仍以现有 userData 内的标签会话恢复结果为准，不新增全局文件或另一套标签列表。物理页面身份、占用、写权限和后台承载面不持久化为可恢复授权。
- **写入确认**：开页前捕获数据库中的任务所属 run；开页返回后重新核对同一任务、父任务、会话及可见代次仍有效，且标签仍存在。归属写入成功后才能登记内存工作面、返回成功；写入失败关闭本次新页并明确报错。旧 run 的迟到结果不能写入或覆盖新 run 的归属。
- **何时失效**：浏览器任务或父任务结束、任务换 run、会话关闭/删除或可见代次改变时，同一数据库写入内清除归属；保留页面，按普通标签处理。关闭标签先确认归属删除，再关闭原生页面；删除失败不关闭，关闭失败恢复归属。重复关闭不重新创建归属。
- **重启对账**：`registerDormantTabs` 在创建物理页面前，只用实际接纳的标签编号和 browser profile 对账；缺失、被拒绝或 profile 不匹配的记录删除。空恢复集也清理；没有恢复会话而直接开新页时，先清掉旧记录，不能因编号复用冒认归属。对账失败不留下半初始化标签，允许重试。有效的休眠标签也要从 `getTabs` 返回任务编号，恢复完成后经既有 `agent:browserTaskAttentionChanged` 按原会话通知重读，任务卡和“全部关闭”沿用现有入口能找到这些标签。重复恢复请求不得清掉已登记的工作标签。
- **禁止自动续跑**：对账不调用任务启动、占用获取、写权限绑定、后台工作面挂载或继续动作；恢复的物理页面不继承旧实例的操作资格。测试断言恢复后的执行工作标签为空，并核对普通标签、休眠标签、终态、会话丢失、旧 run、写入失败与关闭顺序。

现有的浏览器专项 gate（`verify:browser-orchestration`、`verify:browser-surface`、`verify:browser-reliability`、`verify:browser-grounded-orchestration-native`、`verify:browser-target-claims`）全程保持通过。

## 7. 风险

| 风险 | 处理 |
| --- | --- |
| 运行时合同 §6 很细，改一条牵动多条 | 每个解锁项先写出要改的原句与新句，连同对应测试一起改；一次只解一条 |
| 后台工作面在某些站点上行为不同（靠可见性节流、防自动化检测） | 先验证再做；失败可退回；真实站点冒烟清单覆盖几个常用站 |
| 跨标签后占用与清理变复杂 | 标签始终归属一个任务；任务终态时统一释放；用户可以一键关闭 |
| 任务层评测要花模型费用且结果有波动 | 每个任务跑三次取多数；设费用上限；只在能力变更时跑 |
| Electron 大版本升级的连锁影响 | 评估与执行分开，都在独立 worktree；不通过不合入；放在最前面做，问题在其他工作线开始前暴露 |
| WebMCP 规范还在变（148 到 156 之间接口改过名） | 放在实验开关后；实现只依赖 CDP 域，不依赖页面接口的名字 |
| 延迟加载让模型找不到工具 | 用评测前后对比决定哪些工具延迟 |
