# Ready Next W5 资讯筛子：标准、行为、在做的事，三者决定给你看什么

属于 [收束路线图](2026-11-11-ready-next-coherence-roadmap.md) 的 W5，落实 E7。证据：[d-rss](../audits/2026-11-11-ready-next-coherence-audit/d-rss.md) 与截图 `30-rss-list`、`32-rss-curated`、`34-rss-manage`。界面依赖 [W1](2026-11-11-ready-next-w1-design-system-implementation.md)、[W2](2026-11-11-ready-next-w2-shell-unification-implementation.md)；引擎部分（T1、T2）不依赖其他工作线，可以最先开工。

## 1. 现在有什么，缺什么

资讯是 Ready 的出发点：信息太多，用户要一个属于自己的筛子，让最需要的内容自己出现。

**已经有的**（都保留）：

- 来源：RSS、Atom、RDF，以及 YouTube、B 站、微博、抖音、小红书、X 等适配；15 分钟到 12 小时的自动刷新。
- 用户用文字写标准（主题与“精选”），模型逐条判断是否符合，必须给出原文里的证据句，证据不足不猜（`rss-engine/processing-judgment.ts`）。
- 同一事件的多篇报道归组，可人工拆合；48 小时内多来源报道的算热点。
- 每日日报与按范围生成的简报，规则编排，不另调模型。
- 人工纠正优先于模型判断；每日 100 次的判断额度；失败不自动重试。

**缺的**，也就是它还不是筛子的原因：

| 缺口 | 现状 |
| --- | --- |
| 不排序 | 列表只按时间正序或倒序。符合标准的 30 篇里哪 5 篇最值得看，没有答案 |
| 不学习 | 已读、收藏、划线、移出这些行为被记录了，但不影响之后给什么 |
| 不知道用户在忙什么 | 判断只看文章和标准。用户这周在写什么、下周要开什么会，筛子不知道。而这正是 Ready 独有的条件：文档、日历、画板就在隔壁 |
| 常常只看了摘要 | 来源只给 500 字摘要时，判断就基于这 500 字 |
| 不送达 | 没有资讯的系统通知；筛出来的东西要用户自己进资讯模式去翻 |
| 收不下来 | 文章不能直接进 FastCard 或画板，不能直接引用进正在写的文档 |
| 默认视图不是筛过的 | 进来先看到“全部动态”；“精选”只是左边的一栏 |

## 2. 筛子的定义

一句话：**每篇新文章得到一个“现在对这位用户的价值”分数和一句理由，资讯默认按这个分数给出今天最值得看的几篇，用户的每个动作都会让下一次更准。**

### 2.1 三个输入

| 输入 | 来自 | 谁来算 |
| --- | --- | --- |
| 标准 | 用户写的主题与基础标准（现有的 definitions；“精选”的标准改称“基础标准”） | 模型判断是否符合，沿用现有的证据规则 |
| 行为 | 用户对文章做过什么 | 代码统计出来源偏好、主题偏好；模型每周提议一次对“我的关注”的修改，用户确认后才生效 |
| 在做的事 | 资料库与日历 | 代码生成一份不超过 800 字的清单：最近 7 天编辑过的页面标题（最多 12 个）、活跃的涌现项目名、未来 7 天的日程标题（最多 8 个）、在读的书名。只有标题，没有正文 |

### 2.2 分数怎么来

分两步。模型只做语义判断，分数的合成由代码完成，这是项目的规矩。

**第一步，模型**（并进现有的判断请求，不增加调用次数）。输出里增加：

```json
"relevance": {
  "score": 0-100,
  "because": "standard | interest | work",
  "reason": "不超过 40 字的一句话",
  "workRef": "‘在做的事’清单里的某个标题，或 null"
}
```

校验：`workRef` 必须逐字出自本次给出的清单，否则整条判断按现有规则作废；`because` 为 `work` 时 `workRef` 不能为空；只凭摘要判断的（`textKind` 为 `source_summary`）分数上限 70，并标记“仅据摘要”。

**第二步，代码**。最终分由下列因素合成，权重是一张常量表，集中在一个模块里，有单元测试：

| 因素 | 含义 |
| --- | --- |
| 模型相关度 | 第一步的 `score` |
| 来源偏好 | 该来源的文章被打开、读完、收藏、划线、收下的比例，做平滑处理，新来源取中间值 |
| 主题偏好 | 命中的主题上，用户的“多看这类 / 少看这类”与实际行为 |
| 新鲜度 | 随发布时间衰减 |
| 重复 | 同一事件已有更高分的代表文章时降权 |
| 人工 | 用户手动标了“属于”的置顶到该主题内；标了“少看这类”的来源或主题扣分 |

要求：每个因素单调（其他不变时，它越好分数不降）；任何一条文章都能列出贡献最大的两个因素，界面用它们生成理由；权重改动必须同时改测试。

### 2.3 给出

| 视图 | 内容 |
| --- | --- |
| 为你筛过的（默认） | 最近 48 小时、未读、最终分达到门槛（默认 60）的文章，按分数排，最多 12 篇。每篇带一句理由。下面折叠着“其余 N 条”，按时间排 |
| 全部、未读、收藏、各主题 | 保留。排序可选“按相关度”或“按时间” |
| 日报与简报 | 保留；日报的条目按最终分排，并写出理由 |

理由的写法固定三种，取贡献最大的那个：

- “因为你在写《RSS 的筛子理论》”（`work`，书名号里是 `workRef`）
- “符合：AI 视频制作”（`standard`，冒号后是主题名）
- “你常读这个来源”或“和你最近收藏的几篇相近”（`interest`）

### 2.4 学

**记什么。** 新表记录每次行为：打开、读完（滚到正文 80% 以上或停留超过按篇幅估算的时间）、收藏、划线、存笔记、存入 FastCard、引用进文档、问 AI、多看这类、少看这类、移出。只存在本机。

**马上生效的。** “多看这类 / 少看这类”点下去之后可以选一个原因（这个来源、这个话题、太浅、已经知道了），代码据此调整来源偏好或主题偏好，下一次排序就变。

**每周确认一次的。** “我的关注”是一段用户可以直接编辑的文字。每周一次，模型根据这段时间用户实际读了什么、跳过了什么，提出对这段文字的修改；以一张“筛子校准”卡片出现在资讯和今日页，用户可以接受、改写或忽略。**不经确认，这段文字不会变。** 自动学到的东西不直接进提示词，这与项目对站点知识的规矩一致。

**量。** 设置里显示两个数：过去 14 天“筛过的”里被用户打开、收藏或收下的比例（命中率）；用户收藏或收下、但当时没进“筛过的”的篇数（漏网）。

### 2.5 送达（用户已确认的三处）

| 去处 | 规则 |
| --- | --- |
| 今日页 | “为你筛过的”前 5 篇，带理由，由 W6 的今日页消费本工作线提供的查询 |
| 每日日报 | 现有刊期机制不变，排序与理由按上面的规则 |
| 系统通知 | 只发“必须知道”的：用户在主题上打开了“必须马上知道”，且文章最终分不低于 85。每天最多 3 条；默认 22:00–08:00 不发；点击在 Ready 里打开文章。用持久的送达记录保证同一篇只发一次，重启不重发。默认没有任何主题是“必须知道”，所以不设置就不会有通知 |

微信、飞书推送不做。

### 2.6 收下

由 W6 的收下矩阵接入：文章与选区存入 FastCard、经 FastCard 进画板、引用进当前文档。阅读页的动作位置与叫法和书房、PDF 统一（W4 §3）。

## 3. 隐私

“在做的事”清单和“我的关注”会随判断请求发给用户配置的模型服务商。这必须让用户知道并能关掉。

- **首次进入资讯时问一次，不预设开或关**（路线图 §9）。一张卡片说明“筛子可以参考你正在做的事，这份清单会随判断请求发给你配置的模型服务商”，下面原样列出此刻会发出去的清单，两个按钮：“开启”“先不用”。卡片不挡操作；**回答之前按关闭处理，清单一个字也不发**。
- 选择记在设置里，之后不再问。“设置 › 资讯”里有总开关“让筛子参考我正在做的事”，下面原样显示当前会发出去的清单。
- 开启后，三类来源可以分别关掉：页面标题、日程标题、在读的书。日程标题里常有人名，单独能关。
- 关闭后请求里不带清单，`because` 不会出现 `work`。
- 清单只含标题。标题里有敏感内容的页面，用户可以在页面的“…”菜单里选“不让筛子看到”。

## 5. 约束

- 判断仍走 RSS 的受限单请求路径：零工具、零重试；模型未就绪时排队；失败或结果不明的不自动重试，只能由用户批量重跑（运行时合同 §6）。
- 新增的迁移接在现有编号之后，不改已有迁移；升级前的备份规则不变。
- 人工纠正仍然优先；内容、规则、方法任一版本变化使旧的派生结果失效。“在做的事”清单的版本不算在内：清单变了不重判旧文章，只影响之后的判断。
- 额度：相关度并进同一次请求，不增加次数。队列按来源偏好排优先级，把有限的次数先用在更可能有价值的来源上。
- 先取全文再判断：来源只给短摘要（少于 800 字）时，判断前先抓正文；抓取有并发与频率限制，抓不到就按摘要判断并封顶 70 分。

## 7. 合同 V1–V8

| 合同 | 标准 | 入口 |
| --- | --- | --- |
| V1 可解释 | “为你筛过的”里每篇都有一句理由，理由来自贡献最大且能如实陈述的因素 | `src/__tests__/rss-sieve-scoring.test.ts` |
| V2 可调教 | “多看这类 / 少看这类”之后，同来源或同主题的下一篇分数发生方向正确的变化，并能从数据库读回 | 同上，加真实窗口 |
| V3 不擅自学 | 没有用户确认，“我的关注”的文字不变；自动统计只影响来源偏好与主题偏好这两个数值 | `rss-sieve-learning-native.test.ts` |
| V4 证据规则不退 | 现有的“符合必须有原文证据、证据不足不猜”继续成立；新增字段的校验失败按现有方式整条作废 | 现有判断测试扩展 |
| V5 送达唯一 | 同一篇文章的系统通知最多一次；重启、重扫、重复消费都不重发 | `rss-notification-native.test.ts` |
| V6 隐私 | 用户没有回答首次询问时、以及开关关闭时，发出的请求里都不含“在做的事”；关掉某一类来源后清单里没有那一类；设置里显示的清单与实际发出的逐字一致 | `rss-work-context.test.ts` |
| V7 额度 | 一篇文章一次请求；每日次数不超过设置；队列按来源偏好排序 | 现有处理测试扩展 |
| V8 默认是筛过的 | 进入资讯模式默认落在“为你筛过的”；没有可给的内容时说明原因（没有来源、模型未配置、今天额度用完、还没有新文章） | 真实窗口 |

`npm run verify:rss-sieve` 汇总以上测试。

真实使用后的目标（不作为合入门槛，作为两周后的回看）：命中率不低于 50%，漏网每周不超过 3 篇。达不到就调权重表，并把调整记在本文。

## 8. 风险

| 风险 | 处理 |
| --- | --- |
| 模型给的相关度不稳定 | 它只占最终分的一部分；其余因素是确定的统计；理由取自贡献最大的因素而不是模型的自述 |
| 一开始没有行为数据 | 新来源取中间值；前两周主要靠标准和“在做的事” |
| 把用户圈在已有兴趣里 | “其余 N 条”始终在下面；每天从低分里随机放一篇进“筛过的”末位并标明“换换口味”，可在设置里关掉 |
| 先抓全文增加网络请求与被风控的概率 | 只对短摘要的来源抓；沿用现有的并发与验证码暂停机制 |
| 判断前抓取使用用户的登录态，会计入付费墙的免费篇数 | 只对短摘要来源、并且在当天额度内抓取，所以影响有限 |
| 通知打扰 | 默认没有主题会触发；每天上限；静默时段 |
