# 启动动画：一块透明的液态玻璃，五个字母由橙红色的点构成

用户的要求（2026-11-19）：
1. 启动动画还是旧 Ready 的（白卡片上的点阵扫描）；改成一块液态玻璃做底，用摸鱼工坊 DevDay 视频工程（devday-claude）里的点阵效果，由橙红色的点构成 Instrument Serif 的 Ready 字标，更有未来感，也更有自己的特点。
2. 看过第一版后：夜间是一块黑色玻璃，应该是**无色的、像真的普通透明液态玻璃**；一开始**不要出现点点**，初始加载时做一些**随机小点闪烁**；**确认几乎可以打开应用时**，才让五个字母附近的点出现、附着，然后出现五个字母。
3. 2026-11-20 至 23 在演示窗口里逐版看过后（修订见 §6）：玻璃要有真实的折射感，用系统的透明液态玻璃；**不要小点闪烁**；加载时玻璃里有水波——像从玻璃里看一片水池，远处有石子落水，涟漪从玻璃左侧传到右侧；加载好了水面从左到右平静下来，然后再出现点点与 Ready；Ready 字样**白色发光**、比原来小 20%；玻璃边缘要有一圈厚的倒角凸起，越靠近边缘底下的画面变形越多，向中央逐渐减弱；波纹不加高光（试过三种高光，都不自然）。

本文是这项改动的合同。先合同，后代码；每条都对应一个可运行的检查。

## 1. 窗口：透明，以及它的代价

- **窗口透明**，页面只画玻璃板和它的阴影，玻璃板以外什么都不画；玻璃本身无色（只有白色高光与极淡的白，两种外观完全相同），桌面原样透过来，不模糊。圆角与阴影由页面画（窗口不要系统阴影与圆角）。
- **已知代价**：2026-07 的逐帧截屏实证，macOS 透明窗口的出帧耦合主进程主线程，主进程的实心同步段会让画面停住，停完按时间跳到当前帧（当时因此改成不透明窗口）。2026-11-19 实测一次普通启动仍有 0.2–0.8 秒的几段阻塞，其中一段约 0.27 秒可能落在就绪之后。对策是让设计不怕停顿：加载阶段只有随机闪烁（停一下看不出来）；字标的构成放在就绪信号之后。首帧握手的保护（ready-to-show + 36 帧跑道回执，再加载重模块）照旧。
- **只动 opacity 和 transform。** 所有运动都是 CSS 关键帧或过渡，按时间计算；页面里唯一的脚本只在就绪信号到来时加一个类，不逐帧。
- **加载期间不揭示字标**：字标只在就绪之后出现。
- 启动顺序、最短可见 900ms、窗口整体渐隐退场、隐藏启动（`READY_START_HIDDEN=1`）不显示启动窗，全部不变。

## 2. 画面（S1–S5）

**S1 玻璃。** 窗口 714×254，中间是 650×190、圆角 28 的玻璃板：外侧一道极细的暗线与柔和投影（浅色桌面上也看得出板子），内侧上沿亮边、下沿厚度与一道淡淡的焦散光、一圈锥形渐变的高光边。进场时一道光划过玻璃。

**S2 加载：水波（原生层，见 §6）。** 页面在加载期间什么都不画；水波在玻璃下面的原生层里动。（原来的随机小点闪烁已删除。）

**S3 就绪：点在字母旁出现、附着，字母出现。** 就绪信号一到，闪烁淡出；五个字母依次（每个隔 55ms）在各自的 7 个拐角旁 11–24px 处冒出橙红色的点，随即附着到拐角上；每个字母的发丝轮廓沿轮廓线画出、再填实；点缩小消失，玻璃上再划过一道光。字形是 Instrument Serif 的真实轮廓（`scripts/generate-startup-splash-glyphs.py` 从应用自带的字体文件生成 `src/shared/startup-splash-glyphs.ts`），字距与外壳顶栏的字标相同，视觉中心在玻璃板中线上。字标的墨色跟随系统外观（浅色黑字、深色白字），带一圈淡淡的反色光晕，任何壁纸上都读得出来。

**S4 收尾。** 字标立住、点散尽（就绪后约 1.2s），停 0.42s，主进程把整窗在 0.28s 内渐隐后关闭。时间表只有一份：`STARTUP_SPLASH_FINISH`，页面和窗口都读它。“就绪”仍是主窗口 ready-to-show（且启动窗已显示满 900ms）的时刻。

**S5 减少动态效果。** 系统开了“减少动态效果”时，没有点、光和轮廓，字标从第一帧就在；原生层不起水波（玻璃与边缘透镜照旧）。

**S6 字标。** 白色发光（两种外观相同：白字，外面一圈 2.4px 与 9.6px 的白色光晕），字号 83.2px（原 104 的 80%），点的半径与出现距离同比缩小。

## 4. 验收

- （2026-11-23 起见 §6 W6）`node --import tsx --test src/__tests__/startup-splash-markup.test.ts`：五个字母每个拐角一个点，出现在拐角旁 10–25px；闪烁小点都在玻璃板内、半径不超过 2.2px、节奏各不相同；字标水平居中、视觉中心在中线上，玻璃板四周留出阴影边距；只有 opacity / transform 的关键帧和过渡，脚本里没有逐帧调用；页面底透明，玻璃只用无彩色、两种外观相同；nonce 只加在唯一的脚本上。
- `npm run verify:ready-next-splash`（隐藏窗口，不显示、不联网，HOME/TMPDIR 在临时目录）：两种外观各 8 项——首帧只有玻璃；加载中只有小点在闪（每帧亮着 ≥3 个、最大的不过 30 像素），没有字标；就绪后点只出现在五个字母旁边、字母还没出现；立住后没有一个橙色像素，字标和“用 Instrument Serif 字体文件在同一位置排出的 Ready 文字”重合度 ≥0.85；运行时只有 opacity 和 transform 在动、没有 requestAnimationFrame；不暂停时钟的实时播放到同样的结尾；减少动态效果时第一帧就是字标；在透明窗口里四角完全透明、玻璃平均不透明度 <20%。每 150ms 一帧、衬在彩色壁纸上的截图留在临时目录供人看。
- 不能自动验证、需要真机看的：透明窗口在真实桌面上的出帧——启动重活下加载闪烁和字标构成是否有明显停顿（见 §1）。如果构成阶段停顿明显，改进方向是把就绪信号推迟到主进程空闲之后，而不是回到不透明窗口。

## 5. 不做的事

- 不用会模糊的毛玻璃（vibrancy）；系统透明液态玻璃（`NSGlassEffectView` 的 Clear 样式）不模糊，已采用（§6）。
- 不截取或读取桌面壁纸：折射由系统合成器在窗口后面完成，应用拿不到桌面像素。
- 波纹不加高光、光晕或暗线（用户看过三种，都不要）。
- 不新增设置项；不为应用主题另存一份主题缓存（点的颜色跟随系统外观）。

## 6. 修订（2026-11-23）：系统液态玻璃下的水波

**W1 层次。** 启动窗口仍是透明窗口。在 macOS 26 及以上，主进程在页面之下加两层原生视图，自下而上：
1. **水**：一个私有的 `CABackdropLayer`（取窗口后面的桌面）带两道 `displacementMap` 滤镜——先是水波，再是边缘透镜；
2. **玻璃**：系统 `NSGlassEffectView`（Clear 样式，圆角 28），它再折射下面的水，自己的倒角弧边保留；
3. 页面（字标与点）。

水必须在玻璃**下面**：放在上面会盖住玻璃的弧边。此时页面不画自己的玻璃板（`renderStartupSplashMarkup(theme, { glass: 'native' })`）。

**W2 水波。** 四个石子在玻璃左边的远处，波包从左向右穿过玻璃（每个 1–2 滴，波长 52–82、包络 64–94 点，速度 80–104 点/秒），全部是 Core Animation 动画，在渲染服务器里跑，主线程卡住也不停。强度 18。位移图的蓝通道是“推过的画面替换原画面的比例”，必须是 1：0.5 时真实窗口里玻璃发灰、波纹只剩一半。

**W3 边缘透镜。** 一张静态位移图：在圆角矩形边缘向里取样（放大边缘内侧的画面，像凸起的厚玻璃倒角），贴边最强，向里约 44 点平滑减到零；强度 200。向外取样不可行（背景层只看得到玻璃板以内）。

**W4 收尾顺序。** 就绪信号到来时，主进程先让水面从左到右在 1.2 秒内平静（一道“无位移”的覆盖层滑过位移图），之后才向页面发就绪信号，点与字标照 S3 进行，渐隐与关闭的时刻相应后移 1.25 秒。

**W5 回退。** 不是 macOS、系统低于 26、原生模块不存在（开发机没编译，或 Windows）或加载、挂接失败时，页面照旧画自己的玻璃板（S1），没有水波。原生模块随 `rebuild:native` 与 `postinstall` 在 macOS 上编译（`postinstall` 时编译失败只警告），打包时作为 mac 资源放在 `Resources/native/ready_glass.node`。

**W6 验收。**
