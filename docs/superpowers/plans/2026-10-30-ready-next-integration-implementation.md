- 保留 `browser | document | rss | calendar` 四个模式。书房是文档模式的系统标签页；不新增第五模式，不把 RSS 改名为阅读。

## 3. 架构与数据归属

### 3.1 三层存储、资料库与身份

| 层 | 内容与权威 | 边界 |
| --- | --- | --- |
| 资料库文件 | 文件自身是正文权威：页面、画板、来源页、书、附件 | 可被其他编辑器与 Agent 读取；不会由数据库里另一份正文覆盖。 |
| 资料库 `.ready/` | 对应服务管理需要随资料库携带的机器数据：锚点、评论 | `.ready/anchors/`、`.ready/comments/` 保存 JSON；不放 SQLite。 |
| 独立 userData 下的 `ready.db` | 各模块服务管理日程、FastCard、阅读位置/书签、下载任务、草稿、界面状态；对象/关系/全文索引为派生数据 | 不跟随同步盘搬走；重建索引不删除日程、草稿等权威业务记录。 |

是否需要交给另一台电脑或另一种工具，决定数据是否随资料库携带。FastCard 尚未确定保留，先在数据库；“保存到画板”成功后才进入资料库。

```text
资料库/
├─ 灵感.canvas
├─ 灵感/                     子画板、从画板保存的页面
├─ 灵感.assets/
├─ 阅读.md                    书房数据库定义及视图
├─ 阅读/
│  ├─ 三体.md                 来源页：属性、标注、笔记
│  └─ 三体.assets/            EPUB 与封面
├─ 项目/
│  ├─ 新书发布.md
│  ├─ 新书发布/会议 11-03.md
│  └─ 新书发布.assets/
├─ 日记/2026-10-30.md
├─ 模板/
└─ .ready/                    锚点、评论；界面隐藏
```

从 `file_identities` 演进出单一对象登记表。页面首次被文件之外的对象引用（日程、画板、标注、数据库关联、Agent 来源）时才写入 frontmatter `ready_id`，不批量污染所有 Markdown；画板身份位于根对象 `ready.id`，书使用来源页身份；其他文件登记路径、inode、内容哈希。搜索、书签、阅读会话、文件活动改为消费对象 id。

Ready 与 Agent 改名经写入服务；Finder/git 外部移动由监听器以 inode/内容哈希配对，并以文件中的 `ready_id` 确认身份；跨机器靠持久 id 恢复。内容相同但仍同时存在的两个文件不能直接合并身份；身份歧义须显式报告。C2 的删除重建用例以原对象消失、候选唯一为前提，不能把哈希等同于全局身份。索引是可重建投影，源关系来自文件与数据库中的权威业务记录。

### 3.2 ReadyRef 与关系索引

共享类型计划放在 `src/shared/ready-ref.ts`，使用 zod 在边界解析，`toReadyUri` / `parseReadyUri` 负责唯一往返规则。以下是 v2 已确认的语法示例，示例 id 与文件名不代表仓库现有文件：

```text
ready://calendar/event/evt_8k2
ready://calendar/day/2026-11-03
ready://calendar/day/2026-11-03?at=15:00&remind=10
ready://read/book/bk_7q2#c12:3381+21
ready://canvas/cv_31x#node=n_9
ready://rss/item/it_552
ready://web?url=https%3A%2F%2Fexample.com%2Fessay
ready://agent/conversation/c_1#run=r_4
```

文档之间继续支持 `[[页面]]`、`[[页面#标题]]`、`[[页面#^块]]`、`![[…]]` 以及标准相对链接。重名先按路径解析，仍不唯一则提示选择；相对链接也形成关系边；内部引用在 Ready 内打开。日历重复实例继续保留现行结构化实例身份，不得把选中实例降成母事件；具体序列化变体在 C1 实现前补入同一合同与往返语料。

`ready-rss://`、`calendar-event://`、`calendar://`、`rss://`、`rss-reference://`、`browser-tab://`、`doc-tab://` 及拆分应用的私有链接仅在一次性迁移器内识别；迁移成功后删除生产读写旧路径，不保留兼容开关。

`doc_links` 扩展为 `object_links`：边来自 Markdown 链接/嵌入、frontmatter 关联、画板节点、日程关联、标注、卡片出处与 Agent 来源。可全量重建，不反过来成为正文真值。ReadyRef 只负责指向与跳转，不授予访问权限；对话 `@` 由 Main 转为既有资源类型，保留稳定 id、版本和摘要，遵守本轮冻结授权。

### 3.3 两个写入口与跨边界状态

| 对象 | 唯一写入口 | 可复用基础 |
| --- | --- | --- |
| 文档及其层级/链接 | Main 写入服务，供标注、日期拖动、插入引用、改名/移动使用 | Tag Forge 已有的可回滚保存与回读；不扩大其工具授权。 |
| 画板 | 画板句柄，供 FastCard、Agent、画板 UI 使用 | 既有句柄、原子写和回执。 |

共同输入是对象 id、期望版本和结构化操作；文档操作包括追加块、改 frontmatter、替换区间、重写链接，画板操作包括增删改节点。Agent 的 `document_*`、`file_rename`、`file_move` 接到相应写入口，不再直接绕过身份登记改文件。

未打开的对象由 Main 原子写入、回读、更新索引后返回回执。打开且有未保存内容时，Main 将操作交给拥有该缓冲区的标签页，合并并确认后再提交；不能合并则返回明确冲突。标签页切换、关闭、迟到确认或版本变化都不能把旧缓冲发布为新内容。

后续类型和测试须显式区分请求中、等待缓冲确认、提交中、已提交、冲突、失败；Main 拥有持久提交状态，Renderer 拥有当前编辑缓冲。回执绑定对象、版本与操作身份，重试不能重复追加卡片/段落，成功只能在落盘与回读后发布。跨文件、附件和索引的操作须定义可回滚或可恢复的提交边界，失败时保留草稿或暂存，不先显示成功后吞错。

### 3.5 书房

侧栏“阅读”打开或聚焦唯一系统标签页，主区域保留书架、取书动画、纸张翻页与笔记面板；可与文档左右分屏。窄区自动单页，页边批注收进笔记面板，沉浸模式可收起侧栏与助手。EPUB 从文件树打开也进入书房；foliate-js 负责 MOBI/AZW3/FB2/CBZ，PDF 沿用现有阅读器。文档书本模式在 M3 结束时决定是否共用分页引擎，记录明确归属，不能无限期保留两个重叠实现。

`阅读.md` 与 `阅读/` 构成书房数据库，M2 先实现来源页和书架，M5 补通用数据库视图。书名、作者、年份、出版社、语言、15 类分类、标签、来源、字数、状态、读完日期进入来源页；书脊样式按 `ready_id` 稳定生成。翻页进度、书签、打开时间在数据库，翻页不改正文。

划线/批注写成来源页中的引用块与块 id；四色荧光笔、红笔、重叠合并与按章笔记保留。精确锚点在 `.ready/anchors/`，包含引文及前后文、格式位置（EPUB/TXT 为章节与非空白字数，PDF 为页码）。定位顺序为格式位置、引文核对、全文搜索，无法确认则“未定位”，不猜一处文字。

文档可插入 `![[三体#^hl-7f3a]]` 引用卡，点击回到原文位置，分屏时在另一侧打开；阅读器显示引用它的文档数量。选中文字可入 FastCard；Agent 读书笔记逐条引用来源标注。

本地导入 EPUB/TXT/MD/PDF/MOBI/AZW3 常开；Z-Library 调用本机 `zlib` CLI，可设置路径和格式，Ready 不接触账号密码。`ctfile` 默认关闭，同时控制电子书宝库索引和城通网盘模块；开启的自用构建才显示设置入口，验证码交给用户，压缩包只取 EPUB。

下载归 Main，数据库记录排队、下载、等验证码、解压、完成、失败；重启可恢复或明确失败。缓存下载完成并上架后移入资料库，失败/取消清理临时文件。藏书阁 `library.json` 一次导入为来源页、书文件、标注、锚点，进度与书签入数据库，生成迁移回执。

### 3.6 FastCard、画板与成文

完整路径为“添加到 FastCard → 保存到画板 → 整理 → 添加到文档 → 保存到所选层级”，每一步保留出处。

- FastCard 保留浏览器浮层、翻译、反推描述与引入对话的手感；暂存入数据库，图片在添加时进入应用缓存。保存目标为上次画板或《灵感》，也可选其他或新建；保存不切走当前网页，成功后默认移出暂存并允许撤销。失败保留原暂存。
- “添加到 Reference 画板”改为“添加到画板…”，无需先打开目标。全局快记 `⌥⌘Space` 收文字、语音、剪贴板进 FastCard；文档模式的画板侧边可显示 FastCard 拖入栏。
- 一个引擎采用 Stillroom 的磁吸成簇、P/L/R 排版、子画板、回收站、撤销、链接/语音卡，加 Ready 的箭头、形状、手绘。正文用 JSON Canvas 1.0 `.canvas`，Ready 扩展放 `ready`，附件在同级 `画板名.assets/`，子内容在同名文件夹。
- 文字卡存 Markdown，双击原地编辑，长文可用居中编辑窗。文档卡按路径引用文件，经对象身份追踪移动，实时显示标题/摘要，编辑仍走文档写入服务。
- 选区“添加到文档”可选新文档、最近文档、当前草稿；新建时出现虚线草稿卡，按从上到下、从左到右且同簇相邻排序。文字复制为可改段落并附出处（原网页/书优先，否则画板节点）；图片复制到新页面 `.assets`；书摘、划线、文档卡为引用嵌入。
- “保存到…”成功后草稿卡才变文档卡；追加最近文档也经写入服务。`.readyboard` 只作为可在浏览器查看的网页导出格式，旧编辑文件一次迁到 `.canvas` 并留回执，删除旧读写路径。
- Stillroom zip/自动保存 JSON 一次导入，HTML 正文转 Markdown，`idb:` 媒体变附件。链接预览合并为 Main 服务，共用于画板、页面书签块、FastCard，保留防内网请求与大小限制。语音转写使用支持音频的 Ready 模型接入，不依赖 Electron 缺失的浏览器语音识别。

### M1 实施细化（2026-10-30）

依据两份只读调研：身份统一设计（任务 E）与旧伪协议清单（任务 H）。原始报告不入库，结论如下。

**顺序。** 写入服务 → 身份统一 → 关系索引 → ReadyRef 迁移各批。身份写入 `ready_id` 必须经写入服务，所以写入服务先行；资料库设置、跨模式返回与写入服务改动的文件不重叠，可以并行。

**身份统一。** `file_identities` 演进并改名为 `objects`：`objects.id` 沿用原 `file_key`，写入成功后等于文件内的 `ready_id`（画板为 JSON 根上的 `ready.id`）；路径、inode、内容哈希只用于定位和核验，不再各自承担身份。搜索索引、书签、阅读会话、文件活动，以及 Renderer 的标签页、阅读位置、文件外观，一次迁移为按对象 id 记录，不留双写。已确认的边界：

- 只有用户创建的持久关系（书签、标注、关联、来源）才触发写入 `ready_id`；打开标签页、自动阅读记录不改文件。
- 升级时只为已有持久关系涉及的 Markdown 补写 `ready_id`，不扫描全库；不可写或冲突的文件保留本地关系并明确标注。
- "删除后同内容重建"只在同一变更批次、原位置消失、候选唯一时认领；窗口外依靠文件内 id 或明确的恢复操作。
- 外部复制产生的重复 id 先隔离为冲突，由用户引用或"作为副本导入"时经写入服务换号；监听器不擅自改文件。
- 同一数据库里一个对象只有一个活动位置；第二份副本按复制冲突处理。
- 非 Markdown／画板文件不保证跨机器不断链；书以来源页为身份。
- 外部改名后引用方不可写或有未保存编辑时，持久记录待修复链接，不覆盖正文。

一并修复调研发现的现存缺陷：`findRelatedFiles` 查询不存在的 `f.last_seen_at`；内部移动后历史活动回填为旧路径新建身份；删除目标后 `doc_links.resolved` 未清零；Agent 的 `organize_undo` 与 rename、move、organize_apply 一样绕过身份登记。

**ReadyRef 迁移分七批。** 每批同时改生成、消费和必要的数据迁移，不保留同一对象的新旧双读路径：

1. 核心与迁移合同：先定 RSS 精确引用（含文章版本与选区）、无持久身份的草稿、无 URL 书签的表达方式。

## 6. 检查与交付规则

每个实现里程碑先写能观察实际结果的测试，再实施最小改动；结构 lint 只覆盖结构红线，不能用源码 grep 代替保存、跳转、恢复和 UI 行为。被 skip 的用例属于未覆盖，不算通过。后续检查按改动范围执行：

- 代码/类型改动运行 `npm run typecheck`；SQLite、设置、索引及本地持久化运行 `npm run verify:native`，新增原生合同接入现有运行器。
- 阅读、Widget、文件涌现、Tag Forge 受影响时运行既有 `verify:document-reading`、`verify:widget-ready`、`verify:file-emergence`、`verify:tag-forge`；样式变动运行 `node scripts/check-css-cascade-layer-reset.cjs`。
- 真实 Electron 使用独立 userData 与测试资料库，验证主窗口、分屏、BrowserView、保存失败与强制退出恢复；包体声明只能以实际构建产物证明。
- 原方案记载 Stillroom 38 项、Tempo 50 项及 Inkwell 冒烟脚本；移植时先核对当前脚本再改为在 Ready 中执行，不把历史数量或独立应用通过当作 Ready 已通过。
- 代码文件净增行数后检查总行数，超过 1000 行按 [大文件健康台账](../../code-health/large-file-health-log.md) 规则登记；不在子任务允许范围时报告，不能越界修改。
- 每阶段给 Claude 的交付包含文件清单、合同证据、失败归属与未完成项，审阅后合入；不得以空审阅结果放行。

本次纯文档交付按 [文档导航](../../README.md) 的检查入口核对：根指引同步、版本、`verify:meta-paths`、测试规约文档、R/T 引用检查和 `check-plan-pairing.cjs --all`；另核对本计划链接、D/C/M 编号及两处登记。上述文档检查不证明 C1–C15 产品行为，未来测试名不作现存链接。
