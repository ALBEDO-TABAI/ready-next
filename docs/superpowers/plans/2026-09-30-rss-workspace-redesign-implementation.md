## 1. 这轮要达到什么结果

让 RSS 在保留 Ready 设计风格的基础上，形成便于浏览、筛选、阅读和与 Agent 协作的资讯工作区。参考 AIHOT 的信息组织与版式，不复制它的品牌、网站运营区域或整套服务。

本次检查点包括冻结的 v0.1 与复审后定稿：六项要求均有对应方案、现有能力复用位置、可验证的完成标准，另补用户确认的事件归组和日报。复审完成后按阶段施工，不接入未授权的付费采集服务或外部推送。

后续施工的完成标准：用户能够自定义资讯入口和分类，收起导航后舒适阅读；文章内容与原文来源清晰；界面、Agent、导出读到的内容与筛选范围一致；重启、刷新、切换模式不丢失用户设置和阅读状态。

## 3. 产品与交互方案

### 3.1 边界与建议

- RSS 仍是现有四种工作模式之一，保留 Ready 的全局外壳与 Agent 工作区。
- 参考 AIHOT 的日期分组、摘要卡片、顶部筛选搜索、正文主次层级；颜色、字体、圆角、留白和交互反馈服从 Ready 当前共享样式。
- 不照搬 AIHOT 的品牌、固定 AI 行业栏目、分数颜色或网页深色背景。
- 本轮包括事件归组、重要性精选与站内日报。公众号付费获取、外部推送、全网热点和模型榜不随此次改版自动加入。

### 3.2 工作区布局

建议的结构关系如下，具体宽度以真实 Ready 工作区可用空间验证后确定：

```text
Ready 全局外壳与模式入口
┌ RSS 内部导航 ┬ 当前栏目标题 · 自定义筛选 · 搜索 ┐
│ 展开/收起    │ 日期 / 数量 / 更新状态            │
│ 图标＋名称   │ 资讯卡：来源、时间、标题、摘要     │
│ 自定义栏目   │ 标签与归类理由；关联报道按需展开   │
│ 订阅管理入口 │ 阅读正文或继续浏览资讯流           │
└─────────────┴───────────────────────────────────┘
Ready Agent 面板继续由全局布局管理
```

- 资讯卡保留来源、发布时间、原文入口、未读/收藏和已有分析入口。没有生成的推荐理由或评分不显示虚构占位值。
- 搜索与筛选共同生效；搜索结果显示当前范围、总数及一键清除条件，不在无提示时从当前栏目跳成全库搜索。
- 搜索默认匹配标题和已有摘要；扩展到已保存正文必须明确标明搜索范围，搜索本身不触发后台全文抓取。先用普通关键词匹配，不额外引入语义搜索服务。
- 顶部分类条来自用户定义。长名称、较多项目通过横向滚动或溢出菜单处理，不挤出搜索区。
- 返回列表时恢复栏目、筛选、搜索、排序和滚动位置。
- 宽屏可展示导航、正文和辅助信息；中窄工作区先收纳辅助信息，再压缩导航，不强制照搬网站四列布局。
- 搜索无结果、正在更新、部分来源失败、缺少正文、尚未分类分别展示，不共用一个“没有内容”。
- 日期分组使用应用当前时区；优先显示原始发布时间，缺失时标明“收录于”，不伪造发布时间。首次订阅的历史文章不自动成为“今天的新消息”。
- “全部动态”默认对应现有收件箱范围（含应保留可见的收藏）；被清出收件箱的底稿仍有明确的历史查询入口。切换到历史范围后，数量、搜索、Agent 与导出一起切换，不能只在其中一处悄悄扩大范围。

### 3.3 液态玻璃的应用范围

| 区域 | 建议呈现 | 要守住的效果 |
|---|---|---|
| 导航与顶部工具区 | Ready 现有玻璃表面和选中态 | 明暗主题一致，选中项清楚 |
| 分类筛选、搜索、菜单 | 复用液态玻璃控件与浮层 | 点击、键盘焦点、边界和弹出位置正确 |
| 资讯卡与辅助信息块 | 同体系的轻玻璃表面 | 摘要易读，长列表滚动不被重度折射拖慢 |
| 文章正文 | 沿用文档阅读排版，玻璃用于外围控件 | 不让玻璃效果降低长文阅读清晰度 |

“尽量使用”不等于给每篇资讯建立一份动态背景投影。强折射用于有限的浮动控件；大量重复卡片使用共享表面样式。出现性能问题时先减少重复投影，不另建一套 RSS 专用材质体系。

### 3.4 自定义栏目、筛选与智能归类

先区分两类可配置项目，避免仅能改名称、实际内容仍被固定规则控制：

1. **左侧栏目**决定看什么集合，例如“全部动态”“值得读”“AI 视频制作”“品牌案例”。支持创建、改名、修改描述、排序、图标、显示/隐藏及删除自定义项目。
2. **顶部分类筛选**细分当前集合，例如“工具更新”“教程”“案例”。同样支持名称和描述；栏目与分类引用同一份已保存定义，不各自维护词表。

新增时用户只需填写名称与描述。示例：名称“AI 视频制作”；描述“关注模型更新、实际制作流程和可复用案例，排除单纯融资消息与无操作细节的宣传”。

建议采用下列最小语义；它们属于实施默认方案，不要求用户逐项选择技术做法：

- 内容允许属于多个主题；不为了塞进某一类而强制单选。无法判断时保留未分类状态。
- “全部”“未读”“收藏”是阅读状态集合；“精选”是按用户标准形成的集合；“主题”是语义分类入口。显示名称、顺序和可见性可调整，但改名不能改变收藏的真实含义，也不能让全部内容无处找回。
- 默认项目只是可编辑起点，不把“AI 动态”“模型”“论文”等写死。本轮提供真实可用的日报入口；不预置没有数据能力的全网热点榜。
- 删除栏目或分类只移除定义及归属关系，不删除原文、收藏或阅读记录。
- 每条自动归类保留理由和依据；用户纠正优先，刷新不能改回。修改描述后旧结果标明需要更新，按用户选择重算旧内容，不默默对全库重新收费。
- 默认只对新内容或确实变化的内容进行自动归类；失败不影响普通订阅与阅读。
- 用户已选择新增资讯自动处理。自动处理不默认回算首次导入的全部历史；历史整理入口先显示范围和数量。
- 首期“精选”不能用“收藏”冒充：根据用户填写的关注标准给出入选/不入选/证据不足以及简短理由。默认不展示未经校准的 0–100 分数，不复制 AIHOT 双次打分。分类与精选可在同一次受控判断中完成，但分别保存结果含义。
- 只有改名称、顺序、图标或可见性时不重新运行分类；描述标准改变才更新规则版本。用户手工“属于/不属于”覆盖自动结论，并可选择恢复自动判断。
- 栏目与顶部筛选共用定义：顶部项目通过指定分类 ID 绑定到栏目，查询取“栏目集合 ∩ 当前分类 ∩ 搜索/阅读状态”；不是自动创建第二套同名分类，也不是每篇资讯只能归到一个文件夹。

**子 skill 的实现选择：**采用一个通用“资讯归类”方法，名称用于展示与识别，描述是模型读取的归类标准；仅改展示名称不会改变语义条件。不为每个分类复制技能文件，也不为首期再拆两个流程。技能负责判断方法，应用负责保存、调度、权限和费用限制。用户无需提供技能文件。

### 3.5 文章内页与文档功能复用

点击卡片统一进入 RSS 内的阅读面；浏览器与 RSS 分栏时也如此，不因布局不同自动改为打开原文。独立的“打开原文”动作复用现有浏览器路由，不强制关闭用户正在看的网页。这修正 v0.1 中“分栏沿用原文打开行为”与“点击进入新阅读面”之间的冲突。

- 内页优先组织为：返回入口、标题与来源时间、摘要/推荐理由、正文、目录和主题标签。
- 复用文档的 Markdown 阅读排版、图片/表格/代码块显示、标题定位、复制与引用能力；只把与文档标签、保存和编辑绑定的部分留在 Document 中。
- 新闻原文默认为只读；用户明确选择“保存为笔记”后，才创建可编辑文档，并保留来源链接。RSS 原文与用户笔记是不同用途的内容，不在背后双向覆盖。
- 来源摘要、提取正文、AI 摘要和翻译分别标识，不能把来源摘要标成“全文”。没有译文时不显示可用的中外文切换。
- 正文缺失、需要登录、仅抓到部分内容时，说明实际状态并提供原文入口；长文按章节或片段读取，不能默默截掉后半篇却声称已读完整。
- 目录和 Agent 引用位置都从同一份正文产生。重新提取后，旧引用能识别版本变化，不能跳到错误段落。
- 来源内容作为资料处理，不允许其中的文字、脚本或特殊文档块自动变成应用指令、可执行卡片或文件操作。
- 打开阅读面先显示已保存内容；不足时按需发起正文提取，多个同时读取者合并为一次获取，不默认为全部订阅后台下载全文。依赖登录的内容沿用应用现有浏览器会话与用户接管流程；失败保持可阅读的摘要，不降级成模型补写。
- 文章、图片帖和视频分别呈现：视频保留封面、原始链接与已有文案/视觉分析入口，不将视频标题当成完整内容。图片/视频资源的来源、可用性、已完成分析及缺失状态对 Agent 可查；实际视觉理解或转录仍需对应能力与动作。
- 保存笔记时使用用户选择的合法文档位置，不覆盖同名文件；创建后回读确认内容与来源，再进入文档模式。此动作不自动开启原文与笔记的双向同步。

### 3.6 Agent 可读范围

“全部信息可读”指 Agent 可以按需查询 RSS 内已保存、当前会话有权访问的资料；不等于每轮把整个资料库塞进对话，也不等于缺失的全文已经获取。

| 信息 | Agent 必须能获得的内容 |
|---|---|
| 当前工作区 | 当前栏目、分类定义、搜索条件、排序、结果总数、选中文章 |
| 内容集合 | 分页查询所有符合条件的条目，不止屏幕上已加载的几张卡 |
| 单篇内容 | 原始标题、来源、时间、链接、来源摘要、正文及完整性状态 |
| 图片和视频 | 已保存或可访问的媒体引用、媒体类型、缺失状态，以及已有转录/分析；不得把“链接可读”说成“已经理解媒体内容” |
| 整理结果 | 自定义主题、归类依据、推荐理由、事件成员/后续进展与日报正文/引用 |
| 用户状态 | 已读、收藏、手工归类及纠正，不从卡片颜色猜测 |
| 工作进度 | 实际刷新时间、部分失败来源、分类/分析状态及可读取的产物 |

基本验证场景：“总结我当前筛选下的全部资讯，并说明为何归入这个主题。”返回条目必须和界面同范围，超过一页也能继续读取；引用必须回到确切文章与正文位置。

只读查询不应为了拿数据而强制切换工作模式、打开网页、启动分析或改阅读状态。执行这些动作仍走原有动作入口和授权。

### 3.7 左侧收起与移除区域

- 不搬入图 4 的“Agent 接入、关于、更新日志、反馈、GitHub 开源、独立主题切换、备案信息”等网站附属区域。Ready 自身原有设置、帮助和主题控制不因此删除。
- 展开时显示图标与名称；收起时只显示图标，悬停或键盘聚焦可看到名称，当前选中项仍清楚。
- 左上角按钮切换宽度，列表/正文自然获得空间；不能只是把文字透明化而保留原宽度。
- 收起前后的选择、搜索、滚动和阅读状态保持一致。折叠偏好重启后保留；窄空间临时布局调整不覆盖用户偏好。
- **范围已确认：**用户明确选择“RSS 内部导航”。折叠仅作用于 RSS 内的栏目/主题切换区，不扩展到 Ready 全局主侧栏。

### 3.8 事件归组与站内日报（用户已纳入本轮）

**事件：**多篇报道可以描述同一次发生；后续进展是新的事实，但仍属于原事件。仅有相同公司名或相近标题不能直接合并。归组保留原始文章、来源、收藏与阅读状态，只减少重复展示；分组卡显示代表报道、来源数及可展开的成员和进展。

- 分类阶段提取事件事实和依据，再从近期已有事件中找有限候选作语义判断；不移植 AIHOT 完整向量服务与多模型复核体系。候选不足或证据不够时保持分开，不强并，也不把未处理当成已判无关。
- 优先展示直接来源及信息完整的报道，但不把“一手”当成内容正确的证明。成员排序、后续进展与去重规则由代码执行。
- 提供“拆开”“移到另一事件”“并入事件”的纠正入口，纠正持久化并优先于后续自动归组。移动/删除文章或修改归属时更新相关数量、精选卡、引用和日报状态。
- 未读与收藏仍属于原始文章；组卡汇总成员状态，“读一篇”不把其他报道批量标已读。成员有新增进展时组卡提示新内容，而非反复把已读原文当新文章。

**日报：**本轮是 Ready 内可阅读、可引用、可导出的日报，不自动发送到外部。采用可在设置中修改的默认时间：应用本地时区每天 08:00；使用现有定时任务能力，应用关闭或休眠时不承诺后台运行，恢复后合并补生成最近一期，不补发一串历史通知。

- 每期明确显示时间窗、覆盖订阅、规则版本、生成时间和处理完整性。收稿按首次完成精选的可用时间归期，而非数据库每次刷新时间；首次导入历史材料不混入今日新闻。原始发布时间仍在文章中展示。
- 同一事实每期只列一次，已报道的旧事实不重复占篇幅；真正新增的进展可以再次入刊。采集未完成、正文不足或整理积压时标明遗漏范围；不要把“暂无已入选内容”改写成“今天没有新闻”。
- 无有效新内容时呈现空刊状态，不为凑字数调用模型。有效内容按用户分类组织，包含发生了什么、为何值得关注、原文引用；每个事实性结论须能回查本期输入材料，不仅检查链接是否存在。
- 原文、自动综述和模型判断分别标识。汇总不能补写来源未支持的功能、数字或结论；存在矛盾的报道保留差异，不擅自裁成一个确定事实。
- 同一刊期重复触发复用结果；显式重新生成创建新版本。正文引用绑定文章/事件及内容版本；用户更正归组后旧刊标明待更新，重生成使用新归属，不能悄悄改掉用户正在阅读的旧版本。
- 用户可主动生成当前范围简报；它与每天全订阅的日报是不同范围，标题及覆盖说明必须区分。Agent 能读日报、追溯引用，也能在 RSS 未打开时查询已生成日报。

### 3.9 日报施工合同补充（保存前置项关闭后的复审）

日报使用已接受的精选理由、逐字来源摘句和事件关系组成可阅读刊物，不再调用模型重新判断事实或扩写结论。原文摘句与模型精选理由分开标识，多个来源互相矛盾时保留各自说法。无内容也生成明确的空刊状态，不补造新闻。

归期不能从“是否有自动模型任务”推定：自动整理关闭期间新增的资讯仍可能被用户手工精选。因此采集事务保存首次历史导入/真正新增的接纳资格；历史来源迁移不伪造新内容资格，当前范围简报不受日报资格限制。

首次精选可用时间必须是持久事实，不能使用每次查询、刷新或恢复时的时间。每个文章完整版本仅记录首次成为有效精选的时刻，不复制精选决定正文；通过同一有效归属读取规则，在分类发布、人工决定、来源/正文变化时同事务核对并登记。重复提交、取消再恢复、A→B→A 不改首次时间。已有模型结果可沿绑定的成功任务证明时间，无法证明的历史时间不补成迁移当天。报告仍按当前有效精选判断是否采用，时间记录本身不授予入选资格。

只保存必要的刊期/版本、不可变刊物条目与引用快照、接纳资格和首次可用时间。日报发布与本次待刊完成同事务，刊期唯一；明确重新生成才新增版本。旧刊保留内容，来源删除、证据撤回、规则和归组纠正产生可读取的需要更新状态。日报去重按事实及其所用文章版本关联，不能仅按新建事实 ID 把人工拆分的旧材料当新闻；范围简报不消耗日报已刊记录，同一期重生成只排除其他刊期。

调度复用 `ScheduleCoordinator`、`ScheduleClock` 与现有时间计算，通过 RSS 专属存储适配器接入，不创建虚构 Agent 会话或第二套计时实现。默认本地时区 08:00，按当地日历边界计算；时间窗左闭右开。关机/休眠后只生成最近一期，窗口从上次成功覆盖截止延展至最近截止，明确展示跨度；恢复时先合并历史待刊记录，不能在 `listRecoverable()` 阶段逐条生成。曾入选但旧刊生成时已失效、之后恢复且从未入刊的资料按补收项纳入，并保留原首次时间，不通过改时间把它冒充今日新增。

施工先建立以下真实行为断言，再连接 UI 和 Agent：

| 场景 | 验收结果 |
|---|---|
| 自动整理关闭后新增，再手工精选 | 可进入日报；首次历史导入不因此入刊 |
| 截止前采集、截止后才完成精选 | 按首次可用时间进入下一期，不误投已关闭刊期 |
| 重复保存、重复正选、A→B→A | 首次可用时间不变；已刊事实不重复，未刊恢复项明确补收 |
| 同事实转载、正文补全、人工拆组 | 无实际新内容不靠新 ID 再次占刊；真正新进展可入下一期 |
| 停机数天、恢复与定时同时触发 | 只发布最近一期，覆盖未刊跨度，无重复刊物 |
| 无有效内容、存在积压或缺失正文 | 明确空刊/遗漏范围，不等价于“没有新闻” |
| 范围简报及同一期重生成 | 简报不抢日报内容；旧版本保留，新版本仍包含本期有效材料 |
| 生成中断、资料被删或依据撤回 | 不发布半份刊物；旧刊保持原文并显示失效状态；引用不能跳到新版本冒充旧证据 |
| UI、Agent、导出及引用 | 读同一已发布版本和全部条目，分段边界明确，RSS 未挂载时仍可读 |

本节是日报施工合同，实施与本切片验收见 §11 的日报记录；整轮改版仍按剩余合同继续。

## 5. 实施边界与唯一事实来源（拟定）

### 5.1 工作区与视觉

在 RSS 工作区内划分导航、查询栏、资讯列表与阅读面；局部组件拆分只服务本需求，不扩建通用页面搭建器。

复用共享颜色/间距/表面样式与液态玻璃组件，必要参数最小化向下传递。背景源限定在当前 RSS 工作面的内容层，排除浮层、克隆层与旁边聊天区。Portal 浮层受 RSS 面板实际边界约束。

存在 BrowserView 的分栏/预览场景仍需 hide-ack、show 和 bounds 协调；宽度动画、主题切换、窗口缩放不能只靠 CSS 层级解决原生页面遮挡。

复用 `rssWarmCache` 时必须接入数据变更失效；读取 A 栏目后立即切到 B，A 的晚到响应不能覆盖 B。折叠与布局宽度只用一份状态，不能靠 CSS、React 和原生浏览器各猜一套宽度。

### 5.2 原文、阅读、引用

Main 的 RSS 内容存储是文章身份、来源和正文版本的唯一权威。定义一份文章读取结果供 RSS 阅读、Agent 和导出使用；至少包含文章 ID、原文 URL、正文版本、正文/来源摘要、完整性状态及获取时间。

已有正文直接读取；缺失正文通过受控获取流程补充，获取与纯读取分开。长文采用明确分段，不用额外摘要冒充原文。提取部分优先复用 clipping 的纯适配器，检视其现有失败边界后接入，不复制一套 HTML 清洗与 Markdown 转换。

`NotePreview` 中依赖可信本地文档的能力需要隔离：RSS 来源不开放内联编辑、脚本 Widget、本机文件跳转或任意外部动作。原始 Markdown 中看似 Ready 特殊块的内容按来源文本展示。只有用户实际保存成文档后，才进入现有文档写入权限与生命周期。

引用资源绑定文章 ID、正文版本、选区和原文 URL，复用现有聊天资源桥的传递方式；不得伪造本地文件路径，也不能因复用阅读组件就授予 `current_document_context` 编辑权限。

### 5.3 栏目定义与分类结果

保存最少必要的栏目/分类定义：稳定 ID、类型、名称、描述、顺序、图标/可见性、规则版本。内容关系记录文章 ID、定义 ID、规则版本、内容版本、自动/手工来源及依据；不要只在前端保存一组显示名称。

分类任务读取保存后的定义版本。描述变化或用户纠正后，旧任务晚到不得覆盖新规则或手工决定；未分类、处理中、成功、失败和需更新显式区分。不同主题可以重叠，但不复制文章记录。

保留既有分类记录时做明确迁移；如果最终由新分类关系接管，则切换统计、筛选、导出等全部消费者，并移除旧字段的运行读取，不长期双写两套分类事实。迁移保留用户阅读状态，不能为了满足新格式丢弃旧资料。

同一内容/规则版本复用已有结果；是否回算存量由用户选择。复用应用已有任务与预算边界，不启动独立模型循环、第二个调度器或每分类一套执行进程。

后台任务不能只用“复用现有服务”一句话代替接通：普通采集完成后只提交新/变化条目的待整理工作，采集结果立即可用；整理单独记录状态，应用退出后能识别未完成项。任务键绑定文章内容版本、规则版本与判断方法版本；手工纠正是应用侧最终约束。

实施时先把一次受限语义判断接入当前 SDK provider 及任务生命周期，写出无模型配置、禁用自动处理、取消、重启、达到限额和失败不覆盖旧结果的行为测试，再接批量自动触发。禁止直接复制 [旧 headless 调用](../../../src/main/modules/content-study/headless-one-shot.ts) 或 RSS 分析中的专用请求路径作为新的后台调用旁路；它们的存在不能证明预算、协议和恢复已统一。遇到额度不足时暂停整理，不停止采集；未知计费结果不盲目重发。限额以可验证的调用/用量表示，价格未知时不伪造金额预算。

#### 自动整理的执行合同（2026-10-01）

以下合同先由 `rss-processing.test.ts` 验证，再接采集和界面；它们不表示已经完成。

- O1 采集保存与待整理记录在同一事务内提交。首次来源导入不登记；之后仅新增或内容变化才登记，重复刷新与已读/收藏不会重复调用。名称或描述编辑不回算历史。
- O2 每次判断绑定文章版本、最多 8 个定义及其规则版本、方法版本。同输入自动重复提交复用已有任务；用户选定文章才能显式重算。任务记录是执行状态和调用次数的唯一事实。
- O3 单次判断复用现有 SDK provider，零工具、单轮、无自动重试；有限输入明确标记所读片段及完整性。模型必须逐项返回属于/不属于/证据不足，引用必须来自本次提供的资料；格式错误不发布半份结果。
- O4 发送前先保存运行状态；每日限额按已开始的调用计算，失败与取消仍计入。未配置模型、自动处理关闭或达到限额时保持待处理，采集继续。默认每天最多 100 次，可修改；费用未知时只显示次数。
- O5 运行中取消、退出与重启均阻止晚到发布。重启发现运行记录时标为结果未知，不自动重发；重新尝试须显式请求。没有开始的任务可在下次启动或刷新时继续。
- O6 结果关系和成功终态同一事务提交；原文变化、定义变化/删除、文章删除或旧任务晚到时不得发布。自动写入只改派生判断，不覆盖人工属于/不属于。
- O7 整理是采集后的事件驱动工作，不新增轮询计时器、不借用用户聊天会话。复用现有串行分发能力及 SDK 执行边界，独立于已有文案/视觉分析产物；界面与 Agent 读取同一任务结果和限额状态。

### 5.4 查询与 Agent

事件扩展先按以下合同验证，再接界面和日报：

- E1 每篇一次入队只指定一个持久化的事件判断所有者，不以 UUID 排序、是否含精选或先执行的任务猜“首批”；分类与事件共用这次请求和现有限额。
- E2 候选在发送前从已保存资料读取，最多近期 20 个事件、每事件 3 个当前事实；实际候选 ID、事件版本、事实 ID 及提供依据的文章版本随任务保存。旧候选、外来 ID 或无原文摘句不能发布。
- E3 事件身份与事实身份分开：同事实多篇报道共享事实 ID，真正后续进展获得新的事实 ID。只因公司相同不归组；一篇涉及多个无法明确主次的事件时保留证据不足，不强合。
- E4 人工拆开、移入及合并原子保存，不修改原文/阅读/收藏；后续自动任务不能改回人工关联。事件成员变化使事件和工作区版本失效；删除原文清理关联，旧版本引用明确失效。
- E5 组卡分页在 Main 的完整匹配集合上执行，不能先取文章一页再由前端去重。范围内与全事件的成员数分清，筛选命中的成员不能因代表报道不匹配而消失；展开可读全部匹配成员。Agent 与导出保留完整文章范围。

以下仍是既定查询与 Agent 共同合同。

UI、Agent 与导出共同调用同一查询语义：定义版本、栏目/分类、来源、搜索、时间、已读/收藏、排序和分页。分页使用稳定顺序及可识别的数据版本，避免更新插入期间重复或漏读；返回总数与读取范围。

新增/扩展工具前先走通 Main 查询和 Preload/Renderer 类型，再接入现有工具注册、验证、权限和结果读取。已有 `rss_capture_session` 负责视图上下文，不继续膨胀成携带全库正文的大快照。

当前视图引用只标识正在看的范围；后台内容读取不依赖 RSS 页面是否挂载。引用某一篇文章不自动扩大到别的工作区或会话；信息可读不授予编辑、删除、付费获取或外部发送权限。

沿用当前应用级 RSS 资料库归属，不因本次改版另建按工作区复制的资料库。Agent 读取受现有会话和工具授权约束，远程消息不会因新工具而自动获得本机所有订阅。实际读工具从 Main 查询；只有“我正在看哪一栏”的界面上下文需要 Renderer，未挂载时明确返回没有当前 RSS 视图。

为 `rss` 资源建立只读工具地板，覆盖最终工具面收窄与显式技能并用场景；不能仅注册工具却在真实运行时被过滤掉，也不能借用文档编辑地板。新增字段须沿 Main → Preload → Renderer 类型/资源引用 → 工具返回贯通，至少做一次真实模型可调用面的读回验证。

该交接的机器合同：引用携带规范化的查询或文章读取参数及版本，正文不复制进提示；当前视图只在 RSS 可见且已确认查询一致时生成。引用经过附件保存/恢复、消息组装和 RequestEnvelope 后仍为只读 RSS 资源；文件名形状不得触发文档写入地板。SDK 选技过滤、文档收窄和最终模型工具面保留 RSS 只读地板，不补入刷新/分析/删除工具；`rss_read_reference` 通过本轮引用 ID 直接消费冻结的查询/文章参数，不让模型重拼条件和版本。普通 query/read 仍用于独立的新查询。包括 Tag Forge 同轮文件夹批处理在内，额外保留的仅为有资源依据的 RSS 读取工具，不放开通用文件写入。Main 仍按真实会话来源鉴权，远程伪造引用不能触及资料库。行为测试从正式 envelope、executor、SQLite 及本机合成 provider 请求验证这些边界。

工具须明确返回已读取的来源、范围、缺失与截断状态。刷新、分类任务与实际正文分别报告状态，不把“请求已提交”作为“结果已可读”。

导出分清两个明确动作：现有“全部资料/订阅列表导出”保留其范围；新增“导出当前结果”必须携带同一查询条件。不能把现有全量导出暗改成当前页，也不能把全量文件拿来冒充当前筛选结果。

### 5.5 数据更新、删除与迁移

- 点开文章成功进入阅读面后标记已读；纯查询和搜索不标记。收藏、手工分类等写入成功后以 Main 回读为准；失败恢复界面，不能一直显示并未保存的状态。
- 隐藏栏目、删除分类、移出收件箱与删除订阅源/清空底稿是不同操作。真正删除时沿用现有确认流程，取消关联处理中任务，清理新引入的正文、索引及分类关系，避免已删资料从缓存重现；不得扩大为删除用户已保存的笔记或既有分析产物。
- 迁移在事务中完成并保留已有用户状态；失败回滚不留下半迁移记录。用合成旧库验证正常迁移、失败中断与再次启动；完成后所有消费者一次切换，不保留两套分类权威。
- 在首次写入新结构前有可恢复备份；恢复步骤先停止应用再恢复同一份一致数据，不能只回退代码让旧版本读取不兼容的新结构。实际用户数据迁移前先在副本验证，不以删库重建解决失败。
