# 登录与微信连接进度闭环

enforce: true

## 完成合同

- OAuth 的并发授权复用同一次操作；Main 暴露精确操作身份与阶段。取消必须中止该操作并等清理结束；重新打开页面继续读取同一进度。仅凭据、服务、预设均完成才显示成功。
- OAuth 授权后的模型列表失败保留已获凭据，允许恢复；网络失败不得一概显示凭据失效。浏览器等待和交换凭据都有真实截止与中止信号。
- 微信重复开始不得排队重新绑定；初始化失败与二维码失效必须进入可重试终态。页面重开可恢复当前二维码。取消、停用后的迟到响应不能重新启用连接。
- 微信只有实际运行过的连接才发送退出通知，已经停止的连接不得因退出通知拖慢二维码。扫码网络错误、服务端过期与未知状态必须可见，不能伪装等待。
- 用户与助手消息之间的装饰线删除，消息和上下文边界保留。
- 远程设置的运行状态统计与工具描述列表，每次读取只解析各工具目录一次；不能按工具数量重复扫描整个技能目录。相邻读取仍必须反映工具新增、删除与描述更新，保持跨组重名拒绝，不新增持久缓存或改变模型授权面。行为围栏：`tool-gateway-registry.test.ts` 的 200 工具计数反例；安装版主进程采样及真实设置点击确认。

## 验证

先添加并运行失败反例，再改实现。覆盖 OAuth 并发、取消、保存前不报成功、模型加载失败恢复；微信启动失败、旧响应、停止重入、二维码过期和网络异常。运行 typecheck、OAuth 专项、verify:remote-im、verify:native、CSS gate 与 build。实际 Electron 检查登录状态、二维码、取消及页面重入；真实手机扫码属于独立账号验收，不用夹具冒充。
