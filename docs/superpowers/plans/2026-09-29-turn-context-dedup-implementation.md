# 本轮资源上下文与原生去重对齐

## 已验证事实

- 固定 Codex 0.149.0 会省略连续回合中键和值未变化的 additionalContext；application 与 untrusted 均如此。
- Ready 的资源/未完成输入校验只读取当前用户消息之前的上下文，不能从更早历史补猜授权。
- 因此静态资源引用和未完成输入跨轮重复时，会在本机被拒绝，尚未向上游提交。

## 本轮合同

1. 非空资源集作为一个 application 快照发送，使用稳定键 ready-resource-context，正文绑定 readyRunId 和完整 references；同一资源连续使用仍须重新发出，移除资源不继承旧引用。
2. 未完成输入继续使用 untrusted 通道，在既有负载中绑定本轮 readyRunId；生产者与网关必须使用同一构造函数。
3. 网关只接受当前请求所属的快照和尾项。错误 owner、重复快照、旧格式冒充当前快照及用户文本伪造必须拒绝，不允许跨历史搜索作为当前权限。
4. 历史旧资源标签只保留识别与隔离用途，不作为新回合的资源授权；已有消息不迁移、不重写。
5. 长期记忆、Retry 与工具授权沿用现有合同；不重发失败任务、不引入重试循环、不修改 native runtime。

## 验证

- 真实固定二进制经过本轮输入构造器：相同资源、资源减少、空资源、再次附加、版本变化、相同尾项连续使用，含失败与重启。
- 网关拒绝错误 owner、重复/伪造快照与不匹配尾项；资源顺序不影响既有摘要。
- 类型检查、相关 gateway/记忆隔离/输入测试、原生保存与恢复检查。
- 安装包来源、启动与实例核对；真实账号的失败记录和旧消息保持原样。
