# Ready Next 收束路线图

一个外壳，一种设计语言，一条信息流。

本文是总纲：说明问题出在哪、定了什么、分几条工作线、按什么顺序做、怎么算做完。每条工作线有自己的实施计划（W1–W7），新会话拿到一条工作线时，先读本文 §2–§4，再读那份计划。

- 证据：[全局盘点](../audits/2026-11-11-ready-next-coherence-audit/README.md)（七份代码盘点、外部调研、实机截图，下文用 O1–O16 指其中的实机观察）。
- 前序：[四项目整合计划](2026-10-30-ready-next-integration-implementation.md)（D1–D18、C1–C15、M0–M8）。本文不改它已交付的数据层决定，接手并展开它的 M8，并修改 D15 与 2026-10-31 的一条界面指示（见 E1）。

## 1. 问题出在哪

整合计划把四个拆出去的项目接回了 Ready，数据层接得很实：统一身份、统一引用、两个写入口、可重建的索引。但界面层只是把每个项目连同它自己的外壳一起放进了 Ready 的旧外壳里。用户感到的“半新半旧”“冗余”“串不起来”，是下面五个原因造成的。

| 编号 | 根因 | 表现 |
| --- | --- | --- |
| R1 | **外壳套外壳。** 每个模块带着自己的侧栏、顶栏、标签、命令面板、设置进来，外面还包着 Ready 0.8 的全局文件面板和助手面板 | 五栏并排，正文约占 36%（O1）；两棵树、两个搜索、两处反链、三个日历入口（O2、O4）；模式切换藏在助手面板里（O5）；窄窗口不可用（O10） |
| R2 | **没有一套被强制执行的设计系统。** 界面分三层：Ready 0.8 的旧外壳（系统字体、蓝色强调、液态玻璃），移植模块的外观（Inter、橘红、纸面），以及功能补丁留下的“脚手架界面”（没有设计，只有能用） | 七处字体声明、至少五套按钮、四套菜单、四套对话框、两套玻璃引擎、三种橘红（见 [a-design](../audits/2026-11-11-ready-next-coherence-audit/a-design.md)）；画板、数据库工具栏、斜杠菜单、日历关联区明显没做设计（O6–O9） |
| R3 | **信息模型已经定了，界面没有把它讲清楚。** 存储是文件（D1），界面想做成页面（D5），结果两种都摆出来 | 文件树与页面树并排（O2）；标题重复（O3）；“页面”在不同功能里范围不一致；数据库没有新建入口；索引以“重建索引”面板的样子露在外面（见 [c-document](../audits/2026-11-11-ready-next-coherence-audit/c-document.md)） |
| R4 | **资讯有引擎，没有筛子。** 能按用户写的标准归类、去重、出日报，但不按“对我有多重要”排序，不从阅读行为学习，不知道用户在忙什么，也不主动送达 | 默认视图是按时间排的全部动态；“精选”只是其中一栏；自动判断可能只看到 500 字摘要（见 [d-rss](../audits/2026-11-11-ready-next-coherence-audit/d-rss.md)） |
| R5 | **浏览器 Agent 工具很全，但被圈在“当前这一页”里。** 跨标签、下载没有对助手开放；鼠标操作要求网页在前台；被接管或被复核拒绝后不能接着做；运行所在的 Electron 版本已停止支持 | 多站点调研、带下载的任务、不打断用户的长流程都做不稳（见 [g-browser-agent](../audits/2026-11-11-ready-next-coherence-audit/g-browser-agent.md)、[h-external-landscape](../audits/2026-11-11-ready-next-coherence-audit/h-external-landscape.md)） |

## 2. Ready 是什么

后面所有取舍都从这一节来。

Ready 是一个人的信息工作台。它处理四种信息，由一个助手贯穿：

| 模式 | 这类信息的性质 | 用户在这里做什么 |
| --- | --- | --- |
| 浏览器 | 我去找的——外部世界 | 主动获取，也让助手替我去取 |
| 资讯 | 来找我的——订阅流，先过筛子 | 只看筛过的，值得的收下 |
| 文档（资料库） | 我留下的和我写出的——页面、数据库、画板、书 | 沉淀、整理、创作 |
| 日历 | 时间——什么时候 | 安排，回看 |
| 助手 | 在任何一处都能叫到 | 问、改、代办 |
| 今日 | 四种信息在此刻的交汇 | 打开 Ready 先看这一页 |

“心流”在这里有五条可以检查的含义：

1. **内容优先。** 屏幕的大部分属于正在看或正在写的东西。
2. **两步到达。** 任何对象，`⌘K` 加回车就能打开。
3. **一步收下。** 在任何地方看到值得留的内容，一个动作就进暂存或资料库，不用先切走。
4. **不离开就能看一眼、问一句。** 速览和助手都不打断当前位置。
5. **回得去。** 跳到别处之后，能原路回到刚才的位置。

## 3. 已定的决定 E1–E12

E1、E2、E7 的送达范围、E8 的任务范围由用户在 2026-11-11 确认；其余由本文给出。除非用户另行指示，后续会话不再重议。

| 编号 | 决定 | 约束与说明 |
| --- | --- | --- |
| E1 | **一个外壳，一个侧栏** | 布局固定为：图标栏、侧栏、内容、助手。侧栏的内容随模式切换（浏览器是标签与收藏，文档是页面树或文件树，资讯是栏目，日历是月历与图层）。全局文件面板并入文档侧栏的“文件”视角。**这替代 2026-10-31“外层保留 Ready 0.8 文件管理”的指示，并提前执行 D15 的“最后统一外壳”。** 见 W2 |
| E2 | **一套视觉身份：一块玻璃，几张纸，一个信号色** | 整个窗口是一块磨砂玻璃，导航和工具长在玻璃上，不再切成一张张玻璃卡片；内容是放在玻璃上的纸。橘红 `#ff5a1f` 是唯一强调色。保留明暗两个主题。四种强调色、四套皮肤退役，只留一个“减少透明”开关。外框上下留白对称，品牌红点留在窗口右上角，助手输入框用液态玻璃（用户看过基准页后补充）。见 W1 |
| E3 | **信息模型：文件是正本，对象是界面，索引是底座** | 资料库里，用户面对的是页面、数据库、画板、书，不必关心文件在哪；资料库之外挂载的文件夹，如实当文件看。一棵树，两种视角。索引不作为界面出现。见 W3 |
| E4 | **模式仍然只有四个** | `browser | document | rss | calendar` 不变。“今日”是文档模式里的系统标签页（现有主页的升级），不是第五个模式 |
| E5 | **模式切换归图标栏，助手面板只做助手** | 助手面板可以收起；空间不足时改为浮在内容上方，不挤压内容 |
| E6 | **`⌘K` 是唯一的全局搜索与命令入口** | 模块自带的命令面板并入；全局搜索面板的“查找替换”改为文档模式里的结果页 |
| E7 | **资讯默认给“筛过的”** | 筛子由三样东西决定排序：用户写的标准、用户的阅读行为、用户手头在做的事。送达三处：今日页、每日日报、系统通知（只限“必须马上知道”）。不做微信、飞书推送。见 W5 |
| E8 | **浏览器 Agent 继续用 Ready 自己的工具栈** | Codex 原生浏览器没有给第三方宿主的接口（见 [h-external-landscape](../audits/2026-11-11-ready-next-coherence-audit/h-external-landscape.md) §1）。四类任务都要做稳：多站点调研、登录后的站内操作、下载与文件处理、不打断用户的长流程。见 W7 |
| E9 | **升级 Electron 到受支持的版本线** | Electron 42 已于 2026-10-20 停止支持，对一个内嵌浏览器的产品是安全问题，也是 WebMCP 的前提。先做评估，评估通过即执行，并且放在最前面做（B0），让后面所有批次的真实窗口验收都跑在最终的运行时上。用户已于 2026-11-11 授权，不再另行确认；执行时同步 `CLAUDE.md` 与 `AGENTS.md` §1 的技术基线。见 W7 与 §9 |
| E10 | **界面由 Claude 亲自做，并在真实窗口验收** | 沿用既有约定：视觉、交互、动效不交给 Codex；Codex 做数据、IPC、测试、脚本。没有真实窗口截图的界面改动不算完成 |
| E11 | **不留旧路径** | 被替换的面板、皮肤、令牌、命令面板，在替换它的那一批里删除。需要迁移的用户设置做一次性迁移。这是架构红线 3 |
| E12 | **既有合同继续有效** | Agent 生产主链、BrowserView 让位与恢复、Widget 安全边界、数据隔离（C15）、两个写入口（D4）、文件为正本（D1）都不变。本路线图改的是界面与产品流，不是这些底座 |

## 5. 每个会话怎么做

1. **先读。** 根 `CLAUDE.md`、本文 §2–§4、对应的实施计划、[盘点](../audits/2026-11-11-ready-next-coherence-audit/README.md) 里对应的那一份。涉及 Agent、Browser、文档、Widget 行为时读 [当前运行时合同](../../architecture/current-runtime-contracts.md) 的对应章节。
2. **重新定位证据。** 计划里的 `路径:行号` 是 2026-11-11 的快照。动手前在当前代码里重新找到它，找不到就按现状调整做法，并在计划的“交付状态”里记一笔。
3. **先写合同，再写实现。** 每个任务列了“验收”。能写成测试或脚本的先落成会失败的用例。
4. **分工。** 界面、样式、交互、动效自己做。数据、IPC、迁移、测试、脚本可以按 `~/.claude/CLAUDE.md` 的写法派给 Codex，派之前写清范围和不许做的事，回来后审 diff、自己重跑检查。
5. **在真实窗口里验收。** `npx electron-vite build` 之后用隔离 profile 跑对应的窗口脚本，并亲眼看截图。命令行通过不等于界面通过（整合计划里十几次真实窗口才发现的缺陷都记在它的 §8）。只用隔离数据，不碰 `~/Library/Application Support/Ready`。窗口一律隐藏启动（`READY_START_HIDDEN=1`，不 show、不 focus），用户会同时在这台机器上工作；需要可见窗口的检查（玻璃质感、原生网页层）攒在一起，先问用户方便的时间再做。
6. **收尾。** `npm run typecheck`；按改动范围跑 §6 的检查；净增行数的代码文件查总行数，超过 1000 行登记 [大文件台账](../../code-health/large-file-health-log.md)；在实施计划末尾的“交付状态”写清做了什么、证据、没做的和原因。提交与合并按用户当次的指示。
7. **发现计划错了就改计划。** 事实与计划不符时，以事实为准，把改动和理由写进计划，不要绕过去。

## 7. 不做的事

- 不新增第五个模式，不把资讯改名，不引入云端协作或第二套正文存储。
- 不恢复旧 Agent 主链、Dynamic Delivery、Agent 定时任务、专项人格。
- 不为“以后可能要”保留皮肤、强调色、旧面板的开关或兼容分支。
- 不把外部浏览器自动化 MCP（chrome-devtools-mcp、playwright-mcp 等）接到 Ready 自己的网页上：那会绕过标签所有权、行动确认和证据复核。
- 不在没有评测数据的情况下引入向量检索（见 W3 的 M9）。
- 不在本路线图内迁移日常 Ready 数据；那仍需单独授权。

## 9. 原待定事项的决定

这四件事原本留给用户。用户在 2026-11-11 交给本路线图决定，结论如下，不再另行询问。

| 事项 | 决定 | 理由 | 落在 |
| --- | --- | --- | --- |
| Electron 升级 | **做，评估通过即执行，并且尽早做。** 目标是执行时最新的受支持稳定大版本（至少已有一个补丁版本）。放在最前面的 B0，独立 worktree；评估不通过就留在 42，记录阻塞点，其他工作线照常 | 内嵌浏览器运行在不再有安全更新的 Chromium 上，是这份路线图里唯一的安全问题，不该排到最后。越早升，后面每一批的真实窗口验收和截图基线就都建立在最终的运行时上，不用到结尾重验一遍 | W7 §4.9、T1、T11 |
| 链接预览与代理的 fake-IP 网段 | **放行，但只在确认本机处于 fake-IP 代理下时。** 条件：目标是域名、解析结果落在 198.18.0.0/15，且一个固定的对照域名也解析进这个网段。IP 字面量、其他私网段、不在这种环境下时照旧拦截。不加设置项 | 在这类代理下所有域名都被解析进这个网段，现在的拦截让每一张链接卡都失败（O16），功能等于不可用。这个网段是保留给测试的，正常网络里公开域名不会解析到它；加上“对照域名也在其中”这一条，放行的就只是代理环境，防内网请求的作用没有丢 | W4 §2.4、T6 |
| 筛子参考“手头在做的事” | **不预设开或关，首次进入资讯时问一次。** 回答之前按关闭处理，一个字也不发。开启后，页面标题、日程标题、在读的书三类来源可以分别关掉 | 这份清单会发给模型服务商。它是筛子最有价值的输入，但不该在用户不知情时发出；埋在设置里默认关闭又会让大多数人永远用不上。在最相关的时刻、看着实际清单做一次选择，两头都顾到 | W5 §3、V6 |
| 向量检索 | **评测不达标就做，方案现在定死。** 触发条件：检索评测的第二类或第三类低于 70%。做法：本地嵌入模型，按需下载、不进安装包；派生索引，可重建；与全文检索的结果融合。资料库内容不上传。验收：同一评测集第二、三类不低于 85%，第一类不退步 | 先量再建的原则不变，但把“不达标怎么办”提前定好，免得到时候再停下来问。只做本地，是因为把整个资料库发给服务商做嵌入，隐私和费用都不合适 | W3 的 M9、§5、T9 |
