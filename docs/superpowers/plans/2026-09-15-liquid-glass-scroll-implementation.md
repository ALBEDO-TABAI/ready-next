# 聊天玻璃滚动与质感修正

## 范围与可执行合同

保留透明窗口、单一实时投影、合并遮罩和浮层实测留白。修正共享投影组件，覆盖输入框、模式胶囊及浮动菜单。验收以真实 Electron 开发窗口为准，隔离资料目录，不使用真实会话或调用模型。

先由 `src/__tests__/liquid-backdrop-projection.test.tsx` 固定行为：

1. 滚动立即同步既有投影的位置，不克隆内容、不重建遮罩。
2. 逐字文本沿既有节点位置更新；新增内容、子节点样式和外部根样式变化仍更新。组件自己的遮罩写入不能形成更新循环。
3. 尺寸及浮层高度变化只更新几何；多个玻璃面各自释放孔洞，最后卸载恢复原遮罩。

## 验证

- 相同长度聊天、相同滚动轨迹，记录修改前后的帧间隔、长任务及完整克隆次数。
- 真实工作台验证浅色、深色、窄面板、输入增高、浮动菜单、末条消息和滚动后内容更新。
- 质感调整只修改本区域的光学参数和材质样式；不增加外部暗影、静态贴图或不透明底板。既有折射图与输入行为检查继续通过。
- `typecheck`、投影行为测试、相关玻璃及输入回归、CSS 层检查、`git diff --check`。

## 结果

### 原因与处理

安装版 0.8.0 与工作树都有相同问题：输入框、模式胶囊以及浮层共用的投影组件，在每次滚动时重新克隆整个聊天树、清理属性、替换投影、设置滚动位置并重写合并遮罩。两个常驻玻璃面会重复这份工作。文本逐字更新也走全量复制，造成同源卡顿。原生窗口模糊限制仍然存在，故保留实时投影与遮罩架构。

滚动改为在 scroll 回调中同步保留的投影位置；纯文本更新沿当前树的节点位置写入，结构/样式变动仍在下一帧重建快照。观察源样式时排除投影自管的 mask，避免多个玻璃面互相触发复制。本次基线未复现持续的静止自循环，不能把该风险写成已发生的根因。额外核对了来源替换、菜单孔洞释放，以及输入框增高时只移动不变高的模式胶囊。

质感只调整生产输入框：dome 从 5 收至 2、strength 从 6.4 收至 3.2；保留 squircle、bevel 22、depth 37、无色散与原 SVG 重绑机制。投影层 blur 从 3.5px 至 4.5px，移除投影整体放大，降低底色/局部白雾并收敛为一层轻渐变；沿用已有边缘高光。未增加外部暗影、不透明底板或截图纹理。深色基调与操作按钮语义保持原样。

### 实测

真实 Electron 42.3.0 / Chromium 148.0.7778.180，1440×900、DPR 2，100 条本地夹具消息、1856 个来源元素、两个常驻玻璃面；每段采样 3 秒。表内为 rAF 回调间隔，证明页面更新负担变化，不冒充屏幕实际呈现帧率。

| 场景 | 修改前平均 / P95 | 修改后平均 / P95 | 完整克隆次数 |
| --- | --- | --- | --- |
| 相同长聊天滚动 | 25.10 / 37.50 ms | 8.27 / 11.70 ms | 230 → 0 |
| 每 50ms 更新文本并滚动 | 24.27 / 50.00 ms | 8.24 / 10.70 ms | 114 → 0 |

第二行的“修改前”已经含滚动复用修正，用于单独验证逐字更新缺口；它不是原始版本的完整对照。独立的滚动修正采样为 8.56 / 14.70ms，0 次克隆。最终采样仍有一次 50ms 长任务，未宣称所有页面卡顿归零。更复杂消息结构仍需在结构变化时重建，未增加通用 DOM 差分系统。

- 26 项对应测试全部通过，无跳过；包含新投影行为、折射图、生产输入框、授权菜单、历史菜单和原玻璃回归。
- `npm run typecheck`、CSS 层检查和 `git diff --check` 通过；净增代码文件均小于 1000 行。
- 真实窗口检查浅/深色、320/580px 面板、多行输入、授权菜单开关、实际上下滚动。最后消息高于浮层，留白随浮层实测高度变化；菜单打开/关闭后遮罩孔洞为 3/2，投影滚动位置与来源相同。
- 在独立资料目录运行，无真实模型请求，未修改用户会话。安装版仅核对实现，未替换或重启。
