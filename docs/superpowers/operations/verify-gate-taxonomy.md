## Buckets

- **merge** — must pass before every PR merge. Either part of top-level
  `npm run verify` (the slim merge chain) or a declared W1 expansion target.
- **manual-deep** — opt-in deep diagnostic chains (`verify:a0`..`verify:t` and
  domain-specific suites such as `verify:calendar`). Run before release
  branches or big refactors; **not** PR-gating.
- **release-only** — only run when cutting a release artifact. Includes native
  rebuild verification and cloud sign-off.
- **debt-dashboard** — tracks debt growth without blocking merge. Fails only on
  regression past the recorded ceiling.
- **archive** — historical, dev convenience, or superseded; not run by anyone
  routinely and not part of any gating chain. Candidates for removal in a
  later cleanup pass.

## Proposed renames / removals (W6.4 — documentation only, no PR action)

Per W6.4, this PR is documentation-only; the following candidates are recorded
for future cleanup PRs and **not** applied here:

1. **`verify:i` → consider removal.**
   It is a literal alias to `verify:i1` (`"verify:i": "npm run verify:i1"`).
   Either remove the alias (callers update to `verify:i1`) or document it as
   the canonical name and remove `verify:i1`. Either way, one of the two
   should disappear in a follow-up.

2. **`typecheck:clean` → consider rename or removal.**
   Currently `rm -rf node_modules/.cache/tsc`. Not a verification gate; the
   `^typecheck` prefix puts it in the inventory regex. Either rename (e.g.,
   `cache:clean:typecheck`) so it drops out of the verify-family inventory,
   or remove if no scripted callers exist.

3. **`lint` → consider rename.**
   `lint` runs `eslint --fix`, which mutates source. The verb-without-suffix
   reads like the gate, but `lint:check` is the actual gate. Rename to
   `lint:fix` for consistency with `lint:check` and to remove the inventory
   ambiguity.

4. **`test:i:gates` / `test:i:focus` → consider removal.**
   After the W-era simplification of `verify:i` to a pure alias, these scripts
   are no longer invoked by any `verify:*` chain. They duplicate work already
   covered by `test:i1:gates` plus `check-silent-catch.cjs` in `verify:e`.

Each rename / removal would land in a separate small PR with the rationale
linked here.
