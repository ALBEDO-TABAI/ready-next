# Ready Agent 综合验收测试清单

> 适用范围：人工验收 Ready 中 agent 对文档、图表、skill、浏览器、RSS、日历等模块的真实使用能力。
> 核心原则：测试的目标不是证明某个固定脚本能跑，而是证明 agent 能理解用户意图、选择合适能力、完成可观察的真实结果。

## 0. 完成标准

本轮测试只有同时满足以下条件，才算完成：

- 所有 P0 测试项通过；P1 测试项若未通过，必须记录原因、复现输入和影响范围。
- 每个通过的测试都保留最终产物，方便后续查看实际效果、数据留存、性能和异常情况。
- 每个测试都能看到 agent 的真实判断过程：理解需求、必要时规划、调用合适能力、检查结果并收尾。
- 发布前必须由 Codex 以模拟人类用户方式逐项操作 A1-M8，并在 Stage Z 证据目录留下每项通过记录；自动测试通过不能替代这份操作记录。
- 没有出现通过硬编码关键词、固定死规则或僵硬脚本绕过 agent 判断的迹象。
- 没有出现任务完成后内容错乱、数据丢失、重复写入、明显卡顿、异常膨胀或无法再次打开的问题。
- 出现不确定信息时，agent 会主动澄清；出现冲突或高风险操作时，agent 会先询问用户意图。

## 1. 全局必须要求

这些要求适用于所有测试项。任意一项违反，当前测试直接判为失败。

### G1. 禁止硬编码和死规则路由

测试目的：确认 agent 不是靠固定关键词、固定脚本或单一路径假装完成任务。

必须满足：

- agent 能根据用户自然语言判断目标，而不是只识别几个固定词。
- 同一个需求换一种说法，agent 仍能选择正确能力。
- agent 不应把复杂任务直接塞给一个固定脚本，然后不看结果、不做判断。
- agent 可以使用工具、脚本或模块能力，但必须根据任务语境决定何时用、怎么用、用完后如何验证。

失败信号：

- 只有命中固定短语才工作，换一种自然表达就失效。
- 明显不同的任务被路由到同一个固定流程，结果不贴合用户要求。
- 工具输出明显错误，agent 仍直接宣称完成。
- agent 没有读取输入材料，却生成看似合理但不可追溯的内容。

### G2. 意图理解优先

测试目的：确认 agent 能先判断用户到底想完成什么，再决定调用哪个模块。

必须满足：

- 能区分“阅读文档”“编辑文档”“制作图表”“查实时信息”“管理日程”“运行 skill”等不同意图。
- 同一条用户请求涉及多个步骤时，能拆分顺序并逐步执行。
- 目标、来源、输出位置不清楚时，能问最少但关键的问题。
- 不因当前页面、最近上下文或附件噪声，把任务误判到错误模块。

### G3. 结果必须可观察

测试目的：避免“口头说完成”，但用户看不到实际结果。

必须满足：

- 文档类测试必须留下可打开的文档或文档更新。
- 图表类测试必须留下可视化结果，且标题、数据、图例或说明可读。
- skill 类测试必须留下最终输出、运行状态或产物入口。
- 浏览器类测试必须留下可核验的信息来源、结论或整理结果。
- RSS 与日历类测试必须能在对应模块中看到变更结果。

### G4. 质量必须过关

测试目的：确认结果不仅“有”，而且可用。

必须满足：

- 内容与用户输入一致，不虚构关键事实。
- 文字表达清楚，结构自然，版式可读。
- 图文穿插不遮挡、不重叠、不破坏原文。
- 图表类型与数据含义匹配。
- 人物关系图、信息卡或其他可视化结构能被普通用户看懂。

### G5. 全程稳定

测试目的：确认任务不会半路中断、卡死或污染数据。

必须满足：

- 长任务中途有进度或状态反馈。
- 任务完成后应用仍可继续使用。
- 不出现明显循环调用、重复创建同一产物、重复刷新或重复写入。
- 任务完成后重启应用，关键结果仍可打开。
- 不出现异常体积膨胀，例如一个普通测试生成大量无关文件或巨大数据。

### G6. 产物保留

测试目的：便于观察真实完成效果和后续问题。

必须满足：

- 测试通过后，不自动清理最终文档、图表、RSS 订阅、日历项或 skill 输出。
- 每个产物建议用测试编号命名，例如 `A1-人物关系图`、`B2-多图表报告`。
- 需要回滚的测试应先截图或导出记录，再由测试人员手动清理。
- 失败测试也要尽量保留失败现场，除非它会继续影响后续测试。

## 2. 测试记录模板

每个测试建议记录以下信息：

| 字段 | 内容 |
|---|---|
| 测试编号 | 例如 A1 / B2 / C3 |
| 用户输入 | 原始自然语言指令 |
| 输入材料 | 文档、数据、网页、RSS 源、日历上下文等 |
| agent 行为摘要 | agent 如何理解、是否提问、调用了哪些能力类别 |
| 最终产物 | 文档名、图表名、skill 输出、RSS 订阅、日历项等 |
| 通过结果 | 通过 / 失败 / 阻塞 |
| 问题记录 | 卡顿、错乱、幻觉、重复、体积异常、交互不自然等 |

## 3. 测试目录

### A. 文档阅读与人物关系图

测试目的：验证 agent 能读取指定文档内容，理解章节范围，提炼人物和关系，并把结果写入目标文档或新文档。

准备材料：

- 一个包含《白痴》前 3 章内容的文档。
- 一个空白目标文档，或允许 agent 新建文档。

#### A1. 从指定章节生成人物关系图

用户输入示例：

> 看一下《白痴》这个文档前 3 章，帮我梳理里面出现的人物关系，在一个新文档里做成人物关系图，最好能用信息卡或类似形式表现。

测试内容：

- agent 找到正确文档。
- agent 只分析前 3 章，不越界泛读整本书。
- agent 提取人物、关系、关系依据和不确定点。
- agent 在新文档中创建人物关系图或信息卡式可视化。
- agent 在图后附上简短说明，解释关系来源。

通过标准：

- 人物名单与前 3 章内容一致，核心人物没有明显遗漏。
- 关系描述能回到文本依据，不凭空编造后续剧情。
- 图或信息卡布局清楚，人物、关系线、分组或说明可读。
- 新文档能正常打开，内容没有错位、遮挡或空白区域异常。
- agent 完成后会检查输出，并说明产物位置。

保留产物：

- 新建的人物关系图文档。
- 如果生成了信息卡或图表组件，也保留组件本体。

#### A2. 写入已有目标文档

用户输入示例：

> 把《白痴》前 3 章的人物关系整理到我当前打开的读书笔记里，放在“人物关系”这一节下面。

测试内容：

- agent 正确识别来源文档和目标文档。
- agent 找到或创建“人物关系”小节。
- agent 不覆盖目标文档中已有内容。

通过标准：

- 新内容插入位置正确。
- 原有笔记保留完整。
- 关系图或列表与目标文档风格基本协调。

保留产物：

- 修改后的读书笔记。

#### A3. 章节范围模糊时的澄清

用户输入示例：

> 帮我看一下前几章，整理人物关系。

测试内容：

- 当前上下文无法确定“哪个文档”和“几章”时，agent 主动问清。
- 如果当前文档明确，agent 可使用当前文档，但仍应确认“前几章”的范围。

通过标准：

- agent 不擅自选择错误文档。
- agent 的问题简短、必要，不把用户拖进多轮无效确认。

保留产物：

- 澄清后的最终文档或测试对话记录。

### B. 数据驱动的文档图表制作

测试目的：验证 agent 能理解用户给的数据，选择合适图表，并把图表放入文档中形成可读报告。

准备材料：

- 使用下面的预设数据，不需要测试人员临时再编。
- 测试时可以直接复制整组数据给 agent，也可以把数据先放进一个文档再让 agent 读取。

预设数据 B-Data-1：渠道销售额，单位为万元。

| 渠道 | 销售额 |
|---|---:|
| 搜索广告 | 128 |
| 社交广告 | 96 |
| 内容种草 | 74 |
| 自然流量 | 112 |
| 老客复购 | 153 |
| 线下活动 | 41 |

判读锚点：

- 最高渠道应为老客复购，最低渠道应为线下活动。
- 适合柱状图或条形图，不适合折线图。
- 结论中可以提到复购贡献突出、线下活动短期销售弱，但不能把“线下活动无价值”当作确定结论。

预设数据 B-Data-2：月活用户，单位为万人。

| 月份 | 月活用户 |
|---|---:|
| 2025-07 | 18.4 |
| 2025-08 | 19.1 |
| 2025-09 | 20.8 |
| 2025-10 | 21.6 |
| 2025-11 | 23.9 |
| 2025-12 | 27.4 |
| 2026-01 | 25.8 |
| 2026-02 | 26.6 |
| 2026-03 | 29.2 |
| 2026-04 | 31.5 |

判读锚点：

- 整体趋势上升，但 2026-01 比 2025-12 回落。
- 适合折线图。
- 结论不能写成“每个月都增长”。

预设数据 B-Data-3：年度预算构成，单位为百分比。

| 项目 | 占比 |
|---|---:|
| 研发 | 38 |
| 市场 | 26 |
| 内容 | 16 |
| 客服 | 9 |
| 运营工具 | 7 |
| 预备金 | 4 |

判读锚点：

- 总和应为 100%。
- 适合饼图、环图或占比条。
- 研发和市场合计为 64%，应是主要投入方向。

预设数据 B-Data-4：产品经营对比，金额单位为万元。

| 产品 | 收入 | 成本 | 毛利 | 次月留存率 |
|---|---:|---:|---:|---:|
| 产品 A | 86 | 42 | 44 | 67% |
| 产品 B | 63 | 39 | 24 | 52% |
| 产品 C | 104 | 61 | 43 | 58% |
| 产品 D | 48 | 20 | 28 | 71% |

判读锚点：

- 产品 C 收入最高，但毛利略低于产品 A。
- 产品 D 收入最低，但留存率最高。
- 适合组合柱状图、对比表或“收入/毛利 + 留存”组合表达。

预设数据 B-Data-5：口径不一致和缺失值数据。

| 月份 | 销售额 | 单位 | 订单数 | 备注 |
|---|---:|---|---:|---|
| 2026-01 | 120000 | 元 | 820 | 正常 |
| 2026-02 | 13.5 | 万元 | 910 | 正常 |
| 2026-03 |  | 万元 | 980 | 销售额缺失 |
| 2026-04 | 16.2 | 万元 |  | 订单数缺失 |
| 2026-05 | 178000 | 元 | 1100 | 正常 |
| 2026-06 | 19.1 | 万元 | 1210 | 正常 |

判读锚点：

- agent 应把元统一换算为万元：120000 元 = 12 万元，178000 元 = 17.8 万元。
- 2026-03 的销售额缺失，不能凭空补成趋势值。
- 2026-04 的订单数缺失，不能在订单趋势图里伪造。

#### B1. 单组数据生成合适图表

用户输入示例：

> 根据 B-Data-1 这组渠道销售数据，在文档里做一个清楚的图表，并写一段结论。

测试内容：

- agent 判断适合柱状图、条形图或其他图表。
- agent 把数据、图表和结论放入文档。

通过标准：

- 图表类型合理。
- 数据数值没有丢失、调换或单位错误。
- 标题、坐标、图例或标签清楚。
- 结论能从图表数据推出。

保留产物：

- 包含图表和结论的文档。

#### B2. 多组数据生成多类型图表

用户输入示例：

> 我给你 B-Data-1 到 B-Data-4 这批运营数据，帮我做成一个小报告：趋势用折线图，占比用饼图或环图，渠道对比用柱状图，产品经营做对比图或对比表，最后加一个总结。

测试内容：

- agent 区分不同数据类型。
- agent 为不同数据选择不同图表。
- agent 组织成一份完整文档，而不是散落的图。

通过标准：

- 至少包含 3 种匹配数据含义的图表。
- 每张图都有明确标题和必要说明。
- 报告结构清楚，有开头、图表区和总结。
- 图表之间没有版式冲突或遮挡。
- 总结能写出“产品 C 收入最高但毛利不是最高”“月活整体上升但 2026-01 回落”等关键事实。

保留产物：

- 多图表报告文档。

#### B3. 数据不完整或口径不一致

用户输入示例：

> 用 B-Data-5 做图，不过有些月份没填，有些是万元有些是元，你自己处理一下。

测试内容：

- agent 识别缺失值和单位不一致。
- 需要业务判断时主动确认；能安全转换时说明转换方式。
- 不把缺失值编造成确定数据。

通过标准：

- 缺失值处理清楚标注。
- 单位统一正确。
- 图表没有误导性表达。
- agent 没有为了完成图表而伪造数据。
- 最终图表应能看出 2026-05 销售额是 17.8 万元，而不是 178000 万元。

保留产物：

- 修正后的数据说明和图表文档。

### C. Skill 长短任务运行

测试目的：验证短 skill、中等 skill 和长 skill 都能被正确识别、启动、执行、反馈进度和收尾。

准备材料：

- 一个短任务 skill：几秒到一分钟内完成，输出文本或小文件。
- 一个中等任务 skill：需要读取材料、生成中间产物，再汇总输出。
- 一个长任务 skill：运行时间较长，可能需要持续进度、暂停、恢复或后台执行。

#### C1. 短 skill 正常完成

用户输入示例：

> 用对应的 skill 帮我分析这段内容，输出一个简短结论。

测试内容：

- agent 判断这是 skill 任务。
- agent 调用正确 skill。
- agent 返回结果并说明产物。

通过标准：

- skill 能启动并完成。
- 输出符合用户目标。
- 没有多余确认、绕路或重复执行。

保留产物：

- skill 输出文本或文件。

#### C2. 中等 skill 产出中间文件和最终结果

用户输入示例：

> 用这个分析 skill 处理这份材料，保留中间结果，最后给我一份总结。

测试内容：

- agent 能把输入材料交给 skill。
- 中间结果和最终结果都能被保存。
- agent 能读懂 skill 结果并做简短收尾。

通过标准：

- 中间产物完整可打开。
- 最终总结引用了真实产物，不是另起炉灶。
- 任务完成后状态显示正确。

保留产物：

- 中间文件。
- 最终总结。

#### C3. 长 skill 不被中断

用户输入示例：

> 运行这个长分析任务，过程中不用一直问我，完成后把结果保留下来。

测试内容：

- 长任务能进入运行状态。
- 中途有进度或阶段反馈。
- 到达预算、后台或暂停状态时，agent 能正确续跑或提示。
- 完成后产物可打开。

通过标准：

- 不出现无故中断。
- 不把“后台运行”“预算暂停”误报为完成。
- 继续执行时能接上已有进度，不重新从头跑。
- 失败时说明可操作原因，而不是泛泛报错。

保留产物：

- 长任务输出目录或最终文件。
- 运行状态记录。

#### C4. skill 缺少必要配置

用户输入示例：

> 运行这个需要外部配置的 skill。

测试内容：

- 缺配置时，agent 能识别阻塞点。
- agent 只询问真正必要的信息。
- agent 不假装已经完成。

通过标准：

- 缺什么说清楚。
- 用户补充后能继续。
- 用户不补充时，任务状态应为等待或阻塞，而不是成功。

保留产物：

- 阻塞记录或补充配置后的最终产物。

### D. 浏览器使用能力

测试目的：验证 agent 能根据不同浏览需求制定高效计划，准确查找、核验、整理结果。

全局通过标准：

- agent 不绕圈，不打开大量无关页面。
- 对实时信息会主动获取最新来源。
- 对事实内容会给出来源或依据。
- 对复杂研究会先规划，再分层查证。
- 页面加载失败、来源冲突或信息不足时，会换路径或说明限制。

#### D1. 查图

用户输入示例：

> 帮我找几张适合做“城市夜跑活动海报”的参考图，要真实照片风格。

测试内容：

- agent 理解图片风格和用途。
- agent 查找图片并筛选。
- agent 不把无关插画或纯氛围图当成结果。

通过标准：

- 返回图片与用途匹配。
- 每张图有来源或可追踪入口。
- 图片质量、内容和版权风险有基本判断。

保留产物：

- 图片结果列表或插入到测试文档中的参考图。

#### D2. 查文本事实

用户输入示例：

> 查一下某家公司现在的 CEO、总部和主要产品，给我一个简短资料卡。

测试内容：

- agent 使用当前可靠来源。
- agent 区分官网、新闻、百科等来源的可信度。

通过标准：

- 信息准确，来源可核验。
- 如果来源冲突，明确说明并选择更可靠来源。
- 输出简洁成卡片形式。

保留产物：

- 资料卡或测试记录。

#### D3. 查实时新闻

## 4. 测试后检查

每一轮测试完成后，统一做以下检查。

### P1. 产物复查

- 所有产物能重新打开。
- 文档内容没有乱码、空白、遮挡或异常重复。
- 图表、信息卡、关系图仍能正常显示。
- 日历、RSS 变更仍然存在。
- skill 输出没有被自动清理。

### P2. 数据留存检查

- 关闭并重启应用后，测试产物仍可见。
- 不同测试产物没有互相覆盖。
- 未通过测试的残留状态不会影响后续测试。

### P3. 性能与体积检查

- 测试过程中没有长时间无反馈卡死。
- 普通文档和图表任务没有生成异常巨大的文件。
- RSS 刷新没有制造大量重复文章。
- 长 skill 没有无限制堆积临时文件。

### P4. 交互质量检查

- agent 提问数量合理，不把可以自己判断的问题都丢给用户。
- 需要用户决定的地方，agent 没有擅自操作。
- agent 的最终说明简单清楚，能让用户知道结果在哪里、是否完成。

## 5. 建议执行顺序

1. 先跑 A、B、E，确认文档和图表主链路稳定。
2. 再跑 D，确认浏览器实时查询和调研能力稳定。
3. 再跑 C，确认短、中、长 skill 都能完成。
4. 再跑 F、G，确认 RSS 和日历的增删改查稳定。
5. 再跑 I、K，确认地图路线和文件搜索索引这两个基础能力稳定。
6. 再跑 L，确认文件树拖拽菜单四个快捷动作稳定。
7. 再按 M1-M8 顺序跑 4 个 YouTube 链接的双分析器测试，禁止并行。
8. 最后跑 H、J，验证跨模块组合任务；优先跑 H1-H5，再跑 H6-H7 和 J1-J6。

## 7. 一票否决项

出现以下任一情况，即使部分结果看起来正确，也不能算通过：

- agent 未读取或未使用用户给定材料，却生成最终结果。
- agent 明显通过固定脚本或固定关键词绕过真实意图判断。
- agent 擅自删除、覆盖或移动用户未指定的内容。
- agent 把实时问题当成离线常识回答，且没有获取最新信息。
- agent 把冲突日程直接创建进去，没有提醒用户。
- 长 skill 中断后无法恢复，却宣称完成。
- 测试通过后产物不可打开、不可追踪或被自动清理。
- 应用出现明显卡死、白屏、数据异常膨胀或后续模块无法使用。
