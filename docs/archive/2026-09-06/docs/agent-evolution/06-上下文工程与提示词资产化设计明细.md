# 设计明细 06：上下文工程与提示词资产化

> 系列：docs/agent-evolution/（00 为路线图总览，08 为缺陷追踪）
> 解决缺陷：P5（预算突兀耗尽）、P6（当天摘要污染，残余部分）、D-ctx1（当天摘要纯手动无自动生成）、D-ctx2（提示词/提醒文案硬编码、与代码耦合、无版本无法 A/B）、D-ctx3（注入量无观测）
> 来源：Matrix 调研 01 篇（上下文注入规格）/05 篇（token 经济纪律、seedVersion）+ ready 现状（prompt-assembly L0/L1/L2、system-reminder 注册表、daily-memory-scope-filter、run-budget-policy 取证）

## 1. 总原则

Matrix 的上下文工程铁律："摘要进上下文，全文按需读；索引是检索线索不是知识本身；token 经济是一等规则写进提示词，不靠模型自觉。" ready 的 L0/L1/L2 预算框架是好底子，问题出在**填进预算的内容质量**（手动日志、全文式摘要）和**内容的工程化程度**（硬编码、无版本、无观测）。

## 2. 当天记忆 → 任务索引（P6 根治 + D-ctx1）

### 2.1 现状问题

`memory/{YYYY-MM-DD}.md` 完全手动维护（无自动生成）；`filterDailyMemoryForScope` 已能剥离他 scope 的祈使句（C4.3 方向），但这是"过滤坏内容"，不是"生成好内容"——文件没人写时这层等于空转，有人写时仍是叙事全文。

### 2.2 目标设计：自动任务索引取代叙事日志

新增 `daily-task-index-builder.ts`（纯函数，从 DB 投影生成，不依赖任何人手写）：

```markdown
# 今日任务索引（自动生成，2026-06-11）

## 进行中 / 待处理
- [task:abc123] 小红书穿搭采集 | blocked:permission_or_credential | 续跑条件：用户完成登录
- [task:def456] 周报草稿改写 | check_in_pending | 待裁决：diff 已产出，等确认

## 今日已完结
- [task:ghi789] RSS 摘要生成 | completed | 产物：exports/rss-digest-0611.md
```

- 数据源：`task_projections`（02 篇扩列后含 blockerCategory/criteria 状态）按 scope 谱系过滤；
- 每行 = ref + 状态 + 一句话 + 续跑条件/产物路径，**无叙事、无祈使句**——旧任务的"请继续这项任务"在结构上不存在了；
- 注入：替换 L1 中当天文件的位置（预算从 8000 字符中划 1200 给索引）；`memory/{date}.md` 保留为**用户手记**通道，仍过 scope filter，但不再是任务状态的载体；
- 与 05 篇 §2.1 协同：续跑判断依据的就是这些 ref 的状态字段，索引行即候选集。

### 2.3 渐进切换

阶段 1 索引与旧日志并行注入（索引在前）；阶段 2 观测一个版本周期后旧日志降级为"仅用户手记"；不删文件不破坏用户习惯。

## 3. 预算转向注入（P5）

### 3.1 设计

`run-budget-policy.ts` 已有预算账本，缺的是**让模型提前知道**。新增 `budget-steer-reminder`（注册进 system-reminder-registry）：

| 阈值 | 注入内容（资产化文案，见 §4） |
|------|------------------------------|
| 70% | "工具预算已用 70%（X/Y）。优先完成核心目标，次要验证可省略。" |
| 90% | "预算即将耗尽（X/Y）。本轮开始收尾：保存进度、产出可交付物、声明未完成项与续跑条件。" |
| 100% | finalizer 路径：CheckIn(status: checkpoint 或 blocked, blockerCategory: budget_exhausted, nextAction: 续跑指引)——对接 02 篇 |

- 与 Plan L WP2.9 对齐（该工单已规划 70/90% 转向注入，本设计补足其文案资产化与 02 篇终态对接）；
- Matrix 对应原则："keep improving until satisfied, blocked, **out of budget**, or stopped by a real timing boundary"——预算是预先声明的合法停止条件，触顶收尾是**有准备的 checkpoint** 而非中断。

## 4. 提示词资产化（D-ctx2）

### 4.1 目标形态（Matrix seedVersion 模式）

```
src/main/assets/prompts/
├── reminders/
│   ├── budget-steer-70.md          # frontmatter: name/version/description
│   ├── budget-steer-90.md
│   ├── pending-checkin.md          # 02 篇待裁决队列提醒
│   └── …（现有 6 个 reminder 文案逐步迁入）
├── maintenance/
│   └── crystallize-ready.md        # 03 篇维护回合主提示词
├── intent/
│   └── followup-classifier.md      # 05 篇四分类器提示词（含否定提取）
└── rules-defaults/
    ├── RULES.global.md             # 01 篇 K4 默认内容
    └── RULES.primary-agent.md      # 04 篇主 agent 路由纪律
```

frontmatter 统一：`name / version / description / variables: []`（模板变量声明）。

### 4.2 装载与治理

- `prompt-asset-loader.ts`：启动加载 + 变量插值 + 缺文件回退硬编码兜底（保持健壮）；
- **version 字段的用途**：变更可 diff、可回滚；快照测试锁定渲染结果（version 不变则渲染必须逐字节稳定）；为将来 A/B 留 `variant` 槽位；
- 迁移策略：**新文案一律资产化**（本系列所有新增提示词从第一天就是文件）；存量 6 个 reminder 按"动到哪个迁哪个"原则渐进迁移，不做一次性大搬家；
- persona-system-prompt 的固定段落（~500 行）列为阶段三迁移候选，迁移时拆分为可组合片段。

## 5. 注入观测（D-ctx3）

每轮 turn 在 metrics 日志记录一行注入账单：

```json
{ "kind": "context_bill", "runId": "...", "sections": {
    "L0": 4820, "L1_summary": 1100, "L1_taskIndex": 640, "L1_userNotes": 0,
    "L1_5_knowledgeIndex": 880, "L2_triggers": 1500, "reminders": 420 },
  "total": 9360, "truncations": ["L1_5: 3 行低置信度被截断"] }
```

用途：验收 P6 指标（"普通问答轮注入的历史任务 token 下降一个数量级"）需要这个数据；index/RULES 膨胀的预警（03 篇维护回合读它决定是否收紧索引）；预算调参的依据。

## 6. 工作包拆分与验收

| WP | 内容 | 依赖 | 验收 |
|----|------|------|------|
| X1a | daily-task-index-builder v1：**仅用现有列**（status/blocked_reason/continuation_ref/task_title）+ L1 注入切换（并行期） | 无（阶段一可独立落地） | 快照测试：索引行无祈使句；scope 过滤正确；空任务日为空段 |
| X1b | 索引行增强：补 blockerCategory/criteria 进度/待裁决标记 | 02 篇 Q1 合入后 | 增强字段正确渲染；X1a 行为不回归 |
| X2 | budget-steer-reminder（70/90%）+ 100% 终态对接 | Plan L 预算账本、02 篇 Q4 | 行为测试：触顶前至少一轮收到 90% 转向；触顶产生 checkpoint CheckIn |
| X3 | prompt-asset-loader + frontmatter 规范 + 首批资产（crystallize/classifier/budget 文案） | 无（可先行） | 快照测试；缺文件回退；version 稳定性测试 |
| X4 | context_bill 注入观测 | 无（可先行） | 每轮一行账单；与实际注入字节一致 |

验收红线：`daily-task-index.test.ts`（含"旧任务祈使句不出现"断言）、`budget-steer-injection.test.ts`、`prompt-asset-snapshot.test.ts`。

风险：索引行泄漏他谱系任务 → 复用 C4.3 的 scope 谱系过滤函数并加测试；资产化后文案被随手改坏 → version 快照测试 + PR diff 可见即是防线。
