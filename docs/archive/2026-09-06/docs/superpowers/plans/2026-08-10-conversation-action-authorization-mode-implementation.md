# 对话级行动授权模式

## 目标

在普通 Agent 输入框提供“询问授权 / 替我决定 / 全部授权”三档选择，减少连续小操作的确认打断，同时继续由 Main 进程执行风险边界。

## 机器合同

1. 模式只允许 `ask | auto | full`；缺失、非法或读取失败一律回到 `ask`。
2. 模式只允许本地 conversation scope 写入 `chat_conversations.meta_json`，切换对话、重启 Ready 后仍保持各自选择；远程会话固定为 `ask`，Renderer 不持有独立真值。
3. 每轮 ingress 由 Main 从持久 scope 重新读取并冻结当时的模式；消息元数据即使自报更宽档位也必须被覆盖。运行中的冻结调用不受后续 UI 切换影响。
4. M1 永远只能由用户亲自完成。登录完成、权限扩张、本机安装配置、删除、覆盖、批量不可逆操作、任意本地文件上传和疑似敏感外发，即使选择 `full` 也继续逐次确认。
5. `auto` 只自动放行可预批准的 M3；`full` 还可放行明确标记为普通、可审计的 M2/M3。未明确声明可自动放行的规则继续确认，不能把工具串行标签当作外部写入或安全等级。
6. 飞书 CLI 只委托经当前 Ready 验证版本支持的窄操作：不覆盖已有值的少量纯字面量表格写入、最多五行或五列的插入、短纯文本新文档创建，以及单个云盘文件移动或文件夹创建。公式、富文本外链、资源或主动文档块、显式文档格式、未知单元格字段、跨段替换、全文查找替换、复制扩展区域、复合引用、未知或升级后的 CLI 版本全部回到逐次确认；飞书登录完成、profile/config/update/logout、本地输入、越界业务域仍不自动放行。
7. 切换模式不修改工具面、不跳过 authorization、输入校验、冻结参数、动作回执或结果读回，也不向模型注入“用户已确认某个具体动作”的虚假事实。

## 完成标准

- 三档选择器在普通对话输入区可见，显示当前档位和边界说明。
- 新对话默认 `ask`；已有对话非法值回退 `ask`；选择写入失败时 UI 不伪装成功。
- Main 行为矩阵、跨进程 IPC、对话持久化、Renderer 接线和真实飞书 CLI 场景均有验证。
- 真实飞书 CLI 参数与受支持版本均有行为证据；版本升级后必须安全退回逐次询问，不能沿用旧白名单。
- 类型检查、相关专项测试、原生数据库门禁和生产构建通过。
