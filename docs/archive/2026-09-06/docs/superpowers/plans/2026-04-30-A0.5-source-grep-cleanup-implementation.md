## Audit Patch v2（Codex 2026-04-30 plan-mode 实地核查 + Claude 反向修订）

> Codex 在 plan-mode 派 3 个只读 subagent 实地核查，找出本 plan 原文里的 5 处不可执行点。Claude 在其上做 1 处更深的形态意识修订。**当本 patch 与下文正文冲突时，以 patch 为准**。
>
> 此 patch 与 A0 阶段的 audit patch 是同一模式（plan 出稿后再核查，避免推测落地）。

### Codex 实地核查发现

1. **数字偏差**：plan 原文写 `a1-gate 61 entries / 43 files`、`ui-history 141 / 109`。Codex 实测当前 baseline `201 source-grep + 1 legacy-backdoor`，按本 plan §A0.5.1 改动 1 的 `classifyEntry` 跑出来是 `a1-gate 59 / 41 files`、`ui-history 142 / 110 files`。**踩了 plan §"W0 实测偏差超过 ±5 entries 必须 stop"** 的容差边——必须以 Codex 实测为准。

2. **`--area` 退出语义会卡住中间态**：plan 原文 §D2 / §A0.5.1 改动 2 写 `--area a1-gate ... exit 0 if entries === 0; otherwise exit 1`。这会导致 W0/W1/W2 中间态（baseline 非零是预期）跑 `node scripts/check-eslint-baseline.cjs --area a1-gate` 都返回 exit 1，自己挡住自己。**`--area` 必须只是"报告入口"（exit 0），真正 A1 硬门用 `--area a1-gate --max 0` 显式表达**。

3. **`baseline.json --update` 必须保 v2 schema**：plan 原文升级到 schema v2 后没说 `--update` 行为。如果 `--update` 写回 v1 schema，整个 area-aware 设计被一次 update 抹掉。隐性要求需显式化。

4. **W1 共享 reader helper 前置是反模式**（**最重要**——见下文 Claude 反向修订）。

5. **W2 不能按 entries 数粗暴批量清**：很多 source-grep 测试退化的根因是"Electron / runtime manager 难以单元测试"——这是结构合同。需要先分类"可行为化 / hard-review"，再按 owner 域分组。直接按 entries 多少排序批量改会把 hard-review 案例粗暴改成 `JSON.stringify(...).includes(...)` 之类的伪行为断言（违反原则 5）。

### Claude 反向修订（更深一层）

**1. 删 W1 共享 reader helper 前置（覆盖原 §D3 与 §A0.5.2）**

原 plan §D3 把"110 条 inline 重复 → 抽 `readWorkspaceFile` 共享 util + 集中改造"当成杠杆点，是错的。

**真正的形态意识**：

- 共享 reader helper（`src/__tests__/contract-test-utils.ts` 内带 `eslint-disable ready/no-source-grep-test` 注释的 `readWorkspaceFile`）一旦落地，**下游所有想偷懒的测试 import 它就能合法 source-grep**——ESLint rule 检测的是 `readFileSync` 调用形态，不是 import 关系。
- 这等于给 `ready/no-source-grep-test` 留了**一个永久后门**——直接违反 `CLAUDE.md §0.5` 原则 3（拒绝 legacy 兼容分支）。
- 我之前从"如何高效消除 110 条同款 inline 重复"角度看，错把"集中化"当杠杆。**正确的角度是"110 条 inline 重复说明这 110 条测试都该被消灭，不是该被复用"**——它们是行为测试退化的产物，应该全部转为真行为断言或显式 hard-review 豁免，不该留共享 reader 给未来偷懒。

**修订**：

- W0 不建 `contract-test-utils.ts`。
- W1 不依赖任何"共享 reader helper"。
- W2 各 worker 各自把自己负责的测试改写为行为测试；如果某条违例确实无法行为化（结构合同 / 拓扑断言），写显式 `eslint-disable ready/no-source-grep-test -- <reason>` 注释，**只能 case-by-case 豁免，不能集中后门**。
- 所有此类豁免的 reason 必须在 W2 PR 描述里 1-on-1 review，由 Claude / 你审。

**2. W1 pilot 选择修订**

- **删除**原 plan §A0.5.2 中"Easy pilot: agent-error-ipc-contract.test.ts"——该测试的合同（"emit fn 派生自 derive contract，并 spread 到 emit"）实际是 IPC 边界结构合同，行为化要先有 IPC harness。改为 hard-review 候选，不做 pilot。
- **保留** Medium pilot `skill-internal-action-runtime.test.ts`（2 entries），改为新 Pilot 1。
- **新增** Pilot 2 = `skill-execution-tools-removed.test.ts` 中"退役工具不出现在公开工具列表"的部分——直接调 `getOpenAITools()` / `listToolDefinitions()`，断言无 retired name，是清晰的行为测试。
- W1 完成验收**不要求** `verify:a05` 通过（中间态预期非零）；只要求 a1-gate 数量下降 + 迁移模板可行。

## Architecture decisions

### D1. `baseline.json` schema 升级：加 `area` 字段

```json
{
  "version": 2,
  "identity": "file + rule + snippetHash; line is display-only",
  "areaPolicy": {
    "a1-gate": "Must clear before A1 admission",
    "ui-history": "Frozen; count never grows but cleanup not blocking"
  },
  "entries": [
    { "file": "...", "rule": "...", "snippetHash": "...", "line": 25, "snippet": "...", "area": "a1-gate" },
    ...
  ]
}
```

`area` 字段是写时确定的，由 W0 的分类脚本一次性 stamp。后续 cleanup 减少 a1-gate entries 时直接从 `entries[]` 删；ui-history 保持原状。

### D2. `check-eslint-baseline.cjs` 加 `--area` 参数

```
node scripts/check-eslint-baseline.cjs                    # 全量统计 + 增量比对（A0 行为，保留）
node scripts/check-eslint-baseline.cjs --area a1-gate     # 只看 a1-gate；输出 entries 数 + 0 退出码当 0 entries
node scripts/check-eslint-baseline.cjs --area ui-history  # 只看 ui-history；用于"是否有上涨"
```

新参数不破坏现有 verify:a0 调用语义。

### D3. 共享 contract-test util 必须先于迁移落地

新建 `src/__tests__/contract-test-utils.ts`：

```ts
import { readFileSync } from 'node:fs'
import { resolve } from 'node:path'

/**
 * Test-only helper: read a source file from the workspace by its repo-relative
 * path. ONLY used by contract tests that intentionally inspect source bytes
 * (i.e. baseline-grandfathered contract tests during A0.5 cleanup migration).
 *
 * If you are adding a NEW contract test, do NOT use this helper — write a
 * behavior test instead. ready/no-source-grep-test enforces this.
 */
// eslint-disable-next-line ready/no-source-grep-test -- shared reader for behavior-test migration during A0.5
export function readWorkspaceFile(path: string): string {
  return readFileSync(resolve(process.cwd(), path), 'utf8')
}
```

### D4. 边界 case 决策

W0 在分类时强制把以下 2 个文件归到 `ui-history`（不计入 a1-gate）：

- `src/__tests__/rss-draft-store-ui-contract.test.ts`
- `src/__tests__/rss-list-row-style-contract.test.ts`

W0 必须输出"边界 case 决策清单"作为 PR 描述一部分，让 review 可见 / 可推翻。任何**新发现**的边界 case 必须在 W0 PR 描述里列出，不允许在 W2/W3 阶段悄悄改归类。

## §A0.5.1 — Worker 0 详细规格

### 改动 1 — 升级 baseline.json schema

文件：`eslint-rules/baseline.json`

- 顶层 `version` 从 1 → 2。
- 加 `areaPolicy` 字段说明两类 area 的合同。
- 每条 entry 加 `area: 'a1-gate' | 'ui-history'`。

分类规则（脚本化，禁止人手逐条改）：

```js
function classifyEntry(entry) {
  const f = entry.file
  // 强制降级（W0 边界 case 决策）
  if (f.endsWith('-ui-contract.test.ts') || f.endsWith('-style-contract.test.ts')) {
    return 'ui-history'
  }
  // a1-gate keyword pattern（白名单优先）
  const a1Keywords = /(agent|skill|tool|driver|supervisor|child|task|run-state|run-coordinator|rss-(?!draft-store-ui|list-row-style)|browser-task|document-task|continuation|turn-engine|capability|memory|session-recall|sidecar|live-info|workflow|orchestrator|spawn|delivery|primitive|admission|sanitiz)/i
  if (f.startsWith('src/__tests__/') && a1Keywords.test(f.replace('src/__tests__/', ''))) {
    return 'a1-gate'
  }
  return 'ui-history'
}
```

W0 跑这个分类一次，输出预期：a1-gate 桶 ≈ 43 files / 61 entries（与 Explore 核查一致）；ui-history ≈ 109 files / 141 entries。**实测数字与预期偏差超过 ±5 entries 时 W0 必须 stop 并 review pattern**。

### 改动 2 — `check-eslint-baseline.cjs --area` 参数

```
$ node scripts/check-eslint-baseline.cjs --area a1-gate
a1-gate entries: 61
files: 43
(列出 file:count 分布)
exit 0 if entries === 0; otherwise exit 1
```

`--area` 不传时保持原 A0 行为（全量统计 + 增量比对）。

### 改动 3 — `npm run verify:a05` 一键合同

`package.json` 加：

```json
"verify:a05": "node scripts/check-eslint-baseline.cjs --area a1-gate"
```

W3 收尾时该命令必须输出 `a1-gate entries: 0` 才算 A0.5 完成。

### 测试名

新增 `scripts/__tests__/check-eslint-baseline-area.test.cjs`，测试名一字不差：

```
test('check-eslint-baseline --area a1-gate counts only a1-gate entries', ...)
test('check-eslint-baseline --area ui-history counts only ui-history entries', ...)
test('check-eslint-baseline --area a1-gate exits 0 when count is zero', ...)
test('check-eslint-baseline --area unknown-area errors with usage message', ...)
test('check-eslint-baseline without --area preserves A0 behavior (total entries)', ...)
```

### 验收

- `node scripts/check-eslint-baseline.cjs --area a1-gate` 输出 61。
- `node scripts/check-eslint-baseline.cjs --area ui-history` 输出 141。
- 5 个新测试全过。
- W0 PR 描述包含分类脚本输出 + 边界 case 决策清单。
